# SQL子查询

## 定义

子查询（Subquery）是指嵌套在其他SQL语句（`SELECT`、`INSERT`、`UPDATE`、`DELETE`）中的查询语句。子查询先执行，其结果作为外层查询的条件或数据源。

子查询是处理复杂业务逻辑的重要工具，能够实现多层级的条件过滤、跨表数据对比等高级分析。

---

## 核心概念

### 1. 子查询的分类

| 分类依据 | 类型 | 说明 |
|----------|------|------|
| 按位置 | WHERE子句中的子查询 | 子查询返回单个值或多个值，用于条件过滤 |
|  | FROM子句中的子查询（派生表） | 子查询返回一个临时表，作为外层查询的数据源 |
|  | SELECT子句中的子查询（标量子查询） | 子查询返回单个值，作为外层查询的一个列 |
| 按返回结果 | 标量子查询（Scalar Subquery） | 返回单个值（一行一列） |
|  | 列子查询（Column Subquery） | 返回一列多行 |
|  | 行子查询（Row Subquery） | 返回一行多列 |
|  | 表子查询（Table Subquery） | 返回多行多列 |
| 按执行方式 | 相关子查询（Correlated Subquery） | 子查询依赖外层查询的列，每行执行一次 |
|  | 非相关子查询（Non-correlated Subquery） | 子查询独立执行，只执行一次 |

### 2. 子查询的操作符

| 操作符 | 说明 | 示例 |
|--------|------|------|
| `=` | 等于（标量子查询） | `WHERE salary = (SELECT ...)` |
| `>`、`>=`、`<`、`<=`、`<>` | 比较操作符（标量子查询） | `WHERE salary > (SELECT ...)` |
| `IN` | 在某个值列表中（列子查询） | `WHERE department_id IN (SELECT ...)` |
| `ANY` / `SOME` | 与列表中的任意一个值比较 | `WHERE salary > ANY (SELECT ...)` |
| `ALL` | 与列表中的所有值比较 | `WHERE salary > ALL (SELECT ...)` |
| `EXISTS` | 判断子查询是否返回结果（相关子查询） | `WHERE EXISTS (SELECT ...)` |

### 3. 子查询 vs JOIN

| 场景 | 推荐使用 | 理由 |
|------|----------|------|
| 只需要满足某个条件（如"工资大于平均工资的员工"） | 子查询 | 逻辑更清晰 |
| 需要关联多表并返回多列 | JOIN | 性能通常更好 |
| 需要判断存在性（如"有订单的用户"） | `EXISTS`子查询 | 性能通常比JOIN+DISTINCT更好 |

## 详细内容

### 一、WHERE子句中的子查询

#### 1.1 标量子查询（返回单个值）

**场景**：查询工资高于平均工资的员工

```sql
SELECT first_name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
```

**说明**：
- 子查询`(SELECT AVG(salary) FROM employees)`返回单个值（平均工资）
- 外层查询使用`>`比较，找出工资高于平均的员工

**场景**：查询与"张三"在同一部门的员工

```sql
SELECT first_name, department_id
FROM employees
WHERE department_id = (
    SELECT department_id 
    FROM employees 
    WHERE first_name = '张三'
);
```

#### 1.2 列子查询（返回一列多行）

**场景**：查询在"研发部"或"市场部"的员工

```sql
SELECT first_name, department_id
FROM employees
WHERE department_id IN (
    SELECT department_id 
    FROM departments 
    WHERE department_name IN ('研发部', '市场部')
);
```

**说明**：
- 子查询返回多个`department_id`（一列多行）
- 外层查询使用`IN`判断`department_id`是否在子查询结果中

**场景**：查询工资大于任意一个"研发部"员工工资的员工

```sql
SELECT first_name, salary
FROM employees
WHERE salary > ANY (
    SELECT salary 
    FROM employees 
    WHERE department_id = 10
);
```

**说明**：
- `> ANY`：大于子查询结果中的任意一个值即可
- 等价于`> MIN(子查询结果)`

**场景**：查询工资大于所有"研发部"员工工资的员工

```sql
SELECT first_name, salary
FROM employees
WHERE salary > ALL (
    SELECT salary 
    FROM employees 
    WHERE department_id = 10
);
```

**说明**：
- `> ALL`：大于子查询结果中的所有值
- 等价于`> MAX(子查询结果)`

#### 1.3 EXISTS子查询（判断存在性）

**场景**：查询有员工的部门

```sql
SELECT department_name
FROM departments d
WHERE EXISTS (
    SELECT 1 
    FROM employees e 
    WHERE e.department_id = d.department_id
);
```

**说明**：
- `EXISTS`判断子查询是否返回至少一行
- 相关子查询：子查询依赖外层查询的`d.department_id`，每行执行一次
- `SELECT 1`是惯例写法（不关心具体返回什么，只关心是否有结果）

### 二、FROM子句中的子查询（派生表）

**场景**：查询各部门的平均工资，只显示平均工资大于8000的部门

```sql
SELECT department_id, avg_salary
FROM (
    SELECT department_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
) t
WHERE avg_salary > 8000;
```

**说明**：
- 子查询生成一个临时表（派生表），别名`t`
- 外层查询从临时表中筛选数据
- **注意**：派生表必须有别名（如`t`）

**场景**：查询员工工资在其部门排名前3的员工

```sql
SELECT *
FROM (
    SELECT 
        department_id,
        first_name,
        salary,
        ROW_NUMBER() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rank
    FROM employees
) t
WHERE rank <= 3;
```

---

### 三、SELECT子句中的子查询（标量子查询）

**场景**：查询每个员工的姓名、工资，以及该员工工资与部门平均工资的差值

```sql
SELECT 
    first_name,
    salary,
    department_id,
    (SELECT AVG(salary) FROM employees e2 WHERE e2.department_id = e1.department_id) AS dept_avg_salary,
    salary - (SELECT AVG(salary) FROM employees e2 WHERE e2.department_id = e1.department_id) AS diff
FROM employees e1;
```

**说明**：
- 子查询是相关子查询，依赖外层查询的`e1.department_id`
- 子查询返回单个值（部门平均工资），作为外层查询的一个列

**更优做法**（使用窗口函数）：

```sql
SELECT 
    first_name,
    salary,
    department_id,
    AVG(salary) OVER (PARTITION BY department_id) AS dept_avg_salary,
    salary - AVG(salary) OVER (PARTITION BY department_id) AS diff
FROM employees;
```

---

### 四、关联子查询 vs 非关联子查询

#### 4.1 非关联子查询

**定义**：子查询独立执行，不依赖外层查询，只执行一次

**示例**：

```sql
-- 子查询不依赖外层查询，只执行一次
SELECT first_name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
```

#### 4.2 关联子查询

**定义**：子查询依赖外层查询的列，外层查询每行执行一次子查询

**示例**：

```sql
-- 子查询依赖外层查询的e1.department_id，每行执行一次
SELECT 
    first_name,
    salary,
    department_id,
    (SELECT AVG(salary) FROM employees e2 WHERE e2.department_id = e1.department_id) AS dept_avg_salary
FROM employees e1;
```

**性能对比**：
- 非关联子查询：只执行一次，性能较好
- 关联子查询：外层查询有多少行，子查询就执行多少次，性能较差
- **优化建议**：关联子查询尽量改为JOIN或窗口函数

### 五、子查询的常见错误

#### 5.1 标量子查询返回多个值

**错误示例**：

```sql
-- 错误：子查询返回多个值，但使用了=比较
SELECT first_name, salary
FROM employees
WHERE department_id = (SELECT department_id FROM departments);  -- 错误！子查询返回多个值
```

**正确做法**：

```sql
-- 方法1：使用IN
SELECT first_name, salary
FROM employees
WHERE department_id IN (SELECT department_id FROM departments);

-- 方法2：确保子查询返回单个值（加LIMIT 1）
SELECT first_name, salary
FROM employees
WHERE department_id = (SELECT department_id FROM departments LIMIT 1);
```

#### 5.2 派生表没有别名

**错误示例**：

```sql
-- 错误：派生表没有别名
SELECT department_id, avg_salary
FROM (
    SELECT department_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
)
WHERE avg_salary > 8000;
```

**正确做法**：

```sql
-- 正确：派生表必须有别名
SELECT department_id, avg_salary
FROM (
    SELECT department_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
) t  -- 别名t
WHERE avg_salary > 8000;
```

#### 5.3 滥用关联子查询导致性能问题

**问题示例**：

```sql
-- 性能差：关联子查询，外层查询有多少行就执行多少次
SELECT 
    first_name,
    salary,
    (SELECT AVG(salary) FROM employees e2 WHERE e2.department_id = e1.department_id) AS dept_avg_salary
FROM employees e1;
```

**优化做法**（使用窗口函数）：

```sql
-- 性能好：窗口函数，只扫描一次表
SELECT 
    first_name,
    salary,
    AVG(salary) OVER (PARTITION BY department_id) AS dept_avg_salary
FROM employees;
```

## 示例/应用场景

### 示例1：电商订单分析

**需求**：查询订单金额大于该用户平均订单金额的订单

**涉及的表**：
- `orders`：订单表（订单ID、用户ID、订单金额）

**SQL语句**（使用关联子查询）：

```sql
SELECT 
    order_id,
    user_id,
    order_amount
FROM orders o1
WHERE order_amount > (
    SELECT AVG(order_amount) 
    FROM orders o2 
    WHERE o2.user_id = o1.user_id
);
```

**说明**：关联子查询，子查询依赖外层查询的`o1.user_id`，计算每个用户的平均订单金额，然后筛选大于平均的订单。

**更优做法**（使用窗口函数）：

```sql
SELECT order_id, user_id, order_amount
FROM (
    SELECT 
        order_id,
        user_id,
        order_amount,
        AVG(order_amount) OVER (PARTITION BY user_id) AS user_avg_amount
    FROM orders
) t
WHERE order_amount > user_avg_amount;
```

### 示例2：员工薪资分析

**需求**：查询各部门工资最高的员工（使用子查询）

**涉及的表**：
- `employees`：员工表（员工ID、姓名、部门ID、工资）

**SQL语句**：

```sql
SELECT 
    first_name,
    department_id,
    salary
FROM employees e1
WHERE salary = (
    SELECT MAX(salary) 
    FROM employees e2 
    WHERE e2.department_id = e1.department_id
);
```

**说明**：关联子查询，找出各部门工资等于该部门最高工资的员工（可能有并列）。

**更优做法**（使用窗口函数）：

```sql
SELECT first_name, department_id, salary
FROM (
    SELECT 
        first_name,
        department_id,
        salary,
        MAX(salary) OVER (PARTITION BY department_id) AS max_salary
    FROM employees
) t
WHERE salary = max_salary;
```

### 示例3：用户活跃度分析

**需求**：查询有订单的用户信息

**涉及的表**：
- `users`：用户表（用户ID、用户名）
- `orders`：订单表（订单ID、用户ID）

**SQL语句**（使用EXISTS）：

```sql
SELECT user_id, username
FROM users u
WHERE EXISTS (
    SELECT 1 
    FROM orders o 
    WHERE o.user_id = u.user_id
);
```

**说明**：`EXISTS`判断该用户是否有订单，性能通常比`JOIN + DISTINCT`更好。

**对比**：使用JOIN + DISTINCT

```sql
SELECT DISTINCT u.user_id, u.username
FROM users u
INNER JOIN orders o ON u.user_id = o.user_id;
```

## 数据分析师考点

### SQL子查询常见考点

1. **子查询的分类**：标量子查询、列子查询、行子查询、表子查询（派生表）
2. **子查询的位置**：WHERE子句、FROM子句（派生表）、SELECT子句（标量子查询）
3. **子查询的操作符**：`=`、`<>`、`>`、`IN`、`ANY`、`ALL`、`EXISTS`
4. **关联子查询 vs 非关联子查询**：关联子查询依赖外层查询，每行执行一次；非关联子查询独立执行，只执行一次
5. **EXISTS vs IN**：`EXISTS`判断存在性，性能通常更好；`IN`判断是否在列表中
6. **派生表必须有别名**：FROM子句中的子查询必须起别名
7. **标量子查询返回多个值的错误**：使用`=`时，子查询必须返回单个值

### 实战考点

1. **性能优化**：
   - 尽量避免关联子查询，改为JOIN或窗口函数
   - `EXISTS`通常比`IN`性能更好（尤其是子查询结果集很大时）
   - 派生表可以改为CTE（公共表表达式），可读性更好
2. **NULL值的处理**：
   - 子查询返回的结果中包含NULL时，`IN`和`NOT IN`的行为不同（`NOT IN`遇到NULL会返回空结果）
   - 使用`EXISTS`或`NOT EXISTS`可以避免NULL值的问题
3. **窗口函数替代子查询**：很多子查询可以用窗口函数替代，性能更好且可读性更高

## 最佳实践

### 1. 优先使用JOIN或窗口函数替代子查询

**不推荐**（使用子查询）：

```sql
SELECT 
    first_name,
    salary,
    (SELECT AVG(salary) FROM employees e2 WHERE e2.department_id = e1.department_id) AS dept_avg_salary
FROM employees e1;
```

**推荐**（使用窗口函数）：

```sql
SELECT 
    first_name,
    salary,
    AVG(salary) OVER (PARTITION BY department_id) AS dept_avg_salary
FROM employees;
```

**理由**：
- 窗口函数性能更好（只扫描一次表）
- 可读性更高

### 2. 使用EXISTS替代IN（当子查询结果集很大时）

**不推荐**（使用IN）：

```sql
SELECT first_name
FROM employees
WHERE department_id IN (SELECT department_id FROM departments WHERE location_id = 10);
```

**推荐**（使用EXISTS）：

```sql
SELECT first_name
FROM employees e
WHERE EXISTS (
    SELECT 1 
    FROM departments d 
    WHERE d.department_id = e.department_id 
      AND d.location_id = 10
);
```

**理由**：
- 当`departments`表很大时，`EXISTS`性能更好（找到第一条匹配就停止）
- `EXISTS`不受NULL值影响

### 3. 派生表改为CTE（公共表表达式）

**不推荐**（使用派生表）：

```sql
SELECT department_id, avg_salary
FROM (
    SELECT department_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
) t
WHERE avg_salary > 8000;
```

**推荐**（使用CTE）：

```sql
WITH dept_avg AS (
    SELECT department_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
)
SELECT department_id, avg_salary
FROM dept_avg
WHERE avg_salary > 8000;
```

**理由**：
- CTE可读性更好（尤其是多个派生表时）
- CTE可以复用（同一CTE可以在后续多次引用）

### 4. 注意NOT IN的NULL值陷阱

**问题示例**：

```sql
-- 如果子查询返回的结果中有NULL，整个查询返回空结果
SELECT first_name
FROM employees
WHERE department_id NOT IN (SELECT department_id FROM departments WHERE department_id IS NULL);
```

**正确做法**（使用NOT EXISTS）：

```sql
SELECT first_name
FROM employees e
WHERE NOT EXISTS (
    SELECT 1 
    FROM departments d 
    WHERE d.department_id = e.department_id
);
```

**理由**：
- `NOT IN`遇到NULL会返回空结果（因为NULL代表未知，无法判断不在列表中）
- `NOT EXISTS`不受NULL值影响

## 常见错误

### 1. 标量子查询返回多个值

**错误示例**：

```sql
-- 错误：子查询返回多个值，但使用了=比较
SELECT first_name, salary
FROM employees
WHERE department_id = (SELECT department_id FROM departments);
```

**正确做法**：

```sql
-- 使用IN
SELECT first_name, salary
FROM employees
WHERE department_id IN (SELECT department_id FROM departments);
```

### 2. 派生表没有别名

**错误示例**：

```sql
-- 错误：派生表没有别名
SELECT *
FROM (SELECT department_id, AVG(salary) AS avg_salary FROM employees GROUP BY department_id)
WHERE avg_salary > 8000;
```

**正确做法**：

```sql
-- 派生表必须有别名
SELECT *
FROM (SELECT department_id, AVG(salary) AS avg_salary FROM employees GROUP BY department_id) t
WHERE avg_salary > 8000;
```

### 3. 滥用关联子查询导致性能问题

**问题示例**：

```sql
-- 性能差：关联子查询
SELECT 
    first_name,
    (SELECT AVG(salary) FROM employees e2 WHERE e2.department_id = e1.department_id) AS dept_avg
FROM employees e1;
```

**优化做法**（使用窗口函数）：

```sql
-- 性能好：窗口函数
SELECT 
    first_name,
    AVG(salary) OVER (PARTITION BY department_id) AS dept_avg
FROM employees;
```

### 4. 忽略NOT IN的NULL值陷阱

**错误示例**：

```sql
-- 如果子查询返回NULL，整个查询返回空结果
SELECT first_name
FROM employees
WHERE department_id NOT IN (SELECT department_id FROM departments WHERE department_name LIKE '临时%');
```

**正确做法**（使用NOT EXISTS）：

```sql
SELECT first_name
FROM employees e
WHERE NOT EXISTS (
    SELECT 1 
    FROM departments d 
    WHERE d.department_id = e.department_id
);
```

## 总结

SQL子查询是处理复杂业务逻辑的重要工具，核心要点包括：

1. **掌握子查询的分类**：标量子查询、列子查询、行子查询、表子查询（派生表）
2. **理解子查询的位置**：WHERE子句、FROM子句（派生表）、SELECT子句（标量子查询）
3. **熟练使用子查询操作符**：`=`、`<>`、`>`、`IN`、`ANY`、`ALL`、`EXISTS`
4. **理解关联子查询 vs 非关联子查询**：关联子查询依赖外层查询，性能较差，应尽量改为JOIN或窗口函数
5. **注意NULL值的陷阱**：`NOT IN`遇到NULL会返回空结果，应使用`NOT EXISTS`
6. **优先使用JOIN或窗口函数替代子查询**：性能更好，可读性更高

子查询是SQL高级功能，需要在实践中不断积累经验。
