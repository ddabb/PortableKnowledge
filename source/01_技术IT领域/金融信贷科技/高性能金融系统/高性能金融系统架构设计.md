# 高性能金融系统架构设计

## 定义

**高性能金融系统**是指能够**低延迟、高并发、高可用**处理金融交易的系统，核心指标包括：**延迟（Latency）、吞吐量（Throughput）、可用性（Availability）**。

对于金融信贷科技而言，高性能是**核心竞争力**，直接影响用户体验和业务规模。

---

## 核心概念

### 1. 性能指标

| 指标 | 说明 | 金融场景典型值 |
|----------|----------|----------|
| **延迟（Latency）** | 单个请求的处理时间 | ≤ 100ms（实时决策） |
| **吞吐量（Throughput）** | 单位时间处理的请求数 | 10万+ TPS（交易峰值） |
| **可用性（Availability）** | 系统正常服务时间占比 | ≥ 99.99%（年宕机 < 53分钟） |
| **一致性（Consistency）** | 数据一致性保证 | 强一致性（资金交易） |

### 2. 高性能设计原则

**ACE 原则**：
- **A（Availability）**：高可用，故障自动恢复
- **C（Consistency）**：强一致性，资金交易不丢不重
- **E（Efficiency）**：高性能，低延迟高吞吐

**3 个优化维度**：
1. **计算优化**：算法优化、并行计算、异步处理
2. **存储优化**：缓存、数据库优化、分布式存储
3. **网络优化**：CDN、连接池、协议优化

### 3. 金融系统性能挑战

| 挑战 | 说明 | 解决方案 |
|----------|----------|----------|
| **高并发** | 双11、还款日流量峰值 | 水平扩展、负载均衡、限流 |
| **低延迟** | 实时风控决策 ≤ 100ms | 内存计算、缓存、异步化 |
| **强一致** | 资金交易不能丢不能重 | 分布式事务、幂等性设计 |
| **海量数据** | 亿级用户、万亿级交易 | 分库分表、分布式存储 |

## 详细内容

### 1. 计算优化

#### （1）算法优化

**核心思想**：选择时间复杂度低的算法。

**示例：额度计算**
```python
# ❌ 错误：O(n²) 嵌套循环
def calculate_credit_score(user_list):
    scores = []
    for user in user_list:  # O(n)
        score = 0
        for feature in user.features:  # O(n)
            score += feature.weight * feature.value
        scores.append(score)
    return scores  # 总复杂度：O(n²)

# ✅ 正确：O(n) 向量化计算
import numpy as np

def calculate_credit_score_vectorized(user_matrix, weight_vector):
    # user_matrix: (n_users, n_features)
    # weight_vector: (n_features,)
    scores = np.dot(user_matrix, weight_vector)  # O(n)
    return scores
```

#### （2）并行计算

**多线程**：
```java
// ❌ 错误：单线程处理
for (Order order : orders) {
    processOrder(order);  // 串行处理
}

// ✅ 正确：多线程并行处理
ExecutorService executor = Executors.newFixedThreadPool(10);
for (Order order : orders) {
    executor.submit(() -> processOrder(order));  // 并行处理
}
executor.shutdown();
executor.awaitTermination(1, TimeUnit.HOURS);
```

**分布式计算**：
- **MapReduce**：大规模数据批处理
- **Spark**：内存计算，比 Hadoop 快 10-100倍
- **Flink**：流式计算，实时处理

#### （3）异步处理

**适用场景**：
- 非实时操作：短信通知、账单生成
- 耗时操作：生成报表、导出数据
- 解耦系统：风控结果异步回调

**示例：异步还款处理**
```java
// 同步处理（耗时）
public void repay(RepayRequest request) {
    // 1. 更新还款流水（DB写入）
    updateRepayFlow(request);
    // 2. 调用支付系统扣款（RPC调用）
    paymentService.deduct(request);
    // 3. 发送还款成功通知（RPC调用）
    notificationService.sendSms(request);
    // 总耗时：50ms + 200ms + 100ms = 350ms
}

// 异步处理（快速响应）
public void repayAsync(RepayRequest request) {
    // 1. 更新还款流水（DB写入）
    updateRepayFlow(request);
    // 2. 发送消息到 Kafka（异步处理）
    kafkaTemplate.send("repay-topic", request);
    // 总耗时：50ms + 5ms = 55ms
}
```

### 2. 存储优化

#### （1）缓存优化

**缓存分层**：
```
L1 缓存（本地缓存）：Caffeine、Guava Cache（毫秒级）
  ↓
L2 缓存（分布式缓存）：Redis Cluster（毫秒级）
  ↓
L3 缓存（数据库）：MySQL、PostgreSQL（十毫秒级）
```

**缓存策略**：
| 策略 | 说明 | 适用场景 |
|----------|----------|----------|
| **Cache-Aside** | 先读缓存，未命中读DB并更新缓存 | 读多写少 |
| **Read-Through** | 缓存未命中时，缓存层自动加载DB数据 | 简单读场景 |
| **Write-Through** | 先写缓存，缓存写DB | 写多读少 |
| **Write-Behind** | 先写缓存，异步批量写DB | 写多、允许丢数据 |

**缓存穿透/击穿/雪崩防护**：
- **穿透（查询不存在的数据）**：空值缓存 + Bloom Filter
- **击穿（热点Key过期）**：互斥锁重建、热点Key永不过期
- **雪崩（大量Key同时过期）**：过期时间加随机值

#### （2）数据库优化

**索引优化**：
```sql
-- ❌ 错误：全表扫描
SELECT * FROM credit_apply WHERE user_id = 1001;
-- 无索引，扫描全表（1000万行）

-- ✅ 正确：建立索引
CREATE INDEX idx_user_id ON credit_apply(user_id);
-- 索引查找，仅需扫描1行

-- 联合索引（最左前缀原则）
CREATE INDEX idx_user_status_time ON credit_apply(user_id, status, created_at);
-- 可命中：user_id | user_id + status | user_id + status + created_at
-- 无法命中：status | created_at
```

**分库分表**：
- **水平分表**：按用户ID取模，分散到多个表
- **垂直分表**：按列拆分，热数据（订单状态）和冷数据（订单详情）分离

**示例：水平分表**
```sql
-- 分16个表
credit_apply_0, credit_apply_1, ..., credit_apply_15

-- 路由规则：user_id % 16
SELECT * FROM credit_apply_#{user_id % 16} WHERE user_id = 1001;
```

#### （3）分布式存储

**分布式文件系统**：
- **HDFS**：大数据存储，适合离线计算
- **Ceph**：高性能分布式存储，支持对象/块/文件存储

**分布式数据库**：
- **TiDB**：分布式 NewSQL，兼容 MySQL
- **OceanBase**：蚂蚁自研分布式数据库，支持金融级高可用
- **Cassandra**：宽列存储，高可用、最终一致性

### 3. 网络优化

#### （1）连接池

**数据库连接池**：
```java
// HikariCP 配置
HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:mysql://localhost:3306/credit");
config.setUsername("root");
config.setPassword("password");
config.setMaximumPoolSize(20);  // 最大连接数
config.setMinimumIdle(5);       // 最小空闲连接
config.setConnectionTimeout(30000);  // 连接超时（30秒）
config.setIdleTimeout(600000);  // 空闲连接超时（10分钟）

HikariDataSource ds = new HikariDataSource(config);
```

**HTTP 连接池**：
```java
// Apache HttpClient 连接池
PoolingHttpClientConnectionManager cm = new PoolingHttpClientConnectionManager();
cm.setMaxTotal(200);  // 最大连接数
cm.setDefaultMaxPerRoute(20);  // 每个路由最大连接数

CloseableHttpClient httpClient = HttpClients.custom()
    .setConnectionManager(cm)
    .build();
```

#### （2）CDN

**核心思想**：将静态资源（图片、CSS、JS）缓存到离用户最近的边缘节点。

**适用场景**：
- APP 静态资源（图片、H5页面）
- API 加速（边缘节点缓存 GET 请求）

#### （3）协议优化

**HTTP/2**：
- **多路复用**：一个 TCP 连接处理多个请求
- **头部压缩**：减少传输数据量
- **服务端推送**：服务端主动推送资源

**gRPC**：
- **基于 HTTP/2**：多路复用、流控
- **Protobuf**：比 JSON 快 5-10倍
- **双向流**：支持流式传输

## 最佳实践

### 1. 性能优化原则

- **度量优先**：先度量性能瓶颈，再优化（避免过早优化）
- **80/20 原则**：优化20%的代码，带来80%的性能提升
- **渐进优化**：小步快跑，逐步优化（避免一次性大改）

### 2. 高可用设计

- **冗余**：关键组件多副本部署
- **故障隔离**：熔断、降级、限流
- **快速恢复**：自动故障转移（Failover）
- **无状态设计**：服务实例可随时替换

### 3. 团队协作

- **性能测试**：上线前必须做性能测试（压测）
- **性能监控**：全链路监控（QPS、延迟、错误率）
- **容量规划**：提前规划容量（如：双11前扩容）

## 【常见错误】

### 错误1：缓存穿透

**表现**：恶意查询不存在的用户ID，每次都打到数据库，导致数据库宕机。

**正确做法**：
- 空值缓存（设置较短过期时间）
- Bloom Filter 预热所有合法用户ID

### 错误2：数据库慢查询

**表现**：用户还款时，查询还款流水表全表扫描，导致API超时。

**正确做法**：
- 为 `user_id + created_at` 建立联合索引
- 避免 `SELECT *`，只查需要的字段
- 定期分析慢查询日志（`slow_query_log`）

### 错误3：无熔断降级

**表现**：风控系统故障时，导致整个信贷系统不可用。

**正确做法**：
- **熔断**：风控系统故障时，快速失败（返回默认值）
- **降级**：非核心功能（如：短信通知）故障时，跳过执行

### 错误4：忽视性能测试

**表现**：上线后遇到流量峰值，系统宕机。

**正确做法**：
- **压测**：模拟峰值流量（如：双11流量的 2倍）
- **容量规划**：提前扩容（如：增加服务器、数据库分库分表）
- **限流**：超出系统容量时，快速拒绝请求（保护系统）
