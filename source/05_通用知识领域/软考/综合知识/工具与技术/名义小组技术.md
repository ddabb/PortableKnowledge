> 名义小组技术（NGT）是结构化的头脑风暴方法，适合需要快速达成共识的决策场景。

---

## 一、名义小组技术概述

### 1.1 定义

名义小组技术（Nominal Group Technique，NGT）是一种结构化的集体决策技术，通过书面表达和轮次发言相结合，既保留个体独立思考，又发挥集体智慧。

### 1.2 特点

| 特点 | 说明 |
|------|------|
| **独立思考** | 先书面表达，避免从众 |
| **轮流发言** | 每人都有机会 |
| **结构化** | 有明确的步骤流程 |
| **匿名性** | 初步想法匿名提出 |

### 1.3 适用场景

| 适用 | 不适用 |
|------|--------|
| 需要快速收集想法 | 复杂问题需要深入讨论 |
| 有人主导讨论 | 时间充裕的探索性讨论 |
| 需要达成共识 | 仅需信息收集 |

## 二、实施步骤

### 2.1 步骤概览

```
步骤1：问题陈述（5分钟）
        ↓
步骤2：沉默头脑风暴（10-15分钟）
        ↓
步骤3：轮次展示（20-30分钟）
        ↓
步骤4：初步讨论（15-20分钟）
        ↓
步骤5：匿名投票（10分钟）
        ↓
步骤6：决策（5分钟）
```

### 2.2 详细步骤

#### 步骤1：问题陈述

| 内容 | 说明 |
|------|------|
| 清晰陈述问题 | 让所有人理解要讨论什么 |
| 明确目标 | 说明要达成的决策目标 |
| 设定规则 | 说明各环节时间要求 |

**示例问题陈述：**
"我们需要在3个月内解决客户投诉率高的问题，请大家提出解决方案。"

#### 步骤2：沉默头脑风暴

| 要点 | 说明 |
|------|------|
| 独立思考 | 不讨论，每人独自写想法 |
| 书面表达 | 将想法写在卡片/纸上 |
| 数量要求 | 每人提出5-10个想法 |
| 时间 | 10-15分钟 |

**提示：**
- 每个人想法数量要相当
- 可以用关键词，不需要完整句子
- 想到什么写什么，不要评判

#### 步骤3：轮次展示

| 要点 | 说明 |
|------|------|
| 逐一展示 | 每人轮流说出自己想法 |
| 顺序轮换 | 每人轮流，每人一条 |
| 记录完整 | 将所有想法写在白板/大海报上 |
| 不讨论 | 展示时不评价不讨论 |

**记录技巧：**
- 使用编号便于后续讨论
- 保留原始表述，不要改写
- 相似想法合并标注

#### 步骤4：初步讨论

| 讨论内容 | 说明 |
|---------|------|
| 澄清想法 | "能详细说说这个是什么意思吗？" |
| 合并同类 | 将相似的想法归类 |
| 删除重复 | 明显重复的删除 |
| 补充想法 | 基于已有想法补充新想法 |

**主持人引导：**
- 鼓励补充，不批评
- 控制时间，不要偏离主题
- 确保每个人声音被听到

#### 步骤5：匿名投票

| 步骤 | 说明 |
|------|------|
| 确定评分标准 | 如：重要性、可行性（1-5分）|
| 独立打分 | 每人匿名给每个想法打分 |
| 计算总分 | 汇总所有人评分 |
| 排序结果 | 按总分排序 |

**评分方法：**
- 简单投票：每人选3-5个最重要的
- 评分制：每个想法1-5分
- 权重投票：重要想法给更高权重

#### 步骤6：决策

| 决策类型 | 处理方式 |
|---------|----------|
| 明确最优 | 最高分方案执行 |
| 多方案 | 前3名方案进一步讨论 |
| 分歧大 | 回到步骤4讨论 |

## 三、优势与局限

### 3.1 优势

| 优势 | 说明 |
|------|------|
| **公平参与** | 避免少数人主导 |
| **独立思考** | 减少从众效应 |
| **效率高** | 结构化流程节省时间 |
| **决策清晰** | 投票结果明确 |
| **接受度高** | 参与感强，执行意愿高 |

### 3.2 局限

| 局限 | 说明 |
|------|------|
| **创意受限** | 不如自由头脑风暴发散 |
| **小组人数** | 4-12人效果最好 |
| **时间约束** | 时间紧张时难以充分讨论 |
| **深度有限** | 不适合复杂问题的深入分析 |

## 四、主持技巧

### 4.1 事前准备

| 准备项 | 内容 |
|--------|------|
| 问题设计 | 清晰、可讨论、可决策 |
| 参与者选择 | 4-12人，相关背景 |
| 场地布置 | 便于展示和记录 |
| 材料准备 | 卡片、白板、投票表 |

### 4.2 现场控制

| 场景 | 技巧 |
|------|------|
| 有人主导 | "我们听听其他人的想法" |
| 想法太少 | 适当延长时间 |
| 想法太多 | 合并归类，控制20个以内 |
| 偏离主题 | "这个话题很有趣，我们回头再聊，回到今天的主题" |

## 五、与其他工具对比

### 5.1 vs 头脑风暴

| 对比项 | 头脑风暴 | 名义小组技术 |
|--------|----------|--------------|
| 发言顺序 | 自由发言 | 轮流发言 |
| 独立思考 | 无 | 有（步骤2） |
| 讨论深度 | 深 | 浅 |
| 决策结果 | 模糊 | 明确 |
| 时间 | 灵活 | 结构化 |

### 5.2 vs 德尔菲法

| 对比项 | 德尔菲法 | 名义小组技术 |
|--------|----------|--------------|
| 交互方式 | 匿名问卷多轮 | 面对面一轮 |
| 时间 | 长（数周）| 短（1-2小时）|
| 参与方式 | 书面 | 口头+书面 |
| 适合场景 | 专家预测 | 团队决策 |

## 七、注意事项

### 7.1 成功要点

| 要点 | 说明 |
|------|------|
| **问题清晰** | 参与者理解要解决什么问题 |
| **时间控制** | 各步骤严格控制时间 |
| **公平参与** | 确保每个人都有发言机会 |
| **匿名投票** | 减少政治因素干扰 |
| **后续跟进** | 投票结果要执行 |

### 7.2 常见错误

| 错误 | 后果 |
|------|------|
| 问题模糊 | 产出偏离目标 |
| 步骤跳过 | 失去结构化优势 |
| 评分标准不清 | 结果争议大 |
| 结果不执行 | 打击参与者积极性 |

## 八、案例演示

### 案例：选择项目管理系统

**步骤1：问题陈述**
"我们需要在Q2选型一个新的项目管理工具，请提出评估标准。"

**步骤2：沉默头脑风暴**
每人写下5-10个评估标准

**步骤3：轮次展示**
汇总所有评估标准，如：
1. 价格
2. 易用性
3. 功能完整性
4. 集成能力
5. 安全性
...

**步骤4：讨论澄清**
合并相似项，删除不相关项

**步骤5：匿名投票**
每人给每个标准打分（1-5分），汇总结果：
| 评估标准 | 总分 |
|---------|------|
| 功能完整性 | 38 |
| 易用性 | 35 |
| 价格 | 33 |
| 集成能力 | 28 |
| 安全性 | 22 |

**步骤6：决策**
按总分确定评估权重，开始选型

## 九、总结

### 何时使用名义小组技术

✅ **使用：**
- 需要快速收集想法并排序
- 有人倾向主导讨论
- 需要公平的决策过程
- 时间有限但需要共识

❌ **不使用：**
- 需要深入探索复杂问题
- 时间非常充裕
- 专家预测类问题（用德尔菲）
- 只需信息收集不需要决策
