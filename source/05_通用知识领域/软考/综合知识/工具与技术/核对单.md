> 核对单（Checklist）是确保工作完整性和规范性的有效工具。

---

## 一、什么是核对单

### 1.1 定义

核对单（Checklist）是将需要检查的项目列出清单，逐项确认是否完成或符合要求的工具。

### 1.2 核对单的价值

| 价值 | 说明 |
|------|------|
| **防止遗漏** | 确保重要步骤不被遗忘 |
| **标准化** | 统一工作标准 |
| **可追溯** | 记录检查过程 |
| **培训工具** | 帮助新人学习流程 |

---

## 二、核对单类型

### 2.1 确认型核对单

**特点：** 检查项目是否完成

**示例 - 软件发布检查：**
- [ ] 代码审查通过
- [ ] 测试用例全部通过
- [ ] 文档更新完成
- [ ] 备份已创建
- [ ] 通知相关人员

### 2.2 评分型核对单

**特点：** 按标准评分

**示例 - 项目评审：**
- [ ] 需求完整性 (1-5分): ___
- [ ] 技术可行性 (1-5分): ___
- [ ] 资源充足性 (1-5分): ___
- [ ] 风险可控性 (1-5分): ___

---

## 三、核对单编制

### 3.1 编制原则

| 原则 | 说明 |
|------|------|
| **完整性** | 覆盖所有关键检查项 |
| **简洁性** | 每项检查点清晰明确 |
| **可操作性** | 检查项可被验证 |
| **适用性** | 根据实际情况调整 |

### 3.2 编制步骤

```
1. 明确检查目标
   ↓
2. 收集相关信息
   ↓
3. 列出所有检查项
   ↓
4. 分组分类整理
   ↓
5. 审核优化
   ↓
6. 试用修订
```

### 3.3 检查项来源

| 来源 | 示例 |
|------|------|
| 历史经验 | 上次项目的问题清单 |
| 最佳实践 | 行业标准规范 |
| 专家意见 | 技术专家建议 |
| 教训总结 | 失败案例分析 |

## 四、项目管理中的应用

### 4.1 需求核对单

| 检查项 | 说明 |
|--------|------|
| 需求描述清晰 | 无歧义，可测试 |
| 需求完整 | 功能、数据、约束齐全 |
| 需求可行 | 技术上可实现 |
| 需求一致 | 与其他需求不冲突 |
| 需求可追溯 | 关联业务目标 |

### 4.2 项目启动核对单

| 检查项 | 说明 |
|--------|------|
| 项目章程已批准 | 发起人签字 |
| 项目经理已指定 | 职责明确 |
| 初步范围确定 | 高层范围已定 |
| 干系人识别 | 初步干系人名单 |
| 初步计划 | 里程碑计划 |

### 4.3 项目收尾核对单

| 检查项 | 说明 |
|--------|------|
| 交付物验收 | 客户签字确认 |
| 经验教训归档 | 存入组织过程资产 |
| 资源释放 | 团队成员已释放 |
| 财务结算 | 项目账目已结清 |
| 文档归档 | 所有文档已归档 |

## 五、质量管理中的应用

### 5.1 质量检查核对单

| 检查项 | 检查标准 |
|--------|----------|
| 功能测试 | 所有用例通过率≥95% |
| 性能测试 | 响应时间<2秒 |
| 安全测试 | 无高危漏洞 |
| 兼容性测试 | 支持主流浏览器 |

### 5.2 评审检查核对单

**代码评审核对单：**
- [ ] 代码符合命名规范
- [ ] 有适当的注释
- [ ] 单元测试覆盖充分
- [ ] 无安全漏洞
- [ ] 性能影响已评估

**设计评审核对单：**
- [ ] 架构设计合理
- [ ] 扩展性已考虑
- [ ] 安全性已考虑
- [ ] 与现有系统兼容
- [ ] 文档完整

## 六、使用技巧

### 6.1 核对单设计技巧

| 技巧 | 说明 |
|------|------|
| 分组 | 将相关项放一起 |
| 优先级 | 重要项标注星号 |
| 简洁语言 | 用动词开头 |
| 打勾符号 | 用□或☐便于填写 |

### 6.2 核对单执行技巧

| 技巧 | 说明 |
|------|------|
| 逐项检查 | 不跳项 |
| 及时记录 | 发现问题立即记录 |
| 追溯签名 | 检查人签字确认 |
| 定期回顾 | 检查项是否有遗漏 |

---

## 七、注意事项

1. **不要过于冗长** - 控制在10-20项内
2. **定期更新** - 根据实际情况调整
3. **培训使用者** - 确保理解每项含义
4. **配套改进机制** - 发现问题要改进
5. **电子化** - 可用系统管理，便于追溯

---

## 八、核对单 vs 核对单

|------|------|----------|
