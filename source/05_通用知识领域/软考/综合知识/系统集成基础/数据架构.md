# 数据架构

## 概念定义

数据架构描述了组织的**逻辑和物理数据资产**以及相关数据管理资源的结构。

主要内容涉及数据全生命周期之下的架构规划：数据的产生、流转、整合、应用、归档和消亡。

## 发展演进

### 单体应用架构时代（80年代）
- 以单体应用为主
- 数据架构比较简单：数据模型、数据库设计

### 数据仓库时代
- 面向主题的、集成的、用于数据分析的全新架构
- 主要应用：OLAP（联机分析处理）
- 关注：数据模型、数据分布和流向

### 大数据时代
- 批处理到流处理
- 大集中到分布式
- 批流一体到全量实时

## 设计原则

### 1. 数据分层原则
- 按生命周期分层次
- 解决层次定位合理性问题
- 约束每个层次的建设目标、设计方法、模型、存储策略

### 2. 数据处理效率原则
- 追求合理而非单纯高效率
- 减少明细数据的冗余存储和大规模搬迁操作
- 满足数据处理效率要求的成本合理化

### 3. 数据一致性原则
- 减少数据在不同层次分布中的冗余存储
- 减少按不同业务逻辑的重复加工
- 保障数据一致性的关键

### 4. 可扩展性原则
- 清晰的数据层次定位
- 合理的模型和存储技术策略
- 支持新增业务类型、数据整合要求、数据应用要求

### 5. 服务于业务原则
- 数据架构最终目标服务于业务
- 满足业务特殊目标时可灵活调整

## 数据架构举例

### 数据资源库类型

1. **源数据库**：业务数据的源端
2. **交换库**：数据同步到交换数据库
3. **过渡库**：Hadoop平台中的过渡存储
4. **整合库**：数据对照、转换、清洗、聚集
5. **主题库**：服务库，根据治理主题应用需求

### 数据处理流程
```
源数据 → 交换库 → 过渡库 → 整合库 → 主题库
```

## 数据建模

### 数据模型
- 逻辑数据结构
- 由数据库管理系统提供的操作和约束

### 元数据
- 关于数据的数据
- 包括：数据仓库表结构、属性、源数据、映射规则

### 数据粒度
- 数据单位中保存数据的细化或综合程度
- 细化程度越高，粒度级越小

### 数据分割
- 结构相同的数据被分成多个数据物理单元
- 任何给定的数据单元属于且仅属于一个分割

### ETL过程
- **Extract**：从数据源抽取数据
- **Transformation**：数据清洗、转换
- **Load**：按照数据仓库模型加载到数据仓库
