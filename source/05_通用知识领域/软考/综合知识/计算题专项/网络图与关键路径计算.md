## 基本概念

- **网络图**：用节点表示活动，用箭头表示依赖关系（PDM法，前导图）
- **关键路径**：从开始到结束耗时最长的路径，决定项目最短工期
- **关键活动**：位于关键路径上的活动，**总浮动时间为0**
- **浮动时间（Float）**：活动可以延迟而不影响项目完工的时间

## 六个时间参数

| 参数 | 缩写 | 说明 |
|------|------|------|
| 最早开始时间 | ES | 活动最早能开始的时间 |
| 最早完成时间 | EF | EF = ES + 持续时间 |
| 最晚开始时间 | LS | 不影响工期的最晚开始时间 |
| 最晚完成时间 | LF | 不影响工期的最晚完成时间 |
| **总浮动时间** | TF | TF = LS - ES = LF - EF |
| **自由浮动时间** | FF | 不影响紧后活动ES的延迟时间 |

## 计算步骤

### 正推（计算ES/EF）
- 从左往右推
- ES = 所有紧前活动EF的**最大值**
- EF = ES + 持续时间

### 反推（计算LF/LS）
- 从右往左推
- LF = 所有紧后活动LS的**最小值**
- LS = LF - 持续时间

### 浮动时间
- TF = LS - ES（或 LF - EF）
- TF = 0 的活动就是关键活动

## 典型例题

**题目**：网络图如下，数字为活动持续天数：

```
      B(3)
    ↗      ↘
A(2)   D(4)  → F(2)
    ↘      ↗
      C(5)
```

具体路径：
- A → B → D → F：2+3+4+2 = **11天**
- A → C → D → F：2+5+4+2 = **13天** ← 关键路径
- A → B → F：2+3+2 = **7天**（假设B也可直接到F）

**结论**：关键路径为 A→C→D→F，工期13天。

## 标准例题（带节点计算）

**活动表**：

| 活动 | 紧前活动 | 工期（天） |
|------|---------|----------|
| A | — | 3 |
| B | — | 4 |
| C | A | 2 |
| D | A | 5 |
| E | B,C | 3 |
| F | D,E | 2 |

**路径分析**：
- A→C→E→F：3+2+3+2 = **10天**
- A→D→F：3+5+2 = **10天**
- B→E→F：4+3+2 = **9天**

**关键路径**：A→C→E→F 和 A→D→F（并列，均为10天）  
**工期**：10天

**B的总浮动时间**：关键路径10天 - B到F最长路径9天 = **1天**（B可以推迟1天开始）

## 进度压缩方法（与网络图相关）

### 赶工（Crashing）
- 增加资源压缩关键活动工期
- 只压缩**关键路径上的活动**才有效
- 优先赶工**成本最低**的关键活动
- 赶工可能产生新的关键路径

### 快速跟进（Fast Tracking）
- 将串行活动改为并行执行
- 不增加成本，但**增加风险**
- 需要活动间存在可并行的条件

**考点**：
- 赶工 = 花钱买时间，成本增加
- 快速跟进 = 并行，风险增加
- 两者都只能压缩关键路径上的活动
