# 成本汇总（Cost Aggregation）

## 定义

**成本汇总**是**制定预算**（Determine Budget）过程中的核心活动，指先将**成本估算**汇总到 **WBS 中的工作包**，再由工作包汇总至 **WBS 的更高层次**（如控制账户），最终得出**整个项目的总成本**。

成本汇总是将**估算成本**转化为**成本基准**的关键步骤。

---

## 核心逻辑

### 汇总路径

```
活动成本估算
    ↓
工作包成本估算（汇总活动成本）
    ↓
控制账户成本（汇总工作包成本）
    ↓
项目总成本（汇总所有控制账户成本）
    ↓
成本基准（加应急储备）
    ↓
项目预算（加管理储备）
```

### 汇总原则

1. **自下而上**：从活动→工作包→控制账户→项目总成本
2. **逐级汇总**：每一层都是下一层成本的汇总
3. **不重不漏**：确保成本汇总完整、不重复
4. **与WBS一致**：成本汇总结构需与WBS结构一致

---

## 成本汇总的步骤

### 步骤1：汇总活动成本到工作包

- 每个工作包包含多个活动
- 将工作包下所有活动的成本估算汇总
- 得到**工作包成本估算**

**示例**：
```
工作包：用户登录模块开发
- 活动1：界面设计 → 成本估算：2万元
- 活动2：后端开发 → 成本估算：3万元
- 活动3：测试 → 成本估算：1万元
工作包成本估算 = 2 + 3 + 1 = 6万元
```

---

### 步骤2：汇总工作包成本到控制账户

- 每个控制账户包含多个工作包
- 将控制账户下所有工作包的成本估算汇总
- 得到**控制账户成本**

**示例**：
```
控制账户：系统开发
- 工作包1：用户登录模块开发 → 6万元
- 工作包2：数据录入模块开发 → 8万元
- 工作包3：报表生成模块开发 → 5万元
控制账户成本 = 6 + 8 + 5 = 19万元
```

---

### 步骤3：汇总控制账户成本到项目总成本

- 将所有控制账户的成本估算汇总
- 得到**项目总成本估算**

**示例**：
```
项目：XXX系统开发项目
- 控制账户1：系统开发 → 19万元
- 控制账户2：系统测试 → 10万元
- 控制账户3：项目管理 → 5万元
项目总成本估算 = 19 + 10 + 5 = 34万元
```

---

### 步骤4：制定成本基准

- 在项目总成本估算基础上，加**应急储备**
- 得到**成本基准**

**示例**：
```
项目总成本估算：34万元
应急储备：3.4万元（10%）
成本基准 = 34 + 3.4 = 37.4万元
```

---

### 步骤5：制定项目预算

- 在成本基准基础上，加**管理储备**
- 得到**项目预算**

**示例**：
```
成本基准：37.4万元
管理储备：2万元
项目预算 = 37.4 + 2 = 39.4万元
```

## 成本汇总的关键点

### 1. 与WBS结构一致

- 成本汇总结构需与**WBS结构**一致
- 确保成本汇总完整、不遗漏

### 2. 自下而上汇总

- 从**活动成本估算**开始，逐级汇总
- 确保成本估算的准确性

### 3. 不重不漏

- 确保成本汇总**不重复**、**不遗漏**
- 每个成本只汇总一次

### 4. 考虑储备

- **应急储备**：应对已知未知风险，包含在成本基准中
- **管理储备**：应对未知未知风险，不包含在成本基准中

## 最佳实践

1. **使用工具**：使用Excel或项目管理软件进行成本汇总
2. **版本控制**：成本汇总文件需版本控制
3. **团队评审**：成本汇总结果需团队评审
4. **更新及时**：范围变化时，及时更新成本汇总
5. **与进度计划结合**：成本汇总需与进度计划结合，形成**S曲线**

---

## 常见错误

❌ **汇总路径错误**：不是自下而上汇总，而是自上而下分解  
❌ **与WBS不一致**：成本汇总结构与WBS结构不一致，导致遗漏  
❌ **重复汇总**：同一成本被汇总多次  
❌ **遗漏成本**：某些成本未被汇总  
❌ **不考虑储备**：成本汇总不考虑应急储备和管理储备

---

## 总结

成本汇总是项目**成本管理**的关键活动，将活动成本估算逐级汇总为项目预算。掌握其汇总路径和关键点，能有效提升成本估算的准确性。
