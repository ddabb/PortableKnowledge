## 核心概念

**项目变更**是指在信息系统项目实施过程中，由于项目环境或其他原因，对项目的功能、性能、架构、技术指标、集成方法和项目进度等方面做出的改变。

**变更管理**是为使项目基准与项目实际执行情况相一致，应对项目变化的一套管理方法。其可能结果是拒绝变化或调整项目基准。

> **变更管理的实质**：根据项目推进过程中越来越丰富的项目认知，不断调整项目努力方向和资源配置，最大程度地满足项目需求，提升项目价值。

## 变更产生的原因

- 产品范围（成果）定义的过失或疏忽
- 项目范围（工作）定义的过失或疏忽
- 增值变更
- 应对风险的紧急计划或回避计划
- 项目执行过程与基准要求不一致带来的被动调整
- 外部事件

## 变更分类

### 按性质分类
| 类型 | 说明 |
|------|------|
| **重大变更** | 影响面广，需高级别审批 |
| **重要变更** | 中等影响 |
| **一般变更** | 影响较小，审批流程可简化 |

### 按迫切性分类
- **紧急变更**：必须快速响应，尽快实施（如业务中断、安全攻击）
- **非紧急变更**：可按常规流程处理

### 按行业特征分类（弱电工程为例）
产品范围变更、环境变更、设计变更、实施变更、技术标准变更

## 变更管理原则

| 原则 | 要点 |
|------|------|
| **基准管理** | 基准是变更的依据，初始基准经评审后建立，每次变更通过评审后重新确定基准 |
| **变更控制流程化** | 所有变更必须遵循统一控制流程 |
| **明确组织分工** | 明确评估、评审、执行的职能 |
| **与干系人充分沟通** | 征求重要干系人意见，获得变更支持 |
| **变更的及时性** | 变更宜早不宜晚，越早代价越小 |
| **评估变更的可能影响** | 包括客户可视和不可视的内部工作变更 |
| **妥善保存变更文档** | 确保完整、及时、准确、清晰 |

## 角色与职责

### 变更控制委员会（CCB）
由主要项目干系人代表组成的**决策机构**（非作业机构），通过评审决定项目基准是否能变更：
- 审查、评价、批准、推迟或否决项目变更
- 通知受处置意见影响的相关干系人
- 接收变更与验证结果，确认变更是否按要求完成

### 变更管理负责人（变更经理）
- 负责整个变更过程方案的结果和监控
- 协调资源，保障所有变更按预定过程运作
- 确定变更类型，组织变更计划和日程安排
- 变更实施完成后的回顾和关闭

### 变更请求者
- 提出变更需求，记录并提交变更请求单
- 初步评价变更的风险和影响

### 变更实施者
- 按批准的变更计划实施具体变更任务
- 记录并保存变更产物，将变更后的基准纳入项目基准
- 参与变更正确性的验证与确认

### 变更顾问委员会
- 紧急变更时对被授权者行使审批权限
- 定期听取变更经理汇报，评估执行情况

## 变更管理工作程序（8步）

```
变更申请 → 变更初审 → 变更方案论证 → 变更审查
    ↓
发出通知并实施 → 实施监控 → 效果评估 → 变更收尾
```

1. **变更申请**：以正式书面方式提出，留下书面记录。任何干系人都可以提出。
2. **变更初审**：确认变更必要性，格式校验，确保评估信息充分。
3. **变更方案论证**：对变更是否可实现进行论证，将技术要求转化为资源需求。大型变更需召开论证会议。
4. **变更审查**：项目所有者根据申请及评估方案决定是否变更项目基准。
5. **发出通知并实施**：调整基准，确保资源到位，明确交付日期及对干系人的影响。
6. **实施监控**：监控项目整体基准是否反映实施情况，确认变更正确完成。
7. **效果评估**：以项目基准为依据，评估变更目的是否达成。
8. **变更收尾**：确认项目是否纳入正常轨道，按新基准进行整体监控。

## 变更控制

### 变更申请的控制
- 变更管理体系须确保项目基准反映项目实施情况
- 所有变更操作应覆盖，确保无法绕过变更申请流程

### 变更内容的控制
- **进度变更控制**：判断进度状态、施加影响、查明变化、管理实际变化
- **成本变更控制**：施加影响、确保授权、管理实际变更、监控绩效、防止未批准变更
- **合同变更控制**：规定合同修改过程，与整体变更控制结合

### 变更类型的控制
| 类型 | 特点 |
|------|------|
| **标准变更** | 低风险、预先授权，作为服务请求发起 |
| **正常变更** | 常规、较低风险，通过已确定流程管理 |
| **紧急变更** | 不在计划中，必须快速响应，可精简程序 |

## 变更输入输出

**输入**：项目基准、项目计划、配置管理计划、工作绩效报告、变更请求和变更方案

**输出**：批准的变更请求、更新的基准和计划、变更日志、变更后的工作绩效报告、经验教训

## 变更管理与相关活动的关系

### 与项目整合管理
- 变更管理是项目整合管理的一部分
- 实施整体变更控制过程贯穿项目始终
- 批准前需了解对进度、成本、质量、资源等多方面的影响

### 与配置管理
- 配置管理重点关注可交付产品及过程文档
- 变更管理着眼于识别、记录、批准或否决对项目文件、可交付产品或基准的变更
- 变更管理过程中包含：配置项识别、配置状态记录、配置确认与审计

## 版本发布和回退计划

### 发布前准备
- 进行回退分析
- 备份存储过程、函数等数据
- 备份配置数据
- 备份在线生产平台接口、应用和工作流版本
- 确定启动回退机制的触发条件
- 明确回退机制职责

### 回退步骤
1. 通知相关用户系统开始回退
2. 通知各关联系统进行版本回退
3. 回退存储过程等数据对象
4. 配置数据回退
5. 应用程序、接口程序、工作流等版本回退
6. 回退完成通知各周边关联系统
7. 回退后进行相关测试
8. 通知用户回退完成
