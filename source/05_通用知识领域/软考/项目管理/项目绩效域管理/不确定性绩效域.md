## 定义

不确定性绩效域涉及与**风险和不确定性**相关的活动和功能。不确定性表现为威胁和机会，项目团队需要探索、评估并处理它们。

## 相关定义 — 风险+VUCA

> 口诀：**魔方又复杂又有风险又不确定**（模糊性、易变性、复杂性、不确定性、风险）

| 要素 | 说明 |
|-----|------|
| **V**olatility（易变性） | 快速、意外地变化 |
| **U**ncertainty（不确定性） | 缺乏对问题和事件的理解和意识 |
| **C**omplexity（复杂性） | 多个相互关联的因素 |
| **A**mbiguity（模糊性） | 因果关系模糊，原因不清 |
| **风险** | 不确定事件或情况，可能对项目产生正面或负面影响 |

## 预期成果（7项）

1. 了解项目运行环境（技术、社会、政治、市场、经济）
2. 积极识别、分析和应对不确定性
3. 了解项目中多个因素之间的相互依赖关系
4. 能够对威胁和机会进行预测，了解问题后果
5. **最小化**不确定性对项目交付的**负面影响**
6. 能够**利用机会**改进项目的绩效和成果
7. 有效利用成本和进度储备，与项目目标保持一致

## 绩效要点

### 1. 风险应对
- 所有项目都有风险，团队需主动识别、分析并预制应对策略
- 根据干系人的**风险偏好和承受力**确定临界值

### 2. 模糊性应对方法

| 方法 | 说明 |
|------|------|
| **渐进明细** | 随信息增多，计划越来越详细 |
| **实验** | 设计实验识别因果关系 |
| **原型法** | 测试不同解决方案产生的不同结果 |

### 3. 复杂性应对方法

| 复杂性类型 | 应对方法 |
|-----------|---------|
| 基于系统 | 解耦（断开各部分联系）、模拟 |
| 重新构建 | 多样性（发散→收敛）、平衡 |
| 基于过程 | 迭代（小步快走）、干系人参与、故障保护（增加冗余） |

### 4. 不确定性的通用应对方法

1. **收集信息** — 发现更多信息以减少不确定性
2. **为多种结果做好准备** — 备份和应急计划
3. **集合设计** — 探索选项，权衡时间/成本/质量/风险
4. **增加韧性** — 增强快速适应意外变化的能力

## 考点提示

- VUCA 四要素顺序：易变性→不确定性→复杂性→模糊性
- 预期成果7项，包含"利用机会"（不只是规避风险）
- 预测型项目用**进度和预算储备**应对风险；适应型项目可以**调整计划**应对
- 故障保护 = 关键要素**增加冗余**
