# 可视化流程编排引擎

## 定义

可视化流程编排引擎是营销自动化平台的核心组件，用于**设计、解析和执行**复杂的营销流程。它通过**拖拽式可视化界面**，让业务人员无需编程即可设计自动化营销流程。

**核心目标**：
- **降低使用门槛**：业务人员可以自主设计营销流程
- **提高效率**：可视化设计比手写代码快10倍以上
- **减少错误**：可视化验证 + 实时预览，避免逻辑错误
- **易于维护**：流程可视化展示，便于理解和修改

---

## 核心概念

### 1. 流程编排引擎的核心能力

**可视化设计器**：
- 拖拽式组件库（触发器、分支、动作、等待、目标）
- 画布编辑（连接、删除、复制、粘贴）
- 实时验证（语法检查、逻辑检查）
- 预览与调试（单步执行、模拟运行）

**流程解析器**：
- 解析可视化流程定义（JSON/BPMN）
- 构建执行计划（Execution Plan）
- 优化执行路径（并行执行、短路评估）

**流程执行器**：
- 状态机驱动（State Machine）
- 节点调度与执行
- 错误处理与重试
- 暂停、恢复、终止

**版本管理**：
- 流程定义版本化
- 版本对比与回滚
- A/B测试（不同版本对比效果）

### 2. 流程定义模型

**节点类型**：
- **触发器节点**（Trigger）：流程入口，监听事件
- **分支节点**（Branch）：条件判断，多路径选择
- **动作节点**（Action）：执行具体操作（发送邮件、更新标签）
- **等待节点**（Wait）：延迟执行（3天后、每周一）
- **目标节点**（Goal）：流程目标（用户购买、激活）
- **终止节点**（End）：流程结束

**连接类型**：
- **顺序连接**（Sequence）：A → B
- **条件连接**（Conditional）：A → B (IF condition) / A → C (ELSE)
- **并行连接**（Parallel）：A → B + C（同时执行）
- **汇合连接**（Join）：B + C → D（等待所有分支完成）

### 3. 流程执行模型

**状态机模型**：
- 每个流程实例是一个状态机
- 节点执行对应状态流转
- 状态持久化（防止丢失）

**事件驱动模型**：
- 外部事件触发流程（用户注册、加购）
- 内部事件驱动流转（定时器、条件满足）

**调度模型**：
- 定时调度（Cron表达式）
- 延迟调度（Wait节点）
- 事件驱动（实时响应）

**解析为执行计划 (DAG)**：

```python
class Node:
    def __init__(self, node_id, node_type, config):
        self.id = node_id
        self.type = node_type
        self.config = config
        self.next_nodes = []  # 后继节点列表

def parse_flow(flow_json):
    nodes = {}
    edges = flow_json['edges']
    
    # 构建节点字典
    for node_data in flow_json['nodes']:
        node = Node(node_data['id'], node_data['type'], node_data['config'])
        nodes[node.id] = node
    
    # 构建边（连接关系）
    for edge in edges:
        source_node = nodes[edge['source']]
        target_node = nodes[edge['target']]
        source_node.next_nodes.append((target_node, edge.get('condition')))
    
    # 找到触发器节点（流程入口）
    trigger_nodes = [n for n in nodes.values() if n.type == 'TRIGGER']
    
    return trigger_nodes, nodes

# 验证DAG（检测循环）
def validate_dag(nodes):
    visited = set()
    rec_stack = set()
    
    def has_cycle(node):
        visited.add(node.id)
        rec_stack.add(node.id)
        
        for next_node, _ in node.next_nodes:
            if next_node.id not in visited:
                if has_cycle(next_node):
                    return True
            elif next_node.id in rec_stack:
                return True  # 检测到循环
        
        rec_stack.remove(node.id)
        return False
    
    for node in nodes.values():
        if node.id not in visited:
            if has_cycle(node):
                raise ValueError(f"流程定义存在循环：节点 {node.id}")
    
    return False  # 无循环
```

**状态定义**：

```python
from enum import Enum

class FlowState(Enum):
    PENDING = "PENDING"        # 待执行
    RUNNING = "RUNNING"        # 执行中
    WAITING = "WAITING"        # 等待中（Wait节点）
    COMPLETED = "COMPLETED"    # 已完成（达到Goal）
    FAILED = "FAILED"          # 执行失败
    PAUSED = "PAUSED"          # 已暂停
    TERMINATED = "TERMINATED"  # 已终止
```

**状态机实现**：

```python
class FlowInstance:
    def __init__(self, instance_id, flow_id, user_id):
        self.instance_id = instance_id
        self.flow_id = flow_id
        self.user_id = user_id
        self.state = FlowState.PENDING
        self.current_node_id = None
        self.context = {}  # 上下文（用户属性、变量）
        self.created_at = datetime.now()
        self.updated_at = datetime.now()
    
    def transition(self, new_state):
        """状态流转"""
        old_state = self.state
        self.state = new_state
        self.updated_at = datetime.now()
        logger.info(f"实例 {self.instance_id} 状态变更：{old_state} → {new_state}")
        
        # 持久化状态
        self.save()
    
    def save(self):
        """持久化到数据库"""
        db.execute("""
            UPDATE flow_instances 
            SET state = %s, current_node_id = %s, context = %s, updated_at = %s
            WHERE instance_id = %s
        """, (self.state.value, self.current_node_id, json.dumps(self.context), 
              self.updated_at, self.instance_id))
```

**状态流转逻辑**：

```python
def execute_flow_instance(instance):
    """执行流程实例"""
    if instance.state == FlowState.PENDING:
        instance.transition(FlowState.RUNNING)
        instance.current_node_id = find_trigger_node(instance.flow_id)
    
    while instance.state == FlowState.RUNNING:
        current_node = get_node(instance.current_node_id)
        
        try:
            # 执行当前节点
            result = execute_node(current_node, instance.context)
            
            # 根据节点类型，决定下一个节点
            if current_node.type == 'GOAL':
                # 达到目标，流程完成
                instance.transition(FlowState.COMPLETED)
                break
            
            elif current_node.type == 'BRANCH':
                # 分支节点，根据条件选择下一个节点
                next_node = evaluate_branch(current_node, instance.context)
                instance.current_node_id = next_node.id
            
            elif current_node.type == 'WAIT':
                # 等待节点，状态变更为WAITING，等待定时器触发
                instance.transition(FlowState.WAITING)
                schedule_timer(instance, current_node.config['duration'])
                break
            
            else:
                # 顺序执行，取第一个后继节点
                next_node = current_node.next_nodes[0][0]
                instance.current_node_id = next_node.id
        
        except Exception as e:
            logger.error(f"节点执行失败：{e}")
            instance.transition(FlowState.FAILED)
            break
    
    # 持久化状态
    instance.save()
```

#### 4. 节点执行器 (Node Executor)

**功能**：
- 执行各类节点（触发器、动作、分支、等待、目标）
- 调用外部服务（发送邮件、短信、更新标签）
- 处理重试与失败

**节点执行器接口**：

```python
from abc import ABC, abstractmethod

class NodeExecutor(ABC):
    @abstractmethod
    def execute(self, node, context):
        """执行节点"""
        pass

class TriggerExecutor(NodeExecutor):
    def execute(self, node, context):
        # 触发器节点不需要执行，只是流程入口
        return True

class ActionExecutor(NodeExecutor):
    def execute(self, node, context):
        channel = node.config['channel']
        template_id = node.config['template_id']
        
        if channel == 'EMAIL':
            return send_email(context['user_id'], template_id)
        elif channel == 'SMS':
            return send_sms(context['user_id'], template_id)
        elif channel == 'PUSH':
            return send_push(context['user_id'], template_id)
        else:
            raise ValueError(f"未知渠道：{channel}")

class BranchExecutor(NodeExecutor):
    def execute(self, node, context):
        condition = node.config['condition']
        # 评估条件表达式
        result = evaluate_expression(condition, context)
        return result

class WaitExecutor(NodeExecutor):
    def execute(self, node, context):
        duration = node.config['duration']
        # 注册定时器，延迟执行
        schedule_delay(instance_id, duration)
        return True

class GoalExecutor(NodeExecutor):
    def execute(self, node, context):
        # 目标节点，流程完成
        return True

# 执行器工厂
def get_executor(node_type):
    executors = {
        'TRIGGER': TriggerExecutor(),
        'ACTION': ActionExecutor(),
        'BRANCH': BranchExecutor(),
        'WAIT': WaitExecutor(),
        'GOAL': GoalExecutor(),
    }
    return executors.get(node_type)
```

#### 5. 调度器 (Scheduler)

**功能**：
- 定时任务调度（Cron表达式）
- 延迟任务调度（Wait节点）
- 批量任务调度（百万级用户）

**技术选型**：
- **调度框架**：Quartz / XXL-Job / Temporal
- **延迟队列**：Redis Sorted Set / Kafka延迟主题

**延迟调度实现（Redis Sorted Set）**：

```python
import redis
import time
import json

r = redis.Redis()

def schedule_delay(instance_id, duration):
    """注册延迟任务"""
    # 解析duration（如 "3d" -> 3天）
    seconds = parse_duration(duration)
    execute_at = time.time() + seconds
    
    # 添加到延迟队列
    r.zadd("delayed_tasks", {instance_id: execute_at})
    logger.info(f"实例 {instance_id} 延迟 {duration} 执行")

def parse_duration(duration):
    """解析duration字符串"""
    if duration.endswith('s'):
        return int(duration[:-1])
    elif duration.endswith('m'):
        return int(duration[:-1]) * 60
    elif duration.endswith('h'):
        return int(duration[:-1]) * 3600
    elif duration.endswith('d'):
        return int(duration[:-1]) * 86400
    else:
        raise ValueError(f"未知duration格式：{duration}")

def poll_delayed_tasks():
    """轮询延迟任务（每秒执行一次）"""
    while True:
        now = time.time()
        
        # 查询到期的任务
        tasks = r.zrangebyscore("delayed_tasks", 0, now)
        
        for instance_id in tasks:
            instance_id = instance_id.decode('utf-8')
            
            # 恢复流程实例执行
            instance = get_flow_instance(instance_id)
            if instance.state == FlowState.WAITING:
                instance.transition(FlowState.RUNNING)
                execute_flow_instance(instance)
            
            # 从延迟队列中移除
            r.zrem("delayed_tasks", instance_id)
        
        time.sleep(1)

# 启动轮询线程
threading.Thread(target=poll_delayed_tasks, daemon=True).start()
```

### 三、高级功能

#### 1. 并行执行 (Parallel Execution)

**功能**：
- 多个节点同时执行（提高性能）
- 汇合节点等待所有分支完成

**实现方案**：

```python
def execute_parallel_nodes(nodes, context):
    """并行执行多个节点"""
    with ThreadPoolExecutor() as executor:
        futures = [executor.submit(execute_node, node, context) for node in nodes]
        results = [f.result() for f in futures]
    return results

# 示例：并行发送邮件和短信
nodes = [email_node, sms_node]
execute_parallel_nodes(nodes, context)
```

#### 2. 动态分支 (Dynamic Branch)

**功能**：
- 根据运行时数据，动态决定分支路径
- 支持复杂条件表达式

**实现方案**：

```python
def evaluate_branch(node, context):
    """评估分支条件，返回下一个节点"""
    for branch in node.config['branches']:
        condition = branch['condition']
        
        # 评估条件表达式
        if evaluate_expression(condition, context):
            return get_node(branch['next_node'])
    
    # 默认分支
    return get_node(node.config['default_branch'])
```

#### 3. 版本管理 (Version Management)

**功能**：
- 流程定义版本化
- 版本对比与回滚
- A/B测试（不同版本对比效果）

**实现方案**：

```python
def create_new_version(flow_id):
    """创建新版本"""
    # 获取当前最新版本
    current_version = db.query("SELECT MAX(version) FROM flows WHERE flow_id = %s", (flow_id,))
    new_version = current_version + 1
    
    # 复制流程定义，版本号+1
    db.execute("""
        INSERT INTO flows (flow_id, name, version, definition, created_at)
        SELECT flow_id, name, %s, definition, NOW()
        FROM flows
        WHERE flow_id = %s AND version = %s
    """, (new_version, flow_id, current_version))
    
    return new_version

def compare_versions(flow_id, version1, version2):
    """对比两个版本的差异"""
    def1 = db.query("SELECT definition FROM flows WHERE flow_id = %s AND version = %s", 
                    (flow_id, version1,))
    def2 = db.query("SELECT definition FROM flows WHERE flow_id = %s AND version = %s", 
                    (flow_id, version2,))
    
    # 使用difflib生成差异
    diff = difflib.unified_diff(
        def1.splitlines(),
        def2.splitlines(),
        fromfile=f"version {version1}",
        tofile=f"version {version2}"
    )
    
    return '\n'.join(diff)
```

## 示例/应用场景

### 场景1：新用户欢迎系列

**业务流程**：
1. 用户注册（触发器）
2. 立即发送欢迎邮件（动作）
3. 3天后，如果用户未打开邮件，发送提醒短信（分支 + 等待 + 动作）
4. 7天后，如果用户未购买，推送App通知（等待 + 动作）
5. 如果用户购买，流程完成（目标）

**可视化设计**：
```
[触发器: 用户注册] → [动作: 发送欢迎邮件] → [等待: 3天] → [分支: 是否打开邮件?]
                                                    ↓ True       ↓ False
                                              [动作: 发送短信]   [动作: 发送提醒邮件]
                                                    ↓              ↓
                                              [等待: 7天] ←------┘
                                                    ↓
                                              [分支: 是否购买?]
                                                    ↓ True
                                              [目标: 用户购买]
```

**技术实现**：
- 使用**可视化设计器**设计流程
- 使用**流程解析器**解析为执行计划
- 使用**状态机引擎**管理流程实例状态
- 使用**调度器**实现延迟执行（3天、7天）

### 场景2：购物车弃单召回

**业务流程**：
1. 用户加购但未下单（触发器）
2. 1小时后，发送提醒邮件（等待 + 动作）
3. 24小时后，如果仍未下单，发送优惠短信（等待 + 分支 + 动作）
4. 72小时后，如果仍未下单，推送App通知（等待 + 动作）
5. 如果用户下单，立即终止流程（事件监听）

**技术实现**：
- 使用**事件监听**机制，实时监听`USER_PURCHASE`事件
- 如果用户下单，立即终止流程实例
- 使用**状态机引擎**管理流程实例的暂停/恢复/终止

### 场景3：A/B测试

**业务流程**：
1. 创建两个版本的流程（A版、B版）
2. 随机将用户分配到A版或B版
3. 对比两个版本的转化率，选择最优版本

**技术实现**：
- 使用**版本管理**功能，创建两个版本
- 使用**分流器**（Splitter）随机分配用户
- 使用**效果分析**功能，对比转化率

## 最佳实践

### 1. 可视化设计器最佳实践

**用户体验**：
- **组件库分类**：按功能分类（触发器、动作、控制流）
- **搜索功能**：快速查找组件
- **快捷键**：Ctrl+C复制、Ctrl+V粘贴、Delete删除
- **撤销/重做**：支持无限撤销/重做

**性能优化**：
- **虚拟画布**：只渲染可见区域（大型流程）
- **懒加载**：节点组件按需加载
- **防抖**：拖拽、连接操作防抖

### 2. 流程解析器最佳实践

**验证规则**：
- **语法检查**：节点配置是否完整？
- **逻辑检查**：是否存在孤立节点？是否存在死循环？
- **性能检查**：流程是否过于复杂？（节点数 > 100？）

**错误提示**：
- **精确定位**：错误发生在哪个节点？
- **友好提示**："分支节点缺少默认分支"而不是"解析失败"
- **快速修复**：提供一键修复建议

### 3. 状态机引擎最佳实践

**状态持久化**：
- **热数据**：Redis（流程实例运行时状态）
- **冷数据**：MySQL（流程实例历史记录）
- **事务保证**：状态更新与业务操作在同一事务中

**容错设计**：
- **重试机制**：节点执行失败，自动重试（指数退避）
- **死信队列**：多次重试仍失败的节点，放入死信队列，人工介入
- **降级策略**：非关键节点失败，跳过继续执行

### 4. 性能优化最佳实践

**并行执行**：
- **识别可并行节点**：无依赖关系的节点可以并行执行
- **线程池**：限制并发数，防止资源耗尽

**缓存策略**：
- **流程定义缓存**：热点流程定义缓存到Redis
- **节点配置缓存**：节点配置缓存到本地内存

**异步化**：
- **非关键逻辑异步化**：记录日志、更新统计
- **消息队列解耦**：节点执行结果异步处理

## 【常见错误】

### 错误1：流程定义存在循环

**现象**：
流程实例卡住，无法结束。

**原因**：
- 分支逻辑设计错误（A→B→C→A）
- 缺少终止条件

**解决方案**：
- 使用**流程解析器**的循环检测功能
- 设置**最大步数限制**（如最多100步）
- 设置**超时终止**（如30天未完成则自动终止）

### 错误2：状态机状态丢失

**现象**：
流程实例重启后，状态丢失，从头开始执行。

**原因**：
- 状态未持久化
- 或持久化失败

**解决方案**：
- **必须持久化状态**（Redis + MySQL）
- 使用**事务**保证状态更新的原子性
- 使用**幂等性设计**，即使状态丢失也不影响最终结果

### 错误3：节点执行超时

**现象**：
流程实例卡在某个节点，长时间无响应。

**原因**：
- 外部服务响应慢（如邮件服务API超时）
- 或节点逻辑死循环

**解决方案**：
- 设置**节点执行超时**（如30秒）
- 超时后自动重试或失败
- 使用**熔断降级**（Sentinel / Hystrix）

### 错误4：并行执行结果丢失

**现象**：
并行执行的节点，部分结果丢失。

**原因**：
- 线程安全问题（多个线程同时修改context）
- 或节点执行顺序不确定

**解决方案**：
- 使用**线程安全的数据结构**（如Queue）
- **避免共享状态**，每个节点独立输入输出
- 使用**Future**获取并行执行结果

### 错误5：版本回滚失败

**现象**：
回滚到旧版本后，流程实例执行失败。

**原因**：
- 旧版本流程定义与新版本数据不兼容
- 或旧版本有bug

**解决方案**：
- **版本兼容性测试**：回滚前，先测试旧版本
- **数据迁移**：如果需要，迁移数据到旧版本格式
- **灰度回滚**：先回滚部分流量，验证无误后再全量回滚

## 总结

可视化流程编排引擎是营销自动化平台的核心，涉及**前端可视化、后端状态机、调度、事件驱动**等多个方面。

**设计关键**：
- 采用**前后端分离**架构，前端负责可视化设计，后端负责流程执行
- 使用**状态机**管理流程实例的生命周期
- 引入**事件驱动架构**，实时响应外部事件
- 建设**版本管理**体系，支持A/B测试与回滚

**技术选型建议**：
- **前端**：React + React Flow / X6
- **后端**：Spring Boot + Spring State Machine
- **调度器**：Quartz / XXL-Job / Temporal
- **消息队列**：Kafka / RabbitMQ
- **数据库**：MySQL（流程定义、流程实例）+ Redis（状态缓存）

**未来演进方向**：
- **AI辅助设计**：自动生成流程、自动优化流程
- **低代码/无代码**：让业务人员自主设计流程
- **跨平台集成**：整合更多第三方系统（CRM、ERP、CDP）
- **实时协同编辑**：多人同时编辑同一流程（类似Google Docs）
