# 价值交付系统

## 概述

价值交付系统描述了项目如何在系统内运作，为组织及其干系人创造价值，包括：
- 项目如何创造价值
- 价值交付组件
- 信息流

## 创造价值

项目存在于组织中（包括政府机构、科研院所、企事业单位等），项目为干系人创造价值。

### 价值创造方式

1. **创造新产品或服务**：创造满足客户或最终用户需要的新产品、服务或结果
2. **做出贡献**：做出积极的社会或环境贡献
3. **提高效率**：提高效率、生产力、效果或响应能力
4. **推动变革**：推动必要的变革，以促进组织向期望的未来状态过渡
5. **维持收益**：维持以前的项目集、项目或业务运营所带来的收益

## 价值交付组件

可以单独或共同使用多种组件来创造价值，这些组件共同组成了一个符合组织战略的价值交付系统。

### 组件类型

| 组件 | 说明 |
|------|------|
| 项目组合 | 为实现战略目标而组合在一起管理的项目、项目集 |
| 项目集 | 一组相互关联且被协调管理的项目、子项目集 |
| 项目 | 为创造独特产品、服务或成果而进行的临时性工作 |
| 产品 | 可以量化生产的工件（包括服务及其组件） |
| 运营 | 持续生产产品或提供服务的活动 |

### 价值交付系统结构

```
┌─────────────────────────────────────────┐
│              外部环境                    │
│  ┌─────────────────────────────────┐    │
│  │           内部环境               │    │
│  │  ┌─────────────────────────┐  │    │
│  │  │     价值交付系统          │  │    │
│  │  │  ┌─────────┬─────────┐   │  │    │
│  │  │  │ 项目组合1 │ 项目组合2 │   │  │    │
│  │  │  ├───┬───┼───┬───┤   │  │    │
│  │  │  │项目集│ │项目集│   │  │    │
│  │  │  ├───┼───┼───┼───┤   │  │    │
│  │  │  │项目│ │项目│ │项目│   │  │    │
│  │  │  └───┴───┴───┴───┘   │  │    │
│  │  └─────────────────────────┘  │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

### 组件关系

- 项目组合、项目集和项目会相互影响
- 也会影响运营
- 任何项目或项目集都可能会包括产品
- 运营可以直接支持和影响项目组合、项目集、项目及其他业务职能

### 价值链

```
可交付物 → 成果 → 收益 → 价值

- 可交付物：组件创建的产出
- 成果：某一过程或项目的最终结果或后果
- 收益：组织实现的利益
- 价值：具有收益作用、重要性或实用性的事物
```

## 信息流

当信息和信息反馈在所有价值交付组件之间以一致的方式共享时，价值交付系统最为有效。

### 信息流向

```
┌─────────────────────────────────────────────────────────────┐
│                        高层领导                              │
│     ↑ 绩效信息                                               │
│     │                                                        │
│     │ 战略信息          绩效信息和进展                        │
│     ↓                      ↑                                 │
│ ┌────────────────┐    ┌────────────────┐                   │
│ │   项目组合      │ ←→ │  项目集和项目   │                   │
│ └────────────────┘    └───────┬────────┘                   │
│                               │                             │
│                               │ 包含支持和维护信息的         │
│                               │ 可交付物                     │
│                               ↓                             │
│                        ┌────────────────┐                    │
│                        │      运营      │                    │
│                        └───────┬────────┘                    │
│                                │                             │
│                                │ 针对更新、修复和             │
│                                │ 调整的信息                   │
│                                ↓                             │
│                        ┌────────────────┐                   │
│                        │  项目集和项目   │                   │
│                        └────────────────┘                   │
└─────────────────────────────────────────────────────────────┘
```

### 信息流特点

1. **高层领导与项目组合**：战略信息向下，绩效信息向上
2. **项目组合与项目集/项目**：分享预期成果、收益和价值
3. **项目集/项目与运营**：可交付物及其支持和维护信息传递给运营
4. **运营反馈**：表明对可交付物的调整、修复和更新
5. **运营到项目组合**：提供组织战略推进情况的信息

## 环境因素

价值交付系统是组织内部环境的一部分，该环境受以下因素制约：
- 政策
- 程序
- 方法论
- 框架
- 治理结构

内部环境存在于更大的外部环境中，包括：
- 经济
- 竞争环境
- 法律限制

## 核心概念

| 概念 | 定义 |
|------|------|
| 可交付物 | 组件创建的用于产出成果的产出 |
| 成果 | 某一过程或项目的最终结果或后果 |
| 收益 | 组织实现的利益 |
| 价值 | 具有收益作用、重要性或实用性的事物 |

## 关键认知

1. **系统协调**：价值交付系统中的组件需要协调一致才能实现期望的项目成果
2. **信息共享**：信息和反馈的一致性分享是系统有效运作的关键
3. **与战略保持一致**：价值交付系统使系统与战略保持一致
4. **持续创造**：价值可以在整个项目进行期间、项目结束或完成后实现
