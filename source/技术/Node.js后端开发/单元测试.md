# 单元测试

## 定义

单元测试是对软件中最小可测试单元进行检查和验证的过程。在Node.js后端开发中，单元测试通常针对函数、模块或类进行测试，确保其行为符合预期。

## 核心概念

### 1. 测试框架
- **定义**：提供测试结构、断言库和测试运行器的工具
- **常见框架**：Jest、Mocha、Jasmine
- **选择标准**：易用性、功能丰富度、社区支持

### 2. 断言（Assertions）
- **定义**：验证代码行为是否符合预期的语句
- **常见断言**：相等、深度相等、抛出异常、包含等
- **示例**：`expect(result).toBe(42)`

### 3. 测试覆盖率（Coverage）
- **定义**：代码被测试用例覆盖的程度
- **度量指标**：行覆盖率、分支覆盖率、函数覆盖率
- **目标**：通常要求覆盖率>80%

### 4. Mock和Stub
- **Mock**：模拟依赖对象的行为
- **Stub**：提供预定义 responses 的模拟对象
- **用途**：隔离被测单元，控制依赖行为

## 详细内容

### 单元测试原则

1. **FIRST原则**
   - **Fast**：测试应该快速运行
   - **Independent**：测试之间应该相互独立
   - **Repeatable**：测试应该可在任何环境中重复运行
   - **Self-validating**：测试应该能自动判断通过/失败
   - **Timely**：测试应该及时编写

2. **AAA模式**
   - **Arrange**：准备测试数据和环境
   - **Act**：执行被测代码
   - **Assert**：验证结果是否符合预期

3. **单一职责**
   - 每个测试只测试一个行为
   - 每个测试只有一个断言（或一组相关断言）

### 测试框架比较

| 特性 | Jest | Mocha | Jasmine |
|------|------|-------|---------|
| 断言库 | 内置 | 需配置 | 内置 |
| Mock功能 | 内置 | 需配置 | 内置 |
| 覆盖率 | 内置 | 需配置 | 需配置 |
| 配置复杂度 | 低 | 中 | 中 |
| 流行度 | 高 | 高 | 中 |

### 测试类型

1. **单元测试**
   - 测试最小可测试单元
   - 快速、独立
   - 使用Mock隔离依赖

2. **集成测试**
   - 测试多个组件的交互
   - 可能涉及数据库、网络等
   - 比单元测试慢

3. **端到端测试**
   - 测试整个系统流程
   - 模拟真实用户场景
   - 最慢、最脆弱

## 示例/应用场景

### 示例1：使用Jest测试函数

**被测代码**（`math.js`）：
```javascript
function add(a, b) {
  return a + b;
}

function subtract(a, b) {
  return a - b;
}

module.exports = { add, subtract };
```

**测试代码**（`math.test.js`）：
```javascript
const { add, subtract } = require('./math');

describe('数学函数', () => {
  describe('add函数', () => {
    test('应该正确相加两个正数', () => {
      // Arrange
      const a = 2;
      const b = 3;
      
      // Act
      const result = add(a, b);
      
      // Assert
      expect(result).toBe(5);
    });
    
    test('应该正确处理负数', () => {
      expect(add(-1, -2)).toBe(-3);
      expect(add(-1, 2)).toBe(1);
      expect(add(1, -2)).toBe(-1);
    });
  });
  
  describe('subtract函数', () => {
    test('应该正确相减两个正数', () => {
      expect(subtract(5, 3)).toBe(2);
    });
    
    test('应该正确处理负数', () => {
      expect(subtract(-1, -2)).toBe(1);
      expect(subtract(-1, 2)).toBe(-3);
      expect(subtract(1, -2)).toBe(3);
    });
  });
});
```

### 示例2：测试Express路由

**路由代码**（`userRoutes.js`）：
```javascript
const express = require('express');
const router = express.Router();
const User = require('../models/User');

router.get('/:id', async (req, res) => {
  try {
    const user = await User.findById(req.params.id);
    if (!user) {
      return res.status(404).json({ error: 'User not found' });
    }
    res.json(user);
  } catch (error) {
    res.status(500).json({ error: error.message });
  }
});

module.exports = router;
```

**测试代码**（`userRoutes.test.js`）：
```javascript
const request = require('supertest');
const express = require('express');
const router = require('./userRoutes');
const User = require('../models/User');

// Mock User模型
jest.mock('../models/User');

const app = express();
app.use(express.json());
app.use('/api/users', router);

describe('用户路由', () => {
  beforeEach(() => {
    jest.clearAllMocks();
  });
  
  describe('GET /api/users/:id', () => {
    test('当用户存在时返回用户信息', async () => {
      // Arrange
      const mockUser = { id: 1, name: '张三', email: 'zhangsan@example.com' };
      User.findById.mockResolvedValue(mockUser);
      
      // Act
      const response = await request(app).get('/api/users/1');
      
      // Assert
      expect(response.status).toBe(200);
      expect(response.body).toEqual(mockUser);
      expect(User.findById).toHaveBeenCalledWith('1');
    });
    
    test('当用户不存在时返回404', async () => {
      // Arrange
      User.findById.mockResolvedValue(null);
      
      // Act
      const response = await request(app).get('/api/users/999');
      
      // Assert
      expect(response.status).toBe(404);
      expect(response.body).toEqual({ error: 'User not found' });
    });
    
    test('当数据库错误时返回500', async () => {
      // Arrange
      User.findById.mockRejectedValue(new Error('Database error'));
      
      // Act
      const response = await request(app).get('/api/users/1');
      
      // Assert
      expect(response.status).toBe(500);
      expect(response.body).toEqual({ error: 'Database error' });
    });
  });
});
```

## 【Node.js后端开发】最佳实践

### 1. 测试策略
- **测试金字塔**：大量单元测试，适量集成测试，少量端到端测试
- **关键路径优先**：优先测试核心业务逻辑
- **边界条件**：测试边界条件和异常场景

### 2. 测试组织
- **清晰的测试描述**：使用描述性名称
- **测试隔离**：每个测试独立运行，不依赖其他测试
- **测试数据管理**：使用工厂函数或fixture管理测试数据

### 3. Mock策略
- **只Mock外部依赖**：不Mock被测单元的内部逻辑
- **避免过度Mock**：过度Mock会导致测试失真
- **验证Mock调用**：验证Mock是否按预期调用

### 4. 持续集成
- **自动运行测试**：每次提交代码时自动运行测试
- **测试失败阻止合并**：测试失败不允许合并代码
- **测试报告**：生成测试报告，跟踪测试覆盖率

### 5. 测试维护
- **重构时更新测试**：重构代码时同步更新测试
- **删除过时测试**：删除不再有效的测试
- **定期审查测试**：确保测试质量

## 【常见错误】

### 1. 测试实现细节而非行为
- **错误**：测试函数内部实现而非外部行为
- **正确**：测试函数的输入输出，不测试内部实现

### 2. 测试之间相互影响
- **错误**：一个测试的结果影响另一个测试
- **正确**：每个测试独立设置和调整

### 3. 忽略边界条件
- **错误**：只测试正常场景，忽略边界条件
- **正确**：测试边界条件和异常场景

### 4. 过度依赖真实依赖
- **错误**：测试中使用真实的数据库、网络等
- **正确**：使用Mock隔离外部依赖

## 总结

单元测试是确保代码质量的重要手段，通过测试最小可测试单元，可以早期发现缺陷、简化调试、支持重构。掌握单元测试原则、测试框架使用、Mock技术和最佳实践，是构建高质量Node.js应用的基础。
