# 并发编程实践

## 定义

并发编程是**编写能同时处理多个任务**的软件的技术。在系统编程中，并发是充分利用多核CPU、提高吞吐量的关键。

**并发 vs 并行**：
- **并发（Concurrency）**：多个任务交替执行（单核也可实现）
- **并行（Parallelism）**：多个任务同时执行（需多核）

**为什么需要并发**：
- **提高吞吐量**：多核CPU同时工作
- **提高响应性**：I/O等待时不阻塞其他任务
- **简化设计**：将复杂任务分解为独立子任务

## 核心概念

### 1. 竞态条件（Race Condition）
- **定义**：多个线程同时访问共享资源，执行结果依赖于执行时序
- **示例**：`count++`（读取→修改→写入，三步非原子操作）
- **解决**：互斥锁、原子操作、无锁数据结构

### 2. 临界区（Critical Section）
- **定义**：访问共享资源的代码段
- **原则**：
  - **互斥**：同一时间只有一个线程可进入
  - **进展**：线程有限等待进入临界区
  - **有限等待**：线程等待时间有上限

### 3. 同步原语（Synchronization Primitives）
- **互斥锁（Mutex）**：确保互斥访问
- **读写锁（Read-Write Lock）**：读共享、写独占
- **条件变量（Condition Variable）**：线程等待某个条件成立
- **信号量（Semaphore）**：控制同时访问资源的线程数
- **屏障（Barrier）**：多个线程互相等待，全部到达后继续执行

### 4. 内存模型（Memory Model）
- **定义**：多线程环境下，对内存读写操作的顺序约束
- **问题**：
  - **编译器乱序**：编译器重新排列指令
  - **CPU乱序**：CPU乱序执行（Out-of-Order Execution）
  - **缓存一致性**：多核缓存不一致
- **解决**：内存屏障（Memory Barrier）、原子操作

## 详细内容

### 互斥锁（Mutex）深入

#### 1. 锁的类型
- **普通锁（Fast Mutex）**：
  - 同一线程不能重复加锁（会死锁）
  - 默认类型（Linux PTHREAD_MUTEX_DEFAULT）
- **递归锁（Recursive Mutex）**：
  - 同一线程可重复加锁（需对应次数解锁）
  - 适用场景：递归函数、可重入代码
- **错误检查锁（Error Checking Mutex）**：
  - 检测同一线程重复加锁（返回EDEADLK）
  - 检测未加锁的线程解锁（返回EPERM）
- **自适应锁（Adaptive Mutex）**：
  - 自旋等待+阻塞等待混合
  - 短临界区自旋，长临界区阻塞

#### 2. 锁的性能考量
- **自旋锁（Spinlock）**：
  - 线程在循环中不断检查锁是否释放（忙等待）
  - 适用场景：临界区极短（微秒级），且多核系统
  - 缺点：浪费CPU周期
- **阻塞锁（Blocking Mutex）**：
  - 线程睡眠，等待锁释放时被唤醒
  - 适用场景：临界区较长（毫秒级）
  - 缺点：上下文切换开销（微秒级）

#### 3. 锁争用优化
- **减小临界区**：只保护真正需要保护的共享资源
- **锁分段（Lock Striping）**：将大锁拆分为多个小锁（如ConcurrentHashMap）
- **读写锁**：读多写少场景用读写锁代替互斥锁
- **无锁编程**：使用CAS（Compare-And-Swap）实现无锁数据结构

### 无锁编程（Lock-Free Programming）

#### 1. 原子操作（Atomic Operations）
- **定义**：不可分割的操作，执行过程中不会被中断
- **CPU原子指令**：
  - **CAS（Compare-And-Swap）**：比较并交换，成功返回true
  - **Fetch-And-Add**：原子地增加并返回旧值
  - **Test-And-Set**：原子地设置值并返回旧值
- **内存排序（Memory Ordering）**：
  - **memory_order_relaxed**：无顺序约束（最弱）
  - **memory_order_acquire**：后续读操作不能重排到前面
  - **memory_order_release**：前面写操作不能重排到后面
  - **memory_order_seq_cst**：全局顺序一致（最强）

#### 2. 无锁数据结构
- **无锁栈（Lock-Free Stack）**：
  - 使用CAS实现push/pop
  - 问题：ABA问题（需用双宽CAS或标记指针）
- **无锁队列（Lock-Free Queue）**：
  - Michael-Scott算法（基于CAS）
  - 适用场景：高并发生产者-消费者
- **无锁计数器**：
  - 使用Fetch-And-Add（最简单）
  - 或者用分片计数器（每个线程一个计数器，最后汇总）

#### 3. 无锁编程挑战
- **ABA问题**：值从A变为B又变回A，CAS无法检测
- **内存回收**：无锁数据结构中，节点删除后不能立即释放（其他线程可能还在访问）
  - ** Hazard Pointer**：线程注册正在使用的指针，安全时再释放
  - **Epoch-Based Reclamation**：基于纪元的内存回收
- **复杂度高**：无锁代码难写、难调试、难验证

### 线程池（Thread Pool）

#### 1. 为什么需要线程池
- **线程创建开销大**：创建线程需分配栈、内核数据结构（约1ms）
- **线程数量可控**：避免线程爆炸（成千上万个线程导致上下文切换开销大）
- **任务队列**：缓冲待处理任务，平滑负载

#### 2. 线程池设计
- **任务队列**：
  - 阻塞队列（生产者-消费者模型）
  - 无锁队列（高性能场景）
- **工作线程**：
  - 从任务队列取任务执行
  - 空闲时睡眠（等待新任务）
- **线程管理**：
  - 动态调整线程数（根据任务量）
  - 线程复用（执行完一个任务后取下一个）

#### 3. 线程池类型
- **固定大小线程池**：线程数固定，任务队列无界（可能OOM）
- **缓存线程池**：线程数动态增长，空闲线程回收（适合短任务）
- **单线程线程池**：只有一个工作线程（保证任务顺序执行）
- **定时线程池**：支持延迟/周期性任务执行

## 示例/应用场景

### 场景1：高并发Web服务器
**需求**：处理成千上万个并发HTTP请求

**并发设计**：
1. **事件驱动 + 线程池**：
   - 主线程用epoll监听连接（事件驱动）
   - 工作线程池处理HTTP解析、业务逻辑
2. **无锁队列**：主线程将新连接放入无锁队列，工作线程竞争取出
3. **读写锁**：配置信息用读写锁保护（读多写少）

### 场景2：内存数据库（Redis）
**需求**：微秒级读写延迟，支持高并发

**并发设计**：
1. **单线程事件循环**：
   - 所有命令在主线程顺序执行（无锁）
   - 利用epoll处理并发连接
2. **后台线程**：
   - 异步刷盘（AOF rewrite、RDB快照）
   - 后台线程用互斥锁与主线程同步
3. **原子操作**：INCR、DECR等命令用原子操作实现

### 场景3：分布式存储系统（Ceph）
**需求**：高吞吐、低延迟、数据一致性

**并发设计**：
1. **细粒度锁**：
   - 每个数据对象（Object）有独立锁
   - 不同对象可并行操作
2. **无锁数据结构**：
   - 请求队列用无锁队列
   - 减少锁争用
3. **线程池分离**：
   - 网络I/O线程池
   - 磁盘I/O线程池
   - 业务逻辑线程池

## 【对应领域考点】

1. **竞态条件与临界区**：定义、产生条件、解决方法
2. **同步原语**：互斥锁、读写锁、条件变量、信号量、屏障的区别和适用场景
3. **死锁**：四个必要条件、预防方法、银行家算法
4. **无锁编程**：CAS原理、ABA问题、内存回收（Hazard Pointer）
5. **内存模型**：编译器乱序、CPU乱序、内存屏障、原子操作
6. **线程池**：设计原理、任务队列、线程管理、适用场景
7. **性能优化**：减小临界区、锁分段、读写锁、无锁编程
8. **调试工具**：ThreadSanitizer（检测数据竞争）、Helgrind（Valgrind线程检测）

## 最佳实践

### 1. 锁使用原则
- **最小锁范围**：只锁真正需要保护的代码
- **固定加锁顺序**：避免死锁
- **避免嵌套锁**：如果必须嵌套，固定顺序
- **使用RAII**：C++中用`std::lock_guard`自动加锁/解锁

### 2. 无锁编程适用场景
- **竞争不激烈**：CAS重试次数少
- **性能 critical 路径**：锁开销占比大
- **有专家团队**：无锁代码难写难调试

### 3. 线程池配置
- **线程数 = CPU核心数**：CPU密集型任务
- **线程数 = 2 * CPU核心数**：I/O密集型任务
- **任务队列大小**：根据内存限制设置，避免OOM

### 4. 避免常见陷阱
- **不要共享栈变量**：线程访问栈变量可能已销毁
- **小心优先级反转**：低优先级线程持有锁，高优先级线程等待
- **避免活锁**：线程不断重试但始终无法进展（如两个线程都让路）

### 5. 调试与测试
- **静态分析**：Clang Thread Safety Analysis
- **动态检测**：ThreadSanitizer（编译时加`-fsanitize=thread`）
- **压力测试**：高并发场景下跑长时间（找Heisenbug）

## 【常见错误】

### 错误1：死锁
**表现**：
```c
// 线程1
pthread_mutex_lock(&lockA);
pthread_mutex_lock(&lockB);

// 线程2
pthread_mutex_lock(&lockB);
pthread_mutex_lock(&lockA);
```
**后果**：两个线程互相等待，程序挂起
**正确做法**：固定加锁顺序（都按A→B顺序）

### 错误2：忘记解锁
**表现**：`pthread_mutex_lock(&lock); /* 忘记pthread_mutex_unlock */`
**后果**：其他线程永远等待锁，死锁
**正确做法**：用RAII（C++）或defer（Go）确保解锁

### 错误3：竞态条件
**表现**：`if (count > 0) count--;`（检查与减少非原子）
**后果**：多个线程同时通过if检查，count变为负数
**正确做法**：用互斥锁或原子操作保护

### 错误4：使用已销毁的线程局部存储
**表现**：线程退出后，其他线程访问其线程局部变量
**后果**：野指针，崩溃或数据错误
**正确做法**：确保线程局部变量生命周期在线程退出前结束

### 错误5：无锁编程中的ABA问题
**表现**：无锁栈中，节点A被弹出后重新分配（仍是A），CAS无法检测变化
**后果**：数据结构损坏
**正确做法**：用双宽CAS（带版本号）或Hazard Pointer

## 总结

并发编程是系统编程的核心技能，能充分利用多核CPU性能。

**关键要点**：
1. **竞态条件**：并发编程最常见Bug来源，需用锁或原子操作保护
2. **锁选择**：根据场景选互斥锁、读写锁、自旋锁
3. **无锁编程**：适合高性能场景，但复杂度高
4. **线程池**：控制线程数，复用线程，平滑负载
5. **调试困难**：需用ThreadSanitizer等工具检测

**学习路径**：
1. 理解操作系统并发原理（进程/线程、调度、同步）
2. 实践Pthreads编程（创建、同步、通信）
3. 学习无锁编程（CAS、内存模型、无锁数据结构）
4. 阅读优秀开源代码（Redis、Nginx、Linux内核）
5. 掌握调试工具（gdb、ThreadSanitizer）

掌握并发编程，能让你设计出高性能、高并发的系统软件。
