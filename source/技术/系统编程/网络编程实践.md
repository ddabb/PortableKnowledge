# 网络编程实践

## 定义

网络编程是**编写通过网络进行通信的软件**的技术。在系统编程中，网络编程直接影响分布式系统、Web服务、云计算的性能。

**核心目标**：
- **高并发**：同时处理数万甚至数百万连接
- **低延迟**：减少网络往返时间（RTT）
- **高吞吐**：最大化带宽利用率
- **可靠性**：处理网络故障、超时、重传

**网络编程层次**：
```
应用层（HTTP/HTTPS、WebSocket）
传输层（TCP/UDP、Socket API）
网络层（IP、路由）
链路层（以太网、WiFi）
物理层（光纤、双绞线）
```

## 核心概念

### 1. Socket（套接字）
- **定义**：网络通信端点，封装了IP地址和端口号
- **类型**：
  - **流式套接字（SOCK_STREAM）**：TCP，可靠、有序、面向连接
  - **数据报套接字（SOCK_DGRAM）**：UDP，不可靠、无序、无连接
  - **原始套接字（SOCK_RAW）**：直接访问IP层（需root权限）
- **关键API**：socket()、bind()、listen()、accept()、connect()、send()、recv()

### 2. TCP状态机
- **三次握手（建立连接）**：
  1. Client → SYN → Server
  2. Server → SYN-ACK → Client
  3. Client → ACK → Server
- **四次挥手（关闭连接）**：
  1. A → FIN → B（A不再发送数据）
  2. B → ACK → A（B确认）
  3. B → FIN → A（B不再发送数据）
  4. A → ACK → B（A确认）
- **状态**：LISTEN、SYN_SENT、SYN_RECV、ESTABLISHED、FIN_WAIT1、FIN_WAIT2、TIME_WAIT、CLOSE_WAIT、LAST_ACK、CLOSED

### 3. I/O多路复用
- **定义**：单线程监听多个Socket事件
- **系统调用**：
  - **select()**：监听fd_set，最多1024个fd，线性扫描
  - **poll()**：监听pollfd数组，无数量限制，仍线性扫描
  - **epoll（Linux）**：事件驱动，只返回就绪fd，O(1)复杂度
- **应用**：Nginx、Redis、Node.js事件循环

### 4. 零拷贝网络传输
- **定义**：数据在内核空间内传输，不拷贝到用户空间
- **技术**：
  - **sendfile()**：文件→套接字直接传输
  - **splice()/tee()**：内核缓冲区之间传输
  - **mmap() + write()**：内存映射减少一次拷贝
- **应用**：Nginx静态文件服务、Kafka日志传输

## 详细内容

### Linux网络编程核心API

#### 1. TCP服务器
```c
// 创建socket
int listen_fd = socket(AF_INET, SOCK_STREAM, 0);

// 绑定地址和端口
struct sockaddr_in addr;
addr.sin_family = AF_INET;
addr.sin_port = htons(8080);
addr.sin_addr.s_addr = INADDR_ANY;
bind(listen_fd, (struct sockaddr*)&addr, sizeof(addr));

// 监听
listen(listen_fd, SOMAXCONN);

// 接受连接
int conn_fd = accept(listen_fd, NULL, NULL);

// 读取数据
char buf[4096];
ssize_t n = read(conn_fd, buf, sizeof(buf));

// 发送数据
write(conn_fd, "Hello", 5);

// 关闭连接
close(conn_fd);
```

#### 2. TCP客户端
```c
// 创建socket
int sock_fd = socket(AF_INET, SOCK_STREAM, 0);

// 连接服务器
struct sockaddr_in addr;
addr.sin_family = AF_INET;
addr.sin_port = htons(8080);
inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr);
connect(sock_fd, (struct sockaddr*)&addr, sizeof(addr));

// 发送数据
write(sock_fd, "Hello", 5);

// 读取响应
char buf[4096];
ssize_t n = read(sock_fd, buf, sizeof(buf));

// 关闭连接
close(sock_fd);
```

#### 3. UDP通信
```c
// 创建socket
int sock_fd = socket(AF_INET, SOCK_DGRAM, 0);

// 发送数据
struct sockaddr_in addr;
addr.sin_family = AF_INET;
addr.sin_port = htons(8080);
inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr);
sendto(sock_fd, "Hello", 5, 0, (struct sockaddr*)&addr, sizeof(addr));

// 接收数据
char buf[4096];
struct sockaddr_in client_addr;
socklen_t addr_len = sizeof(client_addr);
ssize_t n = recvfrom(sock_fd, buf, sizeof(buf), 0, (struct sockaddr*)&client_addr, &addr_len);
```

### 高性能网络编程技术

#### 1. 事件驱动架构（Event-Driven Architecture）
- **原理**：单线程（或少数线程）通过epoll监听多个连接事件
- **优势**：
  - 减少线程数（避免线程爆炸）
  - 减少上下文切换
  - 提高缓存局部性
- **应用**：Nginx（多进程事件驱动）、Redis（单线程事件循环）、Node.js（事件循环）

#### 2. Reactor模式
- **原理**：
  - **Reactor**：监听事件，分发到事件处理器
  - **Acceptor**：接受新连接
  - **Handler**：处理已建立连接上的读写事件
- **变种**：
  - **单Reactor单线程**：Redis
  - **单Reactor多线程**：主线程处理连接，工作线程处理读写
  - **多Reactor多线程**：Nginx（每个Worker进程一个Reactor）

#### 3. Proactor模式
- **原理**：真正的异步I/O，由内核完成I/O操作后通知应用
- **对比Reactor**：
  - **Reactor**：内核通知就绪，应用自己读写（同步I/O）
  - **Proactor**：内核完成读写，应用处理结果（异步I/O）
- **应用**：Windows IOCP、Linux io_uring

#### 4. 线程池 + 事件驱动混合
- **原理**：
  - 主线程用epoll监听连接（事件驱动）
  - 工作线程池处理业务逻辑（计算密集型）
- **优势**：兼顾高并发（事件驱动）和高计算（线程池）
- **应用**：Apache Traffic Server、某些Web服务器

### 网络性能优化技术

#### 1. TCP优化
- **TCP_NODELAY**：禁用Nagle算法，减少小包延迟
- **SO_REUSEADDR**：允许端口快速重用（TIME_WAIT状态）
- **SO_KEEPALIVE**：启用TCP保活机制
- **TCP BBR**：Google开发的TCP拥塞控制算法，提高带宽利用率
- **TCP Fast Open**：减少三次握手延迟（首次连接仍可优化）

#### 2. 零拷贝优化
- **sendfile()**：文件到套接字直接传输
- **splice()**：内核缓冲区之间传输
- **mmap() + write()**：内存映射减少一次拷贝
- **io_uring**：新一代异步I/O框架，支持零拷贝

#### 3. 内存优化
- **内存池**：预分配连接对象、缓冲区，减少malloc/free
- **缓冲区管理**：使用readv()/writev()分散读/聚集写
- **避免小包**：合并多个小包为一个大包（Nagle算法或应用层合并）

#### 4. 并发模型优化
- **epoll边缘触发（ET）**：只通知一次，减少epoll_wait返回次数
- **epoll水平触发（LT）**：只要就绪就通知，编程简单但可能惊群
- **多线程epoll**：每个线程一个epoll实例（多线程accept可能惊群）

## 示例/应用场景

### 场景1：高性能Web服务器（Nginx）
**需求**：单台服务器支撑10万+并发连接

**网络编程技术**：
1. **事件驱动架构**：每个Worker进程一个epoll实例
2. **零拷贝**：sendfile()直接传输文件到网络套接字
3. **内存池**：预分配内存块，减少malloc/free
4. **无锁设计**：Worker进程间无共享状态，避免锁争用
5. **TCP优化**：TCP_NODELAY、SO_REUSEADDR

### 场景2：内存数据库（Redis）
**需求**：微秒级读写延迟，高并发

**网络编程技术**：
1. **单线程事件循环**：epoll处理并发连接，避免锁开销
2. **内存驻留**：数据全部在内存，避免磁盘I/O
3. **自定义协议**：RESP协议，简单高效
4. **管道化（Pipelining）**：批量执行命令，减少网络往返
5. **零拷贝**：使用writev()聚集写回复

### 场景3：消息队列（Kafka）
**需求**：高吞吐传输日志数据

**网络编程技术**：
1. **零拷贝**：sendfile()直接传输日志文件到网络
2. **批处理**：累积多条消息后一次发送
3. **压缩**：批量压缩消息（gzip、snappy、lz4）
4. **TCP优化**：TCP_BBR拥塞控制算法
5. **异步I/O**：使用io_uring批量提交网络发送请求

## 最佳实践

### 1. 根据场景选择I/O模型
- **高并发连接**：使用epoll（Linux）或kqueue（BSD）
- **低延迟**：禁用Nagle算法（TCP_NODELAY）
- **高吞吐**：使用零拷贝（sendfile、splice）
- **异步I/O**：使用io_uring（Linux 5.1+）

### 2. 避免常见网络编程错误
- **忽略返回值**：检查socket()、bind()、listen()等返回值
- **地址重用**：设置SO_REUSEADDR避免TIME_WAIT
- **缓冲区大小**：调整TCP发送/接收缓冲区大小（SO_SNDBUF、SO_RCVBUF）
- **优雅关闭**：使用shutdown()半关闭，确保数据发送完毕

### 3. 性能优化
- **减少系统调用**：使用readv()/writev()批量I/O
- **内存对齐**：网络数据包按缓存行对齐
- **批处理**：合并多个小包为一个大包
- **TCP优化**：根据场景调整TCP参数

### 4. 调试与测试
- **tcpdump/Wireshark**：抓包分析网络问题
- **netstat/ss**：查看网络连接状态、缓冲区大小
- **iperf**：测试网络带宽
- **ab/siege**：压力测试Web服务器

### 5. 安全编程
- **输入验证**：防止缓冲区溢出（使用strncpy代替strcpy）
- **加密传输**：使用TLS/SSL（OpenSSL）
- **身份验证**：使用证书或API密钥
- **DDoS防护**：限制连接数、速率限制

## 【常见错误】

### 错误1：忽略SIGPIPE信号
**表现**：向已关闭的连接写数据，触发SIGPIPE，进程退出
**后果**：进程崩溃
**正确做法**：忽略SIGPIPE（signal(SIGPIPE, SIG_IGN)）或设置MSG_NOSIGNAL

### 错误2：地址未重用
**表现**：服务器重启时bind()失败（Address already in use）
**后果**：服务器无法快速重启
**正确做法**：设置SO_REUSEADDR（setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt)))

### 错误3：惊群效应（Thundering Herd）
**表现**：多个进程/线程同时监听同一端口，新连接到来时全部被唤醒
**后果**：只有一个进程/线程能处理连接，其他空转
**正确做法**：使用epoll边缘触发（ET）或io_uring

### 错误4：忘记设置非阻塞
**表现**：epoll监听阻塞socket，epoll_wait返回后read()阻塞
**后果**：事件循环卡住，无法处理其他连接
**正确做法**：设置非阻塞（fcntl(fd, F_SETFL, O_NONBLOCK)）

### 错误5：TCP小包问题
**表现**：多次write()小数据（如1字节），网络带宽利用率低
**后果**：网络拥塞，延迟增加
**正确做法**：禁用Nagle算法（TCP_NODELAY）或应用层合并小包

## 总结

网络编程是系统编程的重要技能，直接影响分布式系统、Web服务、云计算的性能。

**关键要点**：
1. **Socket编程**：掌握TCP/UDP Socket API是基础
2. **I/O多路复用**：epoll是高并发网络服务的基石
3. **零拷贝**：sendfile/splice/mmap减少拷贝次数，提升吞吐量
4. **事件驱动架构**：Reactor模式是高性能网络服务器的核心
5. **TCP优化**：根据场景调整TCP参数（TCP_NODELAY、SO_REUSEADDR等）

**学习路径**：
1. 理解计算机网络原理（TCP/IP、HTTP、DNS）
2. 实践Socket编程（TCP/UDP服务器/客户端）
3. 学习高性能网络编程（epoll、Reactor模式、零拷贝）
4. 阅读优秀开源代码（Nginx、Redis、Linux内核网络栈）
5. 掌握网络调试工具（tcpdump、Wireshark、netstat）

掌握网络编程，能让你设计出高性能、高并发的网络服务。
