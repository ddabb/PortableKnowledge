# 进程与线程管理

## 定义

**进程（Process）**是操作系统中**资源分配的基本单位**，包含独立的虚拟地址空间、打开的文件描述符、信号处理等。

**线程（Thread）**是**CPU调度的基本单位**，同一进程内的线程共享地址空间和资源，但有独立的栈和寄存器。

**核心区别**：
| 维度 | 进程 | 线程 |
|------|------|------|
| 资源隔离 | 完全隔离（独立地址空间） | 共享地址空间（除栈外） |
| 创建开销 | 大（需复制页表、创建地址空间） | 小（共享进程资源） |
| 通信方式 | 进程间通信（IPC）：管道、共享内存、消息队列 | 直接读写共享内存（需同步） |
| 容错性 | 一个进程崩溃不影响其他进程 | 一个线程崩溃可能导致整个进程崩溃 |
| 并发能力 | 多进程（真正的并行，多核） | 多线程（并行+并发） |

## 核心概念

### 1. 进程状态（Process States）
- **新建（New）**：进程刚创建，尚未就绪
- **就绪（Ready）**：等待CPU调度
- **运行（Running）**：正在CPU上执行
- **阻塞（Blocked/Waiting）**：等待I/O或其他资源
- **终止（Terminated）**：进程执行完毕或被终止

**状态转换**：
```
New → Ready → Running → Terminated
            ↓
         Blocked → Ready
```

### 2. 线程模型
- **用户级线程（User-Level Thread）**：线程管理在用户态完成，内核无感知（优点：切换快；缺点：一个线程阻塞，整个进程阻塞）
- **内核级线程（Kernel-Level Thread）**：内核管理线程，调度单位为线程（优点：真正并行；缺点：切换开销大）
- **混合线程模型**：用户态线程多路复用到内核态线程（如Solaris）

### 3. 上下文切换（Context Switch）
- **定义**：保存当前任务的CPU状态（寄存器、程序计数器、栈指针），恢复下一个任务的状态
- **开销来源**：
  - 保存/恢复寄存器（必需）
  - TLB刷新（地址空间切换时）
  - CPU缓存失效（冷缓存）
- **优化**：使用线程（共享地址空间，减少TLB刷新）、CPU亲和性（绑定线程到特定CPU核）

### 4. 调度算法（Scheduling Algorithms）
- **先来先服务（FCFS）**：按到达顺序调度，简单但可能导致护航效应（短任务等待长任务）
- **时间片轮转（RR）**：为每个任务分配固定时间片，公平但上下文切换开销大
- **优先级调度（Priority Scheduling）**：高优先级任务先执行，可能导致饥饿（低优先级任务永远不执行）
- **多级反馈队列（MLFQ）**：动态优先级，交互式任务优先级高，计算密集型优先级低
- **完全公平调度器（CFS，Linux）**：基于虚拟运行时间，保证每个任务获得公平CPU时间

## 详细内容

### Linux进程管理实现

#### 1. 进程描述符（task_struct）
- **定义**：Linux内核中描述进程的数据结构
- **关键字段**：
  - `pid`：进程ID
  - `state`：进程状态（TASK_RUNNING、TASK_INTERRUPTIBLE等）
  - `mm`：内存描述符（指向页表、代码段、数据段等）
  - `files`：打开的文件表
  - `parent`/`children`：进程父子关系
  - `cpu`：最后运行的CPU核（用于CPU亲和性）

#### 2. 进程创建（fork/clone）
- **fork()**：
  - 创建子进程，复制父进程地址空间（写时复制，Copy-On-Write）
  - 返回值：父进程返回子进程pid，子进程返回0
  - 开销：复制页表（不复制物理页，仅标记为只读）
- **vfork()**：
  - 子进程共享父进程地址空间，父进程阻塞直到子进程exec或exit
  - 用于避免fork的页表复制开销（但危险，已不推荐使用）
- **clone()**：
  - 可指定共享哪些资源（文件描述符、信号处理、地址空间等）
  - 用于创建线程（共享地址空间）或轻量级进程（部分共享）

#### 3. 进程终止（exit）
- **正常终止**：从main返回、调用exit()、_exit()
- **异常终止**：收到信号（SIGKILL、SIGSEGV等）
- **僵尸进程（Zombie）**：子进程终止后，父进程尚未读取其退出状态，进程表项仍保留
- **孤儿进程（Orphan）**：父进程先于子进程终止，子进程被init（pid=1）接管

### 线程实现与同步

#### 1. POSIX线程（Pthreads）
- **创建线程**：`pthread_create()`
- **线程终止**：`pthread_exit()`、从线程函数返回
- **线程连接**：`pthread_join()`（等待线程终止并回收资源）
- **线程分离**：`pthread_detach()`（线程终止后自动回收资源）

#### 2. 线程同步原语
- **互斥锁（Mutex）**：
  - 确保同一时间只有一个线程进入临界区
  - 类型：普通锁、递归锁、错误检查锁、自适应锁
  - 实现：futex（Fast Userspace Mutex，Linux）
- **读写锁（Read-Write Lock）**：
  - 多个读者可同时访问，写者独占
  - 适用场景：读多写少
- **条件变量（Condition Variable）**：
  - 线程等待某个条件成立
  - 必须与互斥锁配合使用（防止丢失唤醒）
- **信号量（Semaphore）**：
  - 计数器，控制同时访问资源的线程数
  - 二进制信号量（值0/1）类似互斥锁

#### 3. 死锁（Deadlock）
- **定义**：两个或多个线程互相等待对方持有的资源，导致所有线程都无法继续执行
- **四个必要条件**（全部满足才发生死锁）：
  1. **互斥**：资源同时只能被一个线程占用
  2. **持有并等待**：线程持有资源的同时等待其他资源
  3. **不可抢占**：资源不能被强制释放
  4. **循环等待**：存在线程资源的循环等待链
- **预防**：
  - 破坏互斥（使用无锁数据结构）
  - 破坏持有并等待（一次性申请所有资源）
  - 破坏不可抢占（允许抢占）
  - 破坏循环等待（按固定顺序申请资源）

### 进程间通信（IPC）

#### 1. 管道（Pipe）
- **匿名管道**：半双工，用于有亲缘关系的进程（父/子进程）
- **命名管道（FIFO）**：有文件系统路径，可用于无亲缘关系进程

#### 2. 消息队列（Message Queue）
- **定义**：消息的链表，存储在内核中
- **优点**：支持优先级、异步通信
- **缺点**：不适合大量数据传输（内核复制开销）

#### 3. 共享内存（Shared Memory）
- **定义**：多个进程映射同一块物理内存到各自地址空间
- **优点**：最快的IPC（无需内核复制）
- **缺点**：需配合同步原语（如信号量）使用

#### 4. 套接字（Socket）
- **定义**：网络通信端点，可用于本地进程通信（Unix Domain Socket）或网络通信
- **优点**：通用性强，支持不同机器进程通信
- **缺点**：开销比共享内存大

#### 5. 信号（Signal）
- **定义**：向进程发送异步事件通知（如SIGKILL、SIGSEGV）
- **缺点**：信息量少（只能发送信号编号），不可靠（信号处理函数可能被中断）

## 示例/应用场景

### 场景1：Web服务器（Nginx）的进程模型
**需求**：高并发处理HTTP请求，稳定不崩溃

**解决方案**：
1. **多进程模型**：Master进程管理多个Worker进程
2. **Worker进程**：每个Worker是一个事件循环（epoll），处理多个连接
3. **无锁设计**：Worker进程间独立，无共享状态，避免锁争用
4. **优雅重启**：Master进程启动新Worker，旧Worker处理完现有请求后退出

### 场景2：数据库（PostgreSQL）的进程模型
**需求**：处理多个客户端并发查询，保证事务隔离

**解决方案**：
1. **多进程模型**：每个客户端连接对应一个后端进程
2. **共享内存**：用于缓存数据页、锁表等
3. **信号量/条件变量**：用于进程间同步（如WAL写入、锁等待）
4. **连接池**：减少进程创建开销（但PostgreSQL是每连接一进程）

### 场景3：Java应用的线程模型
**需求**：高并发处理HTTP请求，共享数据（如缓存）

**解决方案**：
1. **多线程模型**：每个HTTP请求由一个线程处理
2. **线程池**：复用线程，减少创建/销毁开销
3. **同步机制**：使用synchronized、ReentrantLock、ConcurrentHashMap等
4. **无锁数据结构**：使用CAS（Compare-And-Swap）实现无锁队列、计数器

## 最佳实践

### 1. 进程/线程设计选择
- **CPU密集型**：多进程（避免GIL限制，真正并行）
- **I/O密集型**：多线程或异步（线程在I/O时让出CPU）
- **稳定性要求高**：多进程（一个进程崩溃不影响主服务）
- **数据共享频繁**：多线程（共享内存，需同步）

### 2. 避免死锁
- **固定加锁顺序**：所有线程按相同顺序获取锁
- **超时机制**：使用`pthread_mutex_timedlock()`，超时则释放已持有锁
- **银行家算法**：运行时检测安全状态（理论上可行，实践中少用）

### 3. 减少上下文切换
- **线程池**：复用线程，减少创建/销毁开销
- **CPU亲和性**：绑定线程到特定CPU核，减少缓存失效
- **无锁编程**：使用CAS实现无锁队列、计数器（适用于竞争不激烈场景）

### 4. 调试与监控
- **ps/top**：查看进程CPU/内存使用
- **strace**：跟踪系统调用（进程执行路径）
- **gdb**：调试多线程程序（线程切换、死锁检测）
- **valgrind/helgrind**：检测线程错误（数据竞争、死锁）

## 【常见错误】

### 错误1：忘记join或detach线程
**表现**：`pthread_create(&tid, NULL, func, NULL); /* 忘记pthread_join */`
**后果**：线程终止后资源未回收，成为僵尸线程
**正确做法**：显式调用`pthread_join()`或`pthread_detach()`

### 错误2：死锁
**表现**：
```c
// 线程1
pthread_mutex_lock(&lockA);
pthread_mutex_lock(&lockB);

// 线程2
pthread_mutex_lock(&lockB);
pthread_mutex_lock(&lockA);
```
**后果**：两个线程互相等待，程序挂起
**正确做法**：固定加锁顺序（都按A→B顺序加锁）

### 错误3：竞态条件
**表现**：`if (count == 0) count++;`（检查与增加非原子操作）
**后果**：多个线程同时进入if块，count最终值小于预期
**正确做法**：使用互斥锁或原子操作保护

### 错误4：使用已销毁的线程局部存储
**表现**：线程退出后，其他线程访问其线程局部变量
**后果**：野指针，崩溃或数据错误
**正确做法**：确保线程局部变量生命周期在线程退出前结束

### 错误5：忽略fork后的内存状态
**表现**：`fork()`后子进程继承父进程锁状态，可能导致死锁
**后果**：子进程中锁状态不确定，可能死锁
**正确做法**：`fork()`后子进程立即调用`exec()`，或使用`pthread_atfork()`注册处理函数

## 总结

进程与线程管理是系统编程的基础，直接影响程序并发性、性能和稳定性。

**关键要点**：
1. **进程 vs 线程**：根据场景选择（CPU密集用多进程，I/O密集用多线程）
2. **上下文切换开销**：减少线程数、使用CPU亲和性、无锁编程
3. **同步原语**：互斥锁、条件变量、信号量，防止竞态条件和死锁
4. **IPC选择**：共享内存最快但需同步，套接字最通用但开销大
5. **调试工具**：ps、strace、gdb、valgrind

**学习路径**：
1. 理解操作系统进程/线程模型
2. 实践Pthreads编程（创建、同步、通信）
3. 阅读优秀开源代码（Nginx、Redis、PostgreSQL）
4. 掌握调试工具（gdb、strace、valgrind）

掌握进程与线程管理，能让你设计出高性能、高并发的系统软件。
