# 共享内存并行

## 定义

共享内存并行是**多个处理器（或核心）通过共享同一内存空间协同工作**的并行计算范式。线程间通过读写共享内存通信，无需显式消息传递。

**核心特征**：
- **共享地址空间**：所有线程看到同一内存视图
- **低通信开销**：通信通过共享变量（纳秒级延迟）
- **编程简单**：无需显式数据搬运（对比分布式内存）
- **可扩展性有限**：通常≤128核（NUMA效应）

**共享内存 vs 分布式内存**：
| 维度 | 共享内存 | 分布式内存 |
|------|----------|--------------|
| 通信方式 | 共享变量（低延迟） | 消息传递（高延迟） |
| 编程模型 | OpenMP、Pthreads | MPI |
| 可扩展性 | 低（≤128核） | 高（数千核） |
| 数据一致性 | 需同步（锁、屏障） | 天生一致（无共享） |
| 容错性 | 差（一个线程崩溃影响所有） | 好（进程隔离） |

## 核心概念

### 1. OpenMP
- **定义**：共享内存并行编程的**行业标准**，基于编译器指令
- **核心机制**：
  - **Fork-Join模型**：主线程创建多个工作线程，执行完合并
  - **编译器指令**：`#pragma omp parallel for`
  - **运行时库**：`omp_get_thread_num()`、`omp_get_num_threads()`
- **优势**：
  - 增量并行化（串行代码加指令即并行）
  - 跨平台（支持C/C++/Fortran）
  - 自动负载均衡

### 2. 线程同步
- **临界区（Critical Section）**：
  - `#pragma omp critical`：同一时间只有一个线程执行
  - 适用：更新共享变量
- **原子操作（Atomic）**：
  - `#pragma omp atomic`：原子更新共享变量
  - 比critical更高效
- **屏障（Barrier）**：
  - `#pragma omp barrier`：所有线程到达后才能继续
  - 隐式屏障：parallel region结束处
- **锁（Lock）**：
  - `omp_lock_t`：显式锁，类似Pthreads的mutex

### 3. 数据作用域
- **共享（Shared）**：所有线程共享（默认）
- **私有（Private）**：每个线程有独立副本
  - `#pragma omp parallel private(x)`
- **线程局部（Threadprivate）**：全局变量的线程局部副本
  - `#pragma omp threadprivate(x)`
- **归约（Reduction）**：
  - `#pragma omp parallel for reduction(+:sum)`
  - 每个线程有局部副本，结束时归约

### 4. NUMA（Non-Uniform Memory Access）
- **定义**：多CPU插槽系统中，内存访问时间取决于内存相对于CPU的位置
- **问题**：
  - 访问本地内存：快（~100ns）
  - 访问远程内存：慢（~200ns）
- **优化**：
  - **线程绑定（Thread Pinning）**：将线程绑定到最近的内存控制器
  - **内存交织（Memory Interleaving）**：内存分布在所有控制器上

## 详细内容

### OpenMP编程基础

#### 1. Hello World示例
```c
#include <omp.h>
#include <stdio.h>

int main() {
    #pragma omp parallel
    {
        int tid = omp_get_thread_num();
        int nthreads = omp_get_num_threads();
        printf("Hello from thread %d of %d\n", tid, nthreads);
    }
    return 0;
}
```

#### 2. 并行循环
```c
#include <omp.h>
#include <stdio.h>

int main() {
    int n = 1000000;
    double a[n], b[n], c[n];

    // 初始化
    for (int i = 0; i < n; i++) {
        a[i] = i * 0.5;
        b[i] = i * 2.0;
    }

    // 并行化循环
    #pragma omp parallel for
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }

    printf("c[0] = %f, c[%d] = %f\n", c[0], n-1, c[n-1]);
    return 0;
}
```

#### 3. 归约操作
```c
#include <omp.h>
#include <stdio.h>

int main() {
    int n = 1000000;
    double a[n];
    double sum = 0.0;

    // 初始化
    for (int i = 0; i < n; i++) {
        a[i] = i * 0.5;
    }

    // 并行归约
    #pragma omp parallel for reduction(+:sum)
    for (int i = 0; i < n; i++) {
        sum += a[i];
    }

    printf("Sum = %f\n", sum);
    return 0;
}
```

### OpenMP性能优化

#### 1. 负载均衡
- **静态调度（Static Scheduling）**：
  - `#pragma omp parallel for schedule(static)`
  - 循环迭代均匀划分给线程
  - 适用：每次迭代工作量相同
- **动态调度（Dynamic Scheduling）**：
  - `#pragma omp parallel for schedule(dynamic, chunk)`
  - 线程完成工作后请求更多迭代
  - 适用：每次迭代工作量不同
- **导向调度（Guided Scheduling）**：
  - `#pragma omp parallel for schedule(guided)`
  - 初始chunk大，逐渐减小
  - 适用：迭代工作量逐渐减少

#### 2. 数据局部性
- **缓存优化**：
  - 让同一线程处理相邻数据（提高缓存命中率）
  - 使用`schedule(static, chunk)`确保数据局部性
- **NUMA优化**：
  - 使用`OMP_PROC_BIND=TRUE`绑定线程到CPU核心
  - 使用`OMP_PLACES=cores`指定线程放置位置

#### 3. 减少同步开销
- **避免频繁临界区**：
  - 临界区串行化，降低并行效率
  - 用归约（reduction）代替临界区
- **使用原子操作**：
  - 原子操作比临界区轻量
  - 适用：简单更新（如`x++`）
- **最小化屏障**：
  - 隐式屏障在parallel region结束处
  - 使用`nowait`子句消除不必要的屏障

### OpenMP与MPI混合编程

#### 1. 混合模型
- **节点内**：OpenMP共享内存并行
- **节点间**：MPI分布式内存并行
- **优势**：
  - 结合两者优点
  - 提高可扩展性
  - 减少MPI通信量
- **应用**：现代超级计算机（如Fugaku、Summit）

#### 2. 编程模式
```c
#include <mpi.h>
#include <omp.h>
#include <stdio.h>

int main(int argc, char** argv) {
    MPI_Init(&argc, &argv);

    int rank, size;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    #pragma omp parallel
    {
        int tid = omp_get_thread_num();
        int nthreads = omp_get_num_threads();
        printf("MPI rank %d, OpenMP thread %d of %d\n", rank, tid, nthreads);
    }

    MPI_Finalize();
    return 0;
}
```

## 示例/应用场景

### 场景1：矩阵乘法
**需求**：加速大矩阵乘法

**共享内存并行技术**：
1. **并行循环**：`#pragma omp parallel for`并行化外层循环
2. **归约**：使用`reduction`归约局部结果
3. **负载均衡**：使用`schedule(dynamic)`处理不规则计算
4. **缓存优化**：调整循环顺序，提高缓存命中率

### 场景2：图像处理
**需求**：并行处理图像滤波器（如高斯模糊）

**共享内存并行技术**：
1. **数据并行**：每个线程处理不同图像块
2. **私有变量**：每个线程有独立的临时缓冲区
3. **同步**：使用屏障确保 all threads完成当前阶段
4. **NUMA优化**：线程绑定到最近的内存控制器

### 场景3：蒙特卡洛模拟
**需求**：并行执行多次模拟，汇总结果

**共享内存并行技术**：
1. **并行循环**：`#pragma omp parallel for`并行化模拟循环
2. **归约**：使用`reduction(+:sum, +:sum_sq)`归约统计值
3. **随机数生成**：每个线程有独立的随机数生成器（避免竞争）
4. **动态调度**：使用`schedule(dynamic)`平衡负载

## 最佳实践

### 1. 并行化策略
- **增量并行化**：先串行调试通过，再加OpenMP指令
- **剖面引导**：用profiling工具找到热点循环，优先并行化
- **避免伪共享**：线程私有的频繁访问变量需缓存行对齐

### 2. 数据管理
- **最小化共享**：尽量使用私有变量或线程局部变量
- **归约代替临界区**：归约更高效，且减少同步开销
- **注意false sharing**：不同线程写同一缓存行不同变量

### 3. 性能调优
- **选择合适的调度**：根据迭代工作量选择static/dynamic/guided
- **设置线程数**：`OMP_NUM_THREADS`设置为物理核心数（勿超线程）
- **绑定线程**：`OMP_PROC_BIND=TRUE`减少上下文切换

### 4. 调试与测试
- **编译选项**：`-fopenmp -g`启用OpenMP和调试信息
- **线程检查器**：Intel Inspector、ThreadSanitizer检测数据竞争
- **性能分析**：Intel VTune、TAU分析OpenMP程序性能瓶颈

### 5. 常见陷阱
- **忽略数据竞争**：共享变量未保护，导致结果不确定
- **过度同步**：频繁屏障/临界区，串行化严重
- **错误作用域**：变量作用域设置错误，导致错误结果

## 【常见错误】

### 错误1：数据竞争
**表现**：
```c
int sum = 0;
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    sum += a[i];  // 多个线程同时更新sum，数据竞争
}
```
**后果**：结果不确定，每次运行可能不同
**正确做法**：使用`reduction(+:sum)`或`#pragma omp atomic`

### 错误2：死锁
**表现**：
```c
#pragma omp parallel
{
    #pragma omp critical
    {
        // 临界区1
        #pragma omp critical  // 同一临界区，死锁
        {
            // 临界区2
        }
    }
}
```
**后果**：线程互相等待，程序挂起
**正确做法**：避免嵌套临界区，或使用不同临界区名

### 错误3：假共享（False Sharing）
**表现**：
```c
int counter[4];  // 4个线程各用一个计数器，但可能在同一缓存行
#pragma omp parallel for
for (int i = 0; i < 4; i++) {
    for (int j = 0; j < 1000000; j++) {
        counter[i]++;  // 频繁写同一缓存行，假共享
    }
}
```
**后果**：缓存频繁失效，性能下降10倍+
**正确做法**：缓存行对齐（`alignas(64)`）

### 错误4：过度并行化
**表现**：并行化小循环（迭代次数<线程数）
**后果**：线程创建/销毁开销大于并行收益
**正确做法**：只并行化计算密集型循环（迭代次数>>线程数）

### 错误5：忽略NUMA
**表现**：线程访问远程内存（非本地内存控制器）
**后果**：内存访问延迟加倍，性能下降
**正确做法**：绑定线程到最近的内存控制器（`OMP_PROC_BIND=TRUE`）

## 总结

共享内存并行是**多核CPU并行编程**的主流技术，OpenMP是其标准。

**关键要点**：
1. **OpenMP编程**：掌握Fork-Join模型、编译器指令、运行时库
2. **线程同步**：根据场景选择临界区、原子操作、屏障、锁
4. **性能优化**：负载均衡、缓存优化、NUMA优化、减少同步开销
5. **混合编程**：OpenMP+MPI结合，适应现代超级计算机架构

**学习路径**：
1. 理解共享内存并行原理（缓存一致性、内存模型）
2. 学习OpenMP编程（官方教程、在线课程）
3. 实践经典算法（矩阵乘法、图像处理、蒙特卡洛模拟）
4. 使用性能分析工具（Intel VTune、TAU）
5. 参与实际项目（科学计算、数据分析、工程仿真）

掌握共享内存并行，能让你充分利用多核CPU的计算能力。
