# 分布式内存并行

## 定义

分布式内存并行是**利用多台独立计算机（节点）通过高速网络连接协同解决大规模问题**的并行计算范式。每个节点拥有独立的内存，节点间通过消息传递（Message Passing）通信。

**核心特征**：
- **独立内存**：每个节点有自己的内存空间，不共享
- **消息传递**：节点间通过发送/接收消息通信（如MPI）
- **高可扩展性**：可扩展至数千甚至数百万核心
- **容错性**：单节点故障不影响整体（需检查点机制）

**分布式内存 vs 共享内存**：
| 维度 | 分布式内存 | 共享内存 |
|------|------------|----------|
| 内存模型 | 独立内存，消息传递 | 共享内存，直接访问 |
| 编程模型 | MPI、RPC | OpenMP、Pthreads |
| 可扩展性 | 高（数千节点） | 低（通常≤128核） |
| 通信开销 | 高（网络延迟微秒级） | 低（共享内存纳秒级） |
| 容错性 | 较好（节点故障隔离） | 差（一个故障可能影响整个系统） |

## 核心概念

### 1. MPI（Message Passing Interface）
- **定义**：分布式内存并行编程的**标准接口**，而非具体实现
- **实现**：
  - **Open MPI**：开源，应用最广
  - **MPICH**：开源，可移植性好
  - **Intel MPI**：商业，高度优化（针对Intel硬件）
- **核心概念**：
  - **Communicator**：通信域（如`MPI_COMM_WORLD`包含所有进程）
  - **Rank**：进程在通信域中的唯一标识（从0开始）
  - **Group**：通信域内进程的集合
- **通信模式**：
  - **点对点通信（Point-to-Point）**：两个进程间通信
  - **集合通信（Collective）**：通信域内所有进程参与

### 2. 点对点通信
- **阻塞通信**：
  - `MPI_Send()`：发送数据，阻塞直到数据可重用
  - `MPI_Recv()`：接收数据，阻塞直到数据接收完成
  - **问题**：可能死锁（循环发送/接收）
- **非阻塞通信**：
  - `MPI_Isend()`：发起发送，立即返回
  - `MPI_Irecv()`：发起接收，立即返回
  - `MPI_Wait()`/`MPI_Test()`：等待/测试非阻塞操作完成
  - **优势**：可重叠计算与通信

### 3. 集合通信
- **广播（Broadcast）**：一个进程将数据发送给所有其他进程
  - `MPI_Bcast()`
- **分散（Scatter）**：一个进程将数据分散到所有进程
  - `MPI_Scatter()`
- **聚集（Gather）**：所有进程将数据发送到同一个进程
  - `MPI_Gather()`
- **归约（Reduce）**：所有进程对数据执行操作（如求和）后发送给一个进程
  - `MPI_Reduce()`
- **全归约（All-Reduce）**：归约后结果分发给所有进程
  - `MPI_Allreduce()`
- **全交换（All-to-All）**：所有进程互相交换数据
  - `MPI_Alltoall()`

### 4. 通信拓扑
- **定义**：进程间通信模式
- **常见拓扑**：
  - **环形（Ring）**：每个进程与两个邻居通信
  - **网格（Mesh）**：多维网格，每个进程与邻居通信
  - **树形（Tree）**：广播、归约的高效拓扑
  - **超立方体（Hypercube）**：高维网格，通信效率高

## 详细内容

### MPI编程基础

#### 1. Hello World示例
```c
#include <mpi.h>
#include <stdio.h>

int main(int argc, char** argv) {
    MPI_Init(&argc, &argv);  // 初始化MPI环境

    int rank, size;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);  // 获取当前进程rank
    MPI_Comm_size(MPI_COMM_WORLD, &size);  // 获取总进程数

    printf("Hello from process %d of %d\n", rank, size);

    MPI_Finalize();  // 结束MPI环境
    return 0;
}
```

#### 2. 点对点通信示例
```c
#include <mpi.h>
#include <stdio.h>

int main(int argc, char** argv) {
    MPI_Init(&argc, &argv);

    int rank, size;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    if (size < 2) {
        fprintf(stderr, "This program requires at least 2 processes\n");
        MPI_Abort(MPI_COMM_WORLD, 1);
    }

    int data = 0;
    if (rank == 0) {
        data = 42;
        MPI_Send(&data, 1, MPI_INT, 1, 0, MPI_COMM_WORLD);
        printf("Process 0 sent %d to process 1\n", data);
    } else if (rank == 1) {
        MPI_Recv(&data, 1, MPI_INT, 0, 0, MPI_COMM_WORLD, MPI_STATUS_IGNORE);
        printf("Process 1 received %d from process 0\n", data);
    }

    MPI_Finalize();
    return 0;
}
```

#### 3. 集合通信示例（归约）
```c
#include <mpi.h>
#include <stdio.h>

int main(int argc, char** argv) {
    MPI_Init(&argc, &argv);

    int rank, size;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    int local_data = rank + 1;  // 每个进程有不同数据
    int sum = 0;
    MPI_Reduce(&local_data, &sum, 1, MPI_INT, MPI_SUM, 0, MPI_COMM_WORLD);

    if (rank == 0) {
        printf("Sum of all data = %d\n", sum);  // 应为 1+2+...+size
    }

    MPI_Finalize();
    return 0;
}
```

### MPI性能优化

#### 1. 减少通信开销
- **合并小消息**：将多个小消息合并为一个大消息
- **非阻塞通信**：重叠计算与通信
- **拓扑感知通信**：根据集群网络拓扑优化通信路径
- **使用派生数据类型**：减少通信次数（如发送不连续数据）

#### 2. 负载均衡
- **静态负载均衡**：根据问题特性预先分配任务
- **动态负载均衡**：使用任务池（Master-Worker模式）
- **示例**：矩阵乘法中，按行循环划分 vs 块划分

#### 3. 集合通信优化
- **选择高效算法**：
  - 广播：树形广播（O(log N)）代替线性广播（O(N)）
  - 归约：树形归约（O(log N)）代替线性归约（O(N)）
- **使用MPI内置优化**：MPI实现已针对硬件优化

#### 4. 进程绑定（Process Pinning）
- **定义**：将MPI进程绑定到特定CPU核心
- **优势**：减少上下文切换，提高缓存局部性
- **方法**：
  - `mpirun --bind-to core`
  - `export OMP_PROC_BIND=TRUE`（OpenMP绑定）

### 分布式内存并行算法设计

#### 1. 域分解（Domain Decomposition）
- **思想**：将计算域划分为子域，每个进程负责一个子域
- **关键**：
  - **负载均衡**：各子域计算量尽量均等
  - **通信最小化**：减少子域间边界数据交换
- **应用**：计算流体力学（CFD）、有限元分析（FEA）

#### 2. 流水线并行（Pipeline Parallelism）
- **思想**：将任务分解为多个阶段，不同阶段并行执行
- **关键**：
  - **阶段划分**：各阶段计算量尽量均等
  - **缓冲管理**：避免上游过快导致缓冲区溢出
- **应用**：信号处理、数据流处理

#### 3. 主从模式（Master-Worker）
- **思想**：主进程分配任务，工作进程执行任务
- **关键**：
  - **动态负载均衡**：工作进程空闲时向主进程请求任务
  - **容错**：工作进程故障时，主进程重新分配任务
- **应用**：参数扫描、蒙特卡洛模拟

## 示例/应用场景

**需求**：全球天气预测，需处理PB级观测数据，计算量达数十PFLOPS

**分布式内存并行技术**：
1. **域分解**：将全球网格划分为子域，分配给不同进程
2. **Halo交换**：子域边界数据需从邻居进程获取（MPI_Send/MPI_Recv）
3. **集合通信**：归约全局统计量（如全球平均温度）
4. **I/O并行**：使用MPI-IO或并行文件系统（Lustre）并发读写

### 场景2：深度学习训练（如GPT-3）
**需求**：千亿参数模型训练，需数千GPU协同计算

**分布式内存并行技术**：
1. **数据并行**：每GPU处理不同数据批次，梯度聚合（MPI_Allreduce）
2. **模型并行**：将模型切分到多GPU（张量并行、流水线并行）
3. **混合并行**：数据并行+模型并行，适应超大模型
4. **通信优化**：使用梯度压缩、All-Reduce优化（Ring All-Reduce）

### 场景3：计算流体力学（如飞机气动设计）
**需求**：模拟飞机周围气流，网格点数达数十亿

**分布式内存并行技术**：
1. **域分解**：将计算域划分为子域，分配给不同进程
2. **Halo交换**：子域边界数据交换（MPI_Send/MPI_Recv）
3. **负载均衡**：根据网格密度动态调整子域大小
4. **集合通信**：归约残差、收敛判据

## 最佳实践

### 1. 通信优化
- **减少通信量**：合并小消息，使用派生数据类型
- **重叠计算与通信**：使用非阻塞通信
- **拓扑感知**：根据集群网络拓扑优化通信路径

### 2. 负载均衡
- **静态负载均衡**：根据问题特性预先分配任务
- **动态负载均衡**：使用任务池（Master-Worker模式）

### 3. 调试与性能分析
- **调试工具**：TotalView、gdb（配合MPI调试支持）
- **性能分析**：TAU、Vampir、Intel Trace Analyzer
- **正确性验证**：小规模问题用串行代码验证

### 4. 可扩展性
- **强可扩展性**：固定问题规模，增加进程数，时间成比例减少
- **弱可扩展性**：增加进程数同时增加问题规模，时间保持不变
- **避免串行瓶颈**：确保串行部分不随规模扩大而增加

### 5. 容错性
- **检查点机制**：定期保存计算状态，故障时从检查点恢复
- **故障检测**：使用MPI错误处理程序
- **冗余计算**：关键任务使用冗余进程

## 【常见错误】

### 错误1：死锁
**表现**：
```c
// 进程0和进程1都先发送后接收
if (rank == 0) {
    MPI_Send(..., 1, ...);
    MPI_Recv(..., 1, ...);
} else if (rank == 1) {
    MPI_Send(..., 0, ...);
    MPI_Recv(..., 0, ...);
}
```
**后果**：两个进程互相等待，程序挂起
**正确做法**：使用`MPI_Sendrecv()`或调整发送/接收顺序

### 错误2：缓冲区溢出
**表现**：接收缓冲区小于发送数据量
**后果**：缓冲区溢出，数据损坏或程序崩溃
**正确做法**：确保接收缓冲区足够大，使用`MPI_Get_count()`获取实际接收数据量

### 错误3：忽略MPI错误处理
**表现**：MPI调用失败后未处理
**后果**：程序行为不可预测
**正确做法**：检查MPI返回值，使用`MPI_Error_string()`打印错误信息

### 错误4：负载不均衡
**表现**：某些进程计算量大，其他进程空闲
**后果**：整体性能受限于最慢的进程
**正确做法**：使用动态负载均衡（如任务池）

### 错误5：过度通信
**表现**：频繁小消息通信（如每次迭代都广播）
**后果**：通信开销大于计算开销
**正确做法**：合并通信（大消息）、异步通信、重叠计算与通信
