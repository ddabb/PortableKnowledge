# 异构计算

## 定义

异构计算是**使用不同类型计算单元（CPU+GPU+FPGA+ASIC）协同执行计算任务**的技术。不同计算单元有各自优势，组合使用可最大化性能/功耗比。

**核心思想**：
- **因材施教**：将合适任务分配给合适计算单元
- **协同执行**：多个计算单元同时工作，提高整体吞吐量
- **性能/功耗优化**：用专用硬件加速特定任务

**异构计算 vs 同构计算**：
| 维度 | 异构计算 | 同构计算 |
|------|----------|----------|
| 计算单元 | 多种（CPU+GPU+FPGA+ASIC） | 单一（全是CPU或全是GPU） |
| 编程复杂度 | 高（需管理数据迁移、同步） | 低（统一编程模型） |
| 性能/功耗比 | 高（专用硬件加速） | 低（通用硬件） |
| 灵活性 | 中（依赖硬件特性） | 高（通用编程） |
| 适用场景 | AI训练、科学计算、信号处理 | 通用计算、业务逻辑 |

## 核心概念

### 1. 计算单元类型
- **CPU（Central Processing Unit）**：
  - 优势：复杂逻辑控制、任务调度、串行任务
  - 劣势：并行计算能力弱（核心数少）
  - 适用：操作系统、业务逻辑、控制流
- **GPU（Graphics Processing Unit）**：
  - 优势：大规模数据并行计算（数千核心）
  - 劣势：控制逻辑弱、分支发散严重
  - 适用：矩阵运算、图像处理、深度学习
- **FPGA（Field-Programmable Gate Array）**：
  - 优势：可定制硬件电路、低延迟、低功耗
  - 劣势：编程复杂（硬件描述语言）、时钟频率低
  - 适用：信号处理、金融高频交易、嵌入式
- **ASIC（Application-Specific Integrated Circuit）**：
  - 优势：极致性能、最低功耗
  - 劣势：不可重构、设计成本高、周期长
  - 适用：专用场景（如TPU、NPU、比特币矿机）

### 2. 异构编程模型
- **CUDA（Compute Unified Device Architecture）**：
  - NVIDIA GPU专有编程模型
  - 语言：C/C++扩展
  - 优势：生态成熟、性能极高
  - 劣势：绑定NVIDIA硬件
- **OpenCL（Open Computing Language）**：
  - 跨平台异构编程标准（支持CPU、GPU、FPGA、DSP）
  - 语言：C99扩展
  - 优势：跨平台、vendor中立
  - 劣势：编程复杂、性能不如CUDA（NVIDIA GPU上）
- **SYCL（C++ Single-source Heterogeneous Programming）**：
  - 基于C++标准的异构编程模型（Khronos Group）
  - 语言：C++11及以上
  - 优势：类型安全、现代C++特性、跨平台
  - 劣势：生态尚在发展中
- **HIP（Heterogeneous-Compute Interface for Portability）**：
  - AMD推出的CUDA兼容层
  - 可将CUDA代码转换为AMD GPU代码
  - 优势：CUDA代码可移植到AMD GPU
  - 劣势：仅支持AMD GPU和NVIDIA GPU

### 3. 异构计算架构
- **CPU-GPU异构**：
  - CPU负责逻辑控制、任务调度
  - GPU负责并行计算（如深度学习训练、科学计算）
  - 通信：PCIe（~32GB/s）、NVLink（~900GB/s）
- **CPU-FPGA异构**：
  - CPU负责复杂逻辑、FPGA负责计算密集型任务
  - 通信：PCIe、AXI总线（嵌入式）
  - 适用：信号处理、高频交易
- **多GPU异构**：
  - 多个GPU协同计算（如数据并行、模型并行）
  - 通信：NVLink、InfiniBand
  - 适用：大模型训练（GPT-3、GPT-4）

### 4. 数据传输与同步
- **主机（Host）**：CPU及其内存
- **设备（Device）**：GPU/FPGA及其内存
- **数据传输**：
  - `cudaMemcpy()`：CPU ↔ GPU数据传输
  - 高延迟（约10微秒级）
  - 优化：尽量减少传输，使用固定内存（Pinned Memory）
- **同步**：
  - `cudaDeviceSynchronize()`：等待GPU完成所有任务
  - 异步执行：GPU计算与CPU计算可重叠

## 详细内容

### 异构编程实践（CUDA）

#### 1. 基本异构程序结构
```c
#include <cuda_runtime.h>
#include <stdio.h>

// GPU内核函数（在GPU上执行）
__global__ void vectorAdd(float* A, float* B, float* C, int N) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < N) {
        C[i] = A[i] + B[i];
    }
}

int main() {
    int N = 1024;
    size_t size = N * sizeof(float);

    // 1. 分配主机内存
    float *h_A = (float*)malloc(size);
    float *h_B = (float*)malloc(size);
    float *h_C = (float*)malloc(size);

    // 初始化数据
    for (int i = 0; i < N; i++) {
        h_A[i] = i * 0.5f;
        h_B[i] = i * 2.0f;
    }

    // 2. 分配设备内存
    float *d_A, *d_B, *d_C;
    cudaMalloc(&d_A, size);
    cudaMalloc(&d_B, size);
    cudaMalloc(&d_C, size);

    // 3. 数据传输：主机 → 设备
    cudaMemcpy(d_A, h_A, size, cudaMemcpyHostToDevice);
    cudaMemcpy(d_B, h_B, size, cudaMemcpyHostToDevice);

    // 4. 启动GPU内核
    int threadsPerBlock = 256;
    int blocksPerGrid = (N + threadsPerBlock - 1) / threadsPerBlock;
    vectorAdd<<<blocksPerGrid, threadsPerBlock>>>(d_A, d_B, d_C, N);

    // 5. 同步（等待GPU完成）
    cudaDeviceSynchronize();

    // 6. 数据传输：设备 → 主机
    cudaMemcpy(h_C, d_C, size, cudaMemcpyDeviceToHost);

    // 7. 验证结果
    for (int i = 0; i < 10; i++) {
        printf("C[%d] = %f\n", i, h_C[i]);
    }

    // 8. 清理
    cudaFree(d_A);
    cudaFree(d_B);
    cudaFree(d_C);
    free(h_A);
    free(h_B);
    free(h_C);

    return 0;
}
```

#### 2. 性能优化关键点
- **尽量减少主机-设备数据传输**：
  - 传输延迟高（约10微秒级）
  - 尽量在GPU上完成所有计算，只传结果回CPU
- **使用固定内存（Pinned Memory）**：
  - `cudaMallocHost()`分配页锁定内存
  - 传输速度比可分页内存快2-5倍
- **异步执行**：
  - 使用CUDA流（Stream）实现CPU-GPU并行
  - 示例：`cudaMemcpyAsync()` + `kernel<<<..., stream>>>` + `cudaMemcpyAsync()`
- ** occupancy优化**：
  - 每个SM上活跃warp数与最大warp数之比
  - 受限于寄存器数量、共享内存大小

### OpenCL跨平台异构编程

#### 1. OpenCL程序基本结构
```c
#include <CL/cl.h>
#include <stdio.h>

int main() {
    // 1. 获取平台和设备
    cl_platform_id platform;
    cl_device_id device;
    clGetPlatformIDs(1, &platform, NULL);
    clGetDeviceIDs(platform, CL_DEVICE_TYPE_GPU, 1, &device, NULL);

    // 2. 创建上下文和命令队列
    cl_context context = clCreateContext(NULL, 1, &device, NULL, NULL, NULL);
    cl_command_queue queue = clCreateCommandQueue(context, device, 0, NULL);

    // 3. 创建缓冲区
    cl_mem bufferA = clCreateBuffer(context, CL_MEM_READ_WRITE, size, NULL, NULL);
    // ... 类似创建bufferB, bufferC

    // 4. 编写内核代码（字符串形式）
    const char* kernelSource = 
        "__kernel void vectorAdd(__global float* A, __global float* B, __global float* C) {"
        "    int i = get_global_id(0);"
        "    C[i] = A[i] + B[i];"
        "}";

    // 5. 编译内核
    cl_program program = clCreateProgramWithSource(context, 1, &kernelSource, NULL, NULL);
    clBuildProgram(program, 1, &device, NULL, NULL, NULL);

    // 6. 创建内核对象并设置参数
    cl_kernel kernel = clCreateKernel(program, "vectorAdd", NULL);
    clSetKernelArg(kernel, 0, sizeof(cl_mem), &bufferA);
    // ... 设置其他参数

    // 7. 启动内核
    size_t globalSize = N;
    clEnqueueNDRangeKernel(queue, kernel, 1, NULL, &globalSize, NULL, 0, NULL, NULL);

    // 8. 读取结果
    clEnqueueReadBuffer(queue, bufferC, CL_TRUE, 0, size, h_C, 0, NULL, NULL);

    // 9. 清理
    clReleaseMemObject(bufferA);
    // ... 释放其他资源

    return 0;
}
```

#### 2. OpenCL vs CUDA
| 维度 | OpenCL | CUDA |
|------|--------|------|
| 跨平台性 | 高（支持多vendor） | 低（仅NVIDIA） |
| 编程复杂度 | 高（C99风格，冗长） | 中（C++风格，相对简洁） |
| 性能（NVIDIA GPU） | 略低（驱动优化不如CUDA） | 最高（NVIDIA官方优化） |
| 生态成熟度 | 中（工业界使用较少） | 高（AI、HPC主流） |
| 学习曲线 | 陡（概念多） | 中（文档丰富） |

## 示例/应用场景

### 场景1：深度学习训练（GPT-3、视觉Transformer）
**需求**：训练千亿参数模型，需数千GPU协同计算

**异构计算技术**：
1. **CPU+多GPU异构**：
   - CPU负责数据加载、预处理、任务调度
   - GPU负责矩阵运算、卷积、激活函数
2. **多GPU并行策略**：
   - 数据并行：每GPU处理不同数据批次，梯度聚合（All-Reduce）
   - 模型并行：将模型切分到多GPU（张量并行、流水线并行）
3. **高速互连**：
   - NVLink：GPU间直接通信（~900GB/s）
   - InfiniBand：节点间通信（~200Gb/s）
4. **混合精度训练**：
   - FP16计算、FP32累加，加速训练且节省显存

### 场景2：计算流体力学（飞机气动设计、汽车风阻优化）
**需求**：模拟飞机周围气流，网格点数达数十亿

**异构计算技术**：
1. **CPU+多GPU异构**：
   - CPU负责I/O、负载均衡、检查点
   - GPU负责求解器计算（如稀疏矩阵求解）
2. **域分解**：
   - 将计算域划分为子域，分配给不同GPU
   - GPU间通过MPI交换边界数据（Halo交换）
3. **GPU内存优化**：
   - 使用共享内存缓存频繁访问数据
   - 合并访问（Coalesced Access）提高显存带宽利用率
4. **混合并行**：
   - 节点内：OpenMP+MPI
   - 节点间：MPI+CUDA

### 场景3：高频交易（金融）
**需求**：微秒级延迟执行交易策略

**异构计算技术**：
1. **CPU+FPGA异构**：
   - CPU负责复杂逻辑（如风险管理、合规检查）
   - FPGA负责低延迟计算（如期权定价、信号处理逻辑）
2. **硬件加速**：
   - FPGA可实现流水线并行、超低延迟（纳秒级）
   - 使用硬件描述语言（Verilog/VHDL）定制电路
3. **网络优化**：
   - 使用Solarflare/Xilinx低延迟网卡
   - 内核旁路（Kernel Bypass）技术（如DPDK、Solarflare OpenOnload）
4. **时间确定性**：
   - FPGA硬件电路延迟固定（无操作系统调度开销）
   - 满足金融交易的时间确定性要求

## 【对应领域考点】

1. **异构计算定义**：使用多种计算单元协同计算，优势（性能/功耗比高）
2. **计算单元类型**：CPU（逻辑控制）、GPU（数据并行）、FPGA（可定制）、ASIC（专用）的特点和适用场景
3. **编程模型**：CUDA（NVIDIA专有）、OpenCL（跨平台）、SYCL（C++标准）、HIP（CUDA兼容）的区别
4. **异构架构**：CPU-GPU、CPU-FPGA、多GPU通信方式（PCIe、NVLink、InfiniBand）
5. **数据传输与同步**：主机（CPU）与设备（GPU/FPGA）之间的数据传输优化、同步机制
6. **性能优化**： occupancy、合并访问、共享内存、固定内存、异步执行
7. **应用场景**：深度学习训练、科学计算、信号处理、高频交易对异构计算的需求
8. **OpenCL vs CUDA**：跨平台性、编程复杂度、性能、生态对比

## 最佳实践

### 1. 任务划分原则
- **CPU适合**：复杂逻辑控制、串行任务、I/O密集型任务
- **GPU适合**：大规模数据并行任务（如矩阵运算、图像处理）
- **FPGA适合**：低延迟、高吞吐量、时间确定性任务（如信号处理、高频交易）
- **ASIC适合**：大批量、固定功能任务（如AI推理芯片、比特币挖矿）

### 2. 数据传输优化
- **尽量减少传输**：将计算尽量放在设备上，只传结果回主机
- **使用固定内存**：`cudaMallocHost()`分配页锁定内存，提高传输速度
- **异步传输**：使用CUDA流（Stream）重叠数据传输和计算
- **零拷贝内存**：使用`cudaHostAlloc()`分配零拷贝内存（适用于小数据量）

### 3. 性能调优
- ** occupancy优化**：调整线程块大小、寄存器使用量、共享内存使用量
- **合并访问**：连续线程访问连续内存地址，减少显存事务数
- **使用共享内存**：缓存频繁访问数据，减少全局内存访问
- **减少分支发散**：Warp内线程执行相同分支，避免串行化

### 4. 跨平台考虑
- **优先使用OpenCL或SYCL**：如果需要跨平台（支持AMD、Intel、FPGA）
- **CUDA仍为主流**：如果仅使用NVIDIA GPU，CUDA生态更成熟
- **HIP作为过渡**：如果有CUDA代码且需移植到AMD GPU，使用HIP

### 5. 调试与性能分析
- **CUDA调试工具**：cuda-gdb（命令行）、Nsight（图形化）
- **CUDA性能分析**：nvprof（命令行）、Nsight Compute（图形化）
- **OpenCL调试工具**：gdb（配合OpenCL调试支持）、CodeXL（AMD）
- **FPGA调试工具**：Vivado Simulator、ModelSim

## 【常见错误】

### 错误1：过度依赖异构计算
**表现**：将所有任务都卸载到GPU，包括不适合并行的任务
**后果**：数据传输开销抵消并行收益，性能反而下降
**正确做法**：只在任务确实适合并行时才使用GPU/FPGA加速

### 错误2：忽略数据传输开销
**表现**：频繁在CPU和GPU之间传输小数据
**后果**：传输延迟（微秒级）远大于计算延迟（纳秒级）
**正确做法**：尽量减少传输次数，批量传输数据

### 错误3：GPU内存溢出
**表现**：分配的设备内存超过GPU显存大小
**后果**：cudaMalloc失败，程序崩溃
**正确做法**：使用`cudaMemGetInfo()`检查可用显存，或分批处理数据

### 错误4：未同步就访问结果
**表现**：启动GPU内核后立刻读取设备内存
**后果**：内核可能未执行完，读到脏数据
**正确做法**：调用`cudaDeviceSynchronize()`等待内核完成

### 错误5：OpenCL内核编译错误未检查
**表现**：`clBuildProgram()`失败后未检查
**后果**：内核执行出错，难以调试
**正确做法**：检查`clBuildProgram()`返回值，并用`clGetProgramBuildInfo()`获取编译日志

## 总结

异构计算是**充分利用不同类型计算单元优势**的关键技术，广泛应用于AI、科学计算、信号处理等领域。

**关键要点**：
1. **计算单元选择**：CPU（逻辑控制）、GPU（数据并行）、FPGA（低延迟）、ASIC（专用）
2. **编程模型**：CUDA（NVIDIA）、OpenCL（跨平台）、SYCL（C++标准）
3. **性能优化**：减少数据传输、合并访问、共享内存、 occupancy优化
4. **应用场景**：深度学习训练、科学计算、信号处理、高频交易
5. **调试与性能分析**：使用专业工具（cuda-gdb、nvprof、Nsight）

**学习路径**：
1. 掌握C/C++编程、计算机体系结构
2. 学习异构计算原理（CPU/GPU/FPGA架构）
3. 实践CUDA或OpenCL编程（向量加法、矩阵乘法、卷积）
4. 使用性能分析工具（nvprof、Nsight Compute）
5. 参与实际项目（深度学习训练、科学计算、信号处理）

掌握异构计算，能让你设计出高性能、低延迟的系统，充分利用现代硬件的计算能力。
