# 文件I/O优化

## 定义

文件I/O优化是**减少文件读写操作延迟、提高吞吐量**的技术集合。在系统编程中，I/O往往是性能瓶颈（延迟毫秒级，比内存访问慢1000倍）。

**核心矛盾**：
- **I/O速度慢**：磁盘I/O延迟毫秒级（SSD 0.1ms，HDD 10ms），内存纳秒级
- **CPU速度快**：现代CPU每秒可执行数十亿条指令
- **优化目标**：减少I/O次数、合并I/O、异步化、零拷贝

**I/O类型对比**：
| I/O类型 | 阻塞？ | 同步？ | 适用场景 |
|----------|--------|--------|----------|
| 阻塞I/O | 是 | 同步 | 简单程序、顺序处理 |
| 非阻塞I/O | 否 | 同步（需轮询） | 事件驱动、高并发 |
| I/O多路复用 | 否 | 同步（需轮询） | 高并发服务器 |
| 异步I/O | 否 | 异步 | 高性能存储、数据库 |

## 核心概念

### 1. 页缓存（Page Cache）
- **定义**：内核管理的磁盘文件缓存，以页（通常4KB）为单位
- **读流程**：
  1. 应用调用read() → 内核检查页缓存
  2. 缓存命中 → 直接拷贝到用户缓冲区（不读磁盘）
  3. 缓存未命中 → 从磁盘读取到页缓存，再拷贝到用户缓冲区
- **写流程**：
  1. 应用调用write() → 数据写入页缓存（标记为脏页）
  2. 内核定期回写脏页到磁盘（pdflush内核线程）
  3. 应用可调用fsync()强制刷盘
- **优势**：减少磁盘I/O，提高读性能
- **劣势**：占用内存，写延迟可能累积（突然掉电可能丢数据）

### 2. 直接I/O（Direct I/O）
- **定义**：绕过页缓存，直接读写磁盘
- **场景**：
  - 数据库（自身有缓存，无需页缓存）
  - 大文件传输（避免页缓存污染）
- **缺点**：需应用自己管理缓存，I/O延迟高

### 3. I/O多路复用（I/O Multiplexing）
- **定义**：单线程监听多个文件描述符，哪个就绪就处理哪个
- **系统调用**：
  - **select()**：监听fd_set（位图），最多1024个fd，线性扫描
  - **poll()**：监听pollfd数组，无数量限制，仍线性扫描
  - **epoll（Linux）**：事件驱动，只返回就绪fd，O(1)复杂度
- **应用**：Nginx、Redis、Node.js事件循环

### 4. 零拷贝（Zero-Copy）
- **定义**：数据在内核空间内传输，不拷贝到用户空间
- **技术**：
  - **sendfile()**：文件→套接字直接传输（内核内完成）
  - **splice()/tee()**：内核缓冲区之间数据传输
  - **mmap() + write()**：内存映射文件，减少一次拷贝
- **应用**：Nginx静态文件服务、Kafka日志传输

## 详细内容

### Linux文件I/O系统调用

#### 1. 基本I/O
```
// 打开文件
int fd = open("/path/to/file", O_RDONLY);

// 读取文件
char buf[4096];
ssize_t n = read(fd, buf, sizeof(buf));

// 写入文件
ssize_t n = write(fd, buf, strlen(buf));

// 关闭文件
close(fd);
```

#### 2. 高级I/O
```
// 内存映射
void *addr = mmap(NULL, length, PROT_READ, MAP_PRIVATE, fd, 0);

// 异步I/O（Linux native AIO）
io_submit(ctx, 1, &iocb);  // 提交I/O请求
io_getevents(ctx, 1, 1, events, NULL);  // 等待完成

// 高效刷盘
fdatasync(fd);  // 只刷数据，不刷元数据（比fsync快）
```

#### 3. I/O多路复用（epoll）
```
// 创建epoll实例
int epfd = epoll_create1(0);

// 添加监听fd
struct epoll_event ev;
ev.events = EPOLLIN;
epoll_ctl(epfd, EPOLL_CTL_ADD, fd, &ev);

// 等待事件
struct epoll_event events[MAX_EVENTS];
int nfds = epoll_wait(epfd, events, MAX_EVENTS, -1);
```

### I/O性能优化技术

#### 1. 缓冲与批量
- **用户态缓冲**：
  - 使用缓冲区（如`FILE*`的`fwrite()`，默认8KB缓冲）
  - 减少系统调用次数（write()系统调用开销约1微秒）
- **批量I/O**：
  - `readv()/writev()`：分散读/聚集写，一次系统调用读写多个缓冲区
  - `preadv()/pwritev()`：原子性地读写多个缓冲区

#### 2. 预读与预取
- **预读（Read-Ahead）**：
  - 内核检测到顺序读，自动预读后续页（默认128KB）
  - 可调整：`posix_fadvise(fd, offset, len, POSIX_FADV_SEQUENTIAL)`
- **预取（Prefetch）**：
  - 应用主动告知内核未来访问模式
  - `posix_fadvise(fd, offset, len, POSIX_FADV_WILLNEED)`

#### 3. I/O调度器
- **目的**：合并相邻I/O请求，减少磁盘寻道
- **Linux I/O调度器**：
  - **mq-deadline**：读写队列，避免饥饿（默认）
  - **BFQ**：公平队列，适合桌面/混合负载
  - **Kyber**：简单队列，低延迟
  - **无调度器（None）**：用于SSD（无需合并寻道）

#### 4. 异步I/O（AIO）
- **Linux native AIO**：
  - 真正的异步I/O（提交请求后立刻返回）
  - 优势：高并发I/O，减少线程数
  - 缺点：仅支持直接I/O（O_DIRECT），接口复杂
- **io_uring（Linux 5.1+）**：
  - 新一代异步I/O框架，统一了文件I/O、网络I/O、定时器
  - 优势：零拷贝提交/完成队列，支持批量操作，性能极高
  - 应用：高性能数据库（RocksDB）、Web服务器

### 零拷贝深入剖析

#### 1. 传统I/O流程（四次拷贝）
```
磁盘 → 内核缓冲区（DMA拷贝） → 用户缓冲区（CPU拷贝） → 套接字缓冲区（CPU拷贝） → 网卡（DMA拷贝）
   ↑                                                       ↑
 2次DMA拷贝                                             2次CPU拷贝
```

#### 2. sendfile()流程（两次拷贝）
```
磁盘 → 内核缓冲区（DMA） → 套接字缓冲区（DMA） → 网卡（DMA）
   ↑                                    ↑
  仅1次CPU拷贝（内核内）                  零拷贝（DMA）
```
- **限制**：仍需一次内核缓冲区→套接字缓冲区的DMA拷贝（某些网卡支持散射-收集可免）

#### 3. splice()流程（零CPU拷贝）
```
磁盘 → 内核缓冲区（DMA） ────── 套接字缓冲区（DMA） → 网卡（DMA）
                         ↑
                   内核内管道缓冲区
```
- **原理**：通过管道缓冲区连接两个文件描述符，数据在内核内流动
- **应用**：Nginx（sendfile不可用时的备选）

#### 4. mmap() + write()流程（三次拷贝）
```
磁盘 → 内核缓冲区（DMA） → 用户缓冲区（缺页中断映射） → 套接字缓冲区（CPU） → 网卡（DMA）
```
- **优势**：减少一次read()的CPU拷贝（内核→用户）
- **劣势**：仍需要write()的CPU拷贝（用户→内核）

## 示例/应用场景

### 场景1：高性能Web服务器（Nginx）
**需求**：高效传输静态文件（图片、CSS、JS）

**I/O优化技术**：
1. **sendfile()**：直接在内核传输文件到网络套接字
2. **内存映射（mmap）**：对小文件使用mmap减少拷贝
3. **直接I/O（O_DIRECT）**：大文件传输绕过页缓存
4. **异步I/O（io_uring）**：批量提交多个文件传输请求

### 场景2：数据库（RocksDB）
**需求**：高吞吐写入、低延迟读取

**I/O优化技术**：
1. **直接I/O（O_DIRECT）**：绕过页缓存，自身管理缓存（Block Cache）
2. **预取（Prefetch）**：顺序扫描时预取数据块
3. **I/O合并**：合并多个写请求为一次I/O（WAL写入）
4. **异步I/O（Linux AIO/io_uring）**：并行读取多个SSTable文件

### 场景3：日志收集系统（Flume/Kafka）
**需求**：高吞吐写入日志文件

**I/O优化技术**：
1. **批量写入**：累积多条日志后一次write()
2. **顺序写入**：只追加，不随机写（减少寻道）
3. **页缓存利用**：write()写页缓存，由内核定期刷盘
4. **零拷贝发送**：使用sendfile()直接传输日志文件到网络

## 【对应领域考点】

1. **页缓存**：定义、读/写流程、优势与劣势
2. **I/O多路复用**：select/poll/epoll区别、事件驱动模型
3. **零拷贝**：sendfile/splice/mmap原理、减少的拷贝次数
4. **异步I/O**：Linux AIO vs io_uring，与同步I/O区别
5. **I/O调度器**：mq-deadline、BFQ、Kyber适用场景
6. **直接I/O**：O_DIRECT使用场景、优缺点
7. **预读与预取**：posix_fadvise使用
8. **性能优化**：缓冲、批量、预读、异步I/O

## 最佳实践

### 1. 根据场景选择I/O模型
- **顺序读/写大文件**：使用直接I/O（O_DIRECT）或mmap
- **高并发网络服务**：使用epoll + 非阻塞I/O
- **随机读/写小文件**：使用页缓存（默认），避免直接I/O
- **日志/append-only**：批量写入，利用页缓存

### 2. 减少系统调用
- **使用缓冲区**：fwrite()代替write()，减少系统调用
- **批量I/O**：readv()/writev()一次调用读写多个缓冲区
- **内存映射**：mmap()将文件操作转为内存访问（减少read/write）

### 3. 利用零拷贝
- **文件到网络**：优先使用sendfile()（Nginx场景）
- **文件到文件**：使用splice()（Linux）
- **大文件传输**：使用io_uring的零拷贝模式

### 4. 异步化
- **高并发I/O**：使用io_uring（Linux 5.1+）
- **批量提交**：一次提交多个I/O请求，减少系统调用
- **轮询模式**：io_uring支持轮询（减少中断开销）

### 5. 监控与调优
- **iostat**：查看磁盘I/O吞吐、利用率、等待时间
- **fio**：基准测试工具，测试不同I/O模式性能
- **调整内核参数**：`/proc/sys/vm/`下的参数（dirty_ratio、dirty_background_ratio）

## 【常见错误】

### 错误1：频繁小I/O
**表现**：循环中每次写1字节（`write(fd, &c, 1)`）
**后果**：系统调用开销远大于实际I/O，性能极差
**正确做法**：使用缓冲区（如4KB），累积后一次写入

### 错误2：忽略fsync
**表现**：write()后不调用fsync()，认为数据已持久化
**后果**：突然掉电，数据丢失（仍在页缓存中）
**正确做法**：关键数据（数据库WAL、元数据）需调用fsync()

### 错误3：错误使用O_DIRECT
**表现**：用O_DIRECT打开文件但缓冲区未对齐
**后果**：EINVAL错误（直接I/O要求内存对齐）
**正确做法**：使用posix_memalign()分配对齐内存

### 错误4：epoll使用水平触发（LT）导致惊群
**表现**：多个进程/线程监听同一epoll实例，事件到来时全部被唤醒
**后果**：只有一个线程能处理事件，其他线程空转
**正确做法**：使用边缘触发（ET）+ EPOLLONESHOT，或使用io_uring

### 错误5：mmap后文件被截断
**表现**：mmap()映射文件后，其他进程截断了文件
**后果**：访问被截断部分触发SIGBUS信号
**正确做法**：使用文件锁（fcntl()）保护，或捕获SIGBUS信号

## 总结

文件I/O优化是系统编程的核心技能，能显著提升软件性能。

**关键要点**：
1. **理解页缓存**：读/写流程、优缺点，决定使用直接I/O还是标准I/O
2. **I/O多路复用**：epoll是高并发网络服务的基石
3. **零拷贝**：sendfile/splice/mmap减少拷贝次数，提升吞吐量
4. **异步I/O**：io_uring是未来方向，支持批量、零拷贝
5. **减少系统调用**：缓冲、批量、内存映射

**学习路径**：
1. 理解操作系统I/O栈（VFS、页缓存、I/O调度器）
2. 实践epoll、sendfile、mmap等系统调用
3. 阅读Nginx、Redis源码（I/O优化典范）
4. 使用fio、iostat等工具分析I/O性能瓶颈

掌握文件I/O优化，能让你写出高性能、高吞吐的系统软件。
