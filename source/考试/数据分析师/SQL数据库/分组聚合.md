# SQL分组聚合

## 定义

SQL分组聚合是指使用`GROUP BY`子句将多行数据按一个或多个列分组，然后使用聚合函数（如`SUM()`、`AVG()`、`COUNT()`等）对每组数据进行计算，返回每组的汇总结果。

分组聚合是SQL数据分析中最常用的操作之一，用于回答"每个类别的销售额是多少？"、"每个地区的平均客单价是多少？"等分组统计问题。

---

## 核心概念

### 1. 聚合函数

| 函数 | 说明 | 是否忽略NULL |
|------|------|--------------|
| `COUNT(*)` | 统计行数（包括NULL和重复行） | 不忽略（统计所有行） |
| `COUNT(列名)` | 统计该列非空值的数量 | 忽略NULL |
| `SUM(列名)` | 求和 | 忽略NULL |
| `AVG(列名)` | 求平均值 | 忽略NULL |
| `MAX(列名)` | 求最大值 | 忽略NULL |
| `MIN(列名)` | 求最小值 | 忽略NULL |

**重要区别**：
- `COUNT(*)`：统计所有行（包括NULL）
- `COUNT(列名)`：只统计该列非NULL的行

```sql
-- 示例
SELECT 
    COUNT(*) AS total_rows,          -- 总行数（包括NULL）
    COUNT(commission_pct) AS non_null_rows  -- commission_pct非NULL的行数
FROM employees;
```

### 2. GROUP BY 的执行逻辑

**执行顺序**：
1. `FROM`：确定数据来源
2. `WHERE`：过滤行（在分组前过滤）
3. `GROUP BY`：分组
4. `HAVING`：过滤组（在分组后过滤）
5. `SELECT`：选择列（可以使用聚合函数）
6. `ORDER BY`：排序
7. `LIMIT`：限制返回行数

**关键点**：
- `WHERE`在分组前过滤，`HAVING`在分组后过滤
- `GROUP BY`之后，`SELECT`中只能出现：分组列、聚合函数、常量

### 3. 分组列的选择

| 分组粒度 | 说明 | 示例 |
|----------|------|------|
| 单列分组 | 按一个列分组 | `GROUP BY department_id` |
| 多列分组 | 按多个列组合分组 | `GROUP BY department_id, job_id` |
| 表达式分组 | 按表达式分组 | `GROUP BY YEAR(hire_date)` |
| 列位置分组 | 按SELECT列表中的位置分组 | `GROUP BY 1`（不推荐，可读性差） |

## 详细内容

### 一、基础分组聚合

#### 1.1 单列分组

**场景**：查询每个部门的员工人数和平均工资

```sql
SELECT 
    department_id,
    COUNT(*) AS employee_count,
    AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id;
```

**说明**：
- 按`department_id`分组，每个部门一行
- `COUNT(*)`统计每个部门的员工人数
- `AVG(salary)`计算每个部门的平均工资

#### 1.2 多列分组

**场景**：查询每个部门每个职位的员工人数和平均工资

```sql
SELECT 
    department_id,
    job_id,
    COUNT(*) AS employee_count,
    AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id, job_id
ORDER BY department_id, job_id;
```

**说明**：
- 按`department_id`和`job_id`的组合分组
- 分组粒度：每个部门每个职位一行

#### 1.3 聚合函数的使用

```sql
SELECT 
    COUNT(*) AS total_employees,              -- 所有员工数
    COUNT(commission_pct) AS has_commission, -- 有提成的员工数
    SUM(salary) AS total_salary,             -- 工资总和
    AVG(salary) AS avg_salary,              -- 平均工资
    MAX(salary) AS max_salary,              -- 最高工资
    MIN(salary) AS min_salary               -- 最低工资
FROM employees
WHERE department_id = 10;
```

### 二、HAVING 子句（过滤分组）

#### 2.1 WHERE vs HAVING

| 子句 | 作用时机 | 用途 |
|------|----------|------|
| `WHERE` | 分组前过滤 | 过滤行（不能使用聚合函数） |
| `HAVING` | 分组后过滤 | 过滤组（可以使用聚合函数） |

**错误示例**：
```sql
-- 错误：WHERE中不能使用聚合函数
SELECT department_id, AVG(salary)
FROM employees
WHERE AVG(salary) > 5000   -- 错误！
GROUP BY department_id;
```

**正确做法**：
```sql
-- 正确：用HAVING过滤分组
SELECT department_id, AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) > 5000;
```

#### 2.2 HAVING 示例

**场景**：查询员工人数大于等于5人的部门

```sql
SELECT 
    department_id,
    COUNT(*) AS employee_count
FROM employees
GROUP BY department_id
HAVING COUNT(*) >= 5;
```

**场景**：查询平均工资在5000到10000之间的部门

```sql
SELECT 
    department_id,
    AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) BETWEEN 5000 AND 10000;
```

### 三、分组聚合与JOIN结合

#### 3.1 分组聚合 + INNER JOIN

**场景**：查询每个部门的名称、员工人数、平均工资（需要连接`departments`表获取部门名称）

```sql
SELECT 
    d.department_name,
    COUNT(e.employee_id) AS employee_count,
    AVG(e.salary) AS avg_salary
FROM employees e
INNER JOIN departments d
  ON e.department_id = d.department_id
GROUP BY d.department_name;
```

#### 3.2 分组聚合 + LEFT JOIN

**场景**：查询所有部门的名称、员工人数、平均工资（包括没有员工的部门）

```sql
SELECT 
    d.department_name,
    COUNT(e.employee_id) AS employee_count,
    AVG(e.salary) AS avg_salary
FROM departments d
LEFT JOIN employees e
  ON d.department_id = e.department_id
GROUP BY d.department_name;
```

**说明**：
- 用`LEFT JOIN`保留所有部门（包括没有员工的部门）
- `COUNT(e.employee_id)`会忽略NULL，所以没有员工的部门计数为0
- `AVG(e.salary)`会忽略NULL，所以没有员工的部门平均值为NULL

### 四、GROUP BY 的扩展语法

#### 4.1 GROUP BY + ROLLUP（累计汇总）

**说明**：`ROLLUP`会生成分组的小计和总计行

**示例**（MySQL / SQL Server / Oracle）：
```sql
SELECT 
    department_id,
    job_id,
    COUNT(*) AS employee_count
FROM employees
GROUP BY ROLLUP(department_id, job_id);
```

**结果说明**：
- 普通分组行：`(department_id, job_id)`的组合
- 小计行：`(department_id, NULL)`表示该部门的小计
- 总计行：`(NULL, NULL)`表示所有部门的总计

**注意**：不同数据库的`ROLLUP`语法略有不同

#### 4.2 GROUP BY + CUBE（交叉汇总）

**说明**：`CUBE`会生成所有可能的分组组合

**示例**（Oracle / SQL Server）：
```sql
SELECT 
    department_id,
    job_id,
    COUNT(*) AS employee_count
FROM employees
GROUP BY CUBE(department_id, job_id);
```

**结果说明**：
- 普通分组行：`(department_id, job_id)`的组合
- 交叉小计：`(department_id, NULL)`和`(NULL, job_id)`两种小计
- 总计行：`(NULL, NULL)`

#### 4.3 GROUPING SETS（自定义汇总）

**说明**：`GROUPING SETS`允许自定义哪些分组组合需要汇总

**示例**：
```sql
SELECT 
    department_id,
    job_id,
    COUNT(*) AS employee_count
FROM employees
GROUP BY GROUPING SETS(
    (department_id, job_id),  -- 按部门和职位分组
    (department_id),           -- 按部门分组（小计）
    ()                         -- 总计
);
```

### 五、常见陷阱与注意事项

#### 5.1 SELECT 中非聚合列必须出现在 GROUP BY 中

**错误示例**：
```sql
-- 错误：first_name没有出现在GROUP BY中，也没有使用聚合函数
SELECT 
    department_id,
    first_name,               -- 错误！
    COUNT(*) AS employee_count
FROM employees
GROUP BY department_id;
```

**正确做法**：
```sql
-- 方法1：将first_name加入GROUP BY
SELECT 
    department_id,
    first_name,
    COUNT(*) AS employee_count
FROM employees
GROUP BY department_id, first_name;

-- 方法2：对first_name使用聚合函数（如MAX、MIN）
SELECT 
    department_id,
    MAX(first_name) AS sample_name,  -- 取该部门中first_name的最大值（按字母排序）
    COUNT(*) AS employee_count
FROM employees
GROUP BY department_id;
```

#### 5.2 NULL 值的处理

**问题**：`GROUP BY`会将所有NULL值分为一组

**示例**：
```sql
SELECT 
    department_id,
    COUNT(*) AS employee_count
FROM employees
GROUP BY department_id;
```

**结果**：如果某些员工的`department_id`为NULL，它们会被分为一组（`department_id`显示为NULL）

**解决方法**：用`COALESCE()`将NULL替换为其他值

```sql
SELECT 
    COALESCE(CAST(department_id AS VARCHAR), '未分配部门') AS dept,
    COUNT(*) AS employee_count
FROM employees
GROUP BY COALESCE(CAST(department_id AS VARCHAR), '未分配部门');
```

#### 5.3 聚合函数忽略 NULL

**问题**：`AVG()`、`SUM()`、`COUNT(列名)`会忽略NULL

**示例**：
```sql
SELECT 
    AVG(commission_pct) AS avg_commission
FROM employees;
```

**说明**：
- 只有`commission_pct`非NULL的行才会参与计算
- 如果想知道所有员工的平均提成（包括没有提成的员工，视为0），可以用`COALESCE()`

```sql
SELECT 
    AVG(COALESCE(commission_pct, 0)) AS avg_commission
FROM employees;
```

## 示例/应用场景

### 示例1：电商订单分析

**需求**：查询2024年1月，每个用户的订单总金额、订单数、平均订单金额，只包括订单总金额大于1000的用户

**涉及的表**：
- `orders`：订单表（用户ID、订单金额、订单日期）

**SQL语句**：

```sql
SELECT 
    user_id,
    SUM(order_amount) AS total_amount,
    COUNT(*) AS order_count,
    AVG(order_amount) AS avg_order_amount
FROM orders
WHERE order_date BETWEEN '2024-01-01' AND '2024-01-31'
GROUP BY user_id
HAVING SUM(order_amount) > 1000
ORDER BY total_amount DESC;
```

### 示例2：员工薪资分析

**需求**：查询每个部门的最高工资、最低工资、平均工资，以及工资总和，只包括平均工资大于5000的部门

**涉及的表**：
- `employees`：员工表（部门ID、工资）

**SQL语句**：

```sql
SELECT 
    department_id,
    MAX(salary) AS max_salary,
    MIN(salary) AS min_salary,
    AVG(salary) AS avg_salary,
    SUM(salary) AS total_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) > 5000
ORDER BY avg_salary DESC;
```

### 示例3：用户活跃度分析

**需求**：查询2024年1月，每个用户的登录次数，只包括登录次数大于等于5次的用户，按登录次数降序排序

**涉及的表**：
- `user_login`：用户登录表（用户ID、登录日期）

**SQL语句**：

```sql
SELECT 
    user_id,
    COUNT(*) AS login_count
FROM user_login
WHERE login_date BETWEEN '2024-01-01' AND '2024-01-31'
GROUP BY user_id
HAVING COUNT(*) >= 5
ORDER BY login_count DESC;
```

## 数据分析师考点

### SQL分组聚合常见考点

1. **GROUP BY 执行顺序**：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
2. **WHERE vs HAVING的区别**：WHERE在分组前过滤（不能使用聚合函数），HAVING在分组后过滤（可以使用聚合函数）
3. **聚合函数忽略NULL**：`COUNT(列名)`、`SUM()`、`AVG()`等会忽略NULL
4. **COUNT(*) vs COUNT(列名)**：`COUNT(*)`统计所有行（包括NULL），`COUNT(列名)`只统计非NULL的行
5. **SELECT 中非聚合列必须出现在GROUP BY中**：否则会报错（部分数据库如MySQL在宽松模式下不会报错，但结果不可预测）
6. **GROUP BY 会将NULL分为一组**：所有NULL值会被分为一组
7. **ROLLUP、CUBE、GROUPING SETS**：用于生成小计和总计行

### 实战考点

1. **性能优化**：
   - `WHERE`在分组前过滤，尽量减少参与分组的数据量
   - 分组列应有索引
   - 避免使用`SELECT *`，只选择需要的列
2. **数据隐式转换**：分组列的数据类型应一致，否则可能导致索引失效
3. **浮点数平均值**：`AVG()`返回浮点数，可能需要用`ROUND()`保留小数位
4. **分组粒度**：分组列越多，分组粒度越细，结果行数越多

## 最佳实践

### 1. 明确分组目的

- **先思考业务问题**：明确要分析的分组维度（如"每个部门"、"每个地区"）
- **选择合适的分组列**：分组列应该是有业务意义的分类字段
- **避免过细的分组**：分组列过多会导致结果难以阅读

### 2. 使用有意义的别名

- **给聚合函数起别名**：如`COUNT(*) AS employee_count`，提升可读性
- **避免使用默认的列名**：如`AVG(salary)`的列名在不同数据库中可能显示为`avg(salary)`或`AVG(salary)`，建议起别名

### 3. 先WHERE后GROUP BY

- **尽量用WHERE过滤**：WHERE在分组前过滤，减少参与分组的数据量，提升性能
- **HAVING只用于过滤聚合结果**：如果过滤条件不需要聚合函数，应该放在WHERE中

```sql
-- 不推荐：先用GROUP BY分组，再用HAVING过滤
SELECT department_id, AVG(salary)
FROM employees
GROUP BY department_id
HAVING department_id IN (10, 20, 30);

-- 推荐：先用WHERE过滤，再GROUP BY分组
SELECT department_id, AVG(salary)
FROM employees
WHERE department_id IN (10, 20, 30)
GROUP BY department_id;
```

### 4. 注意NULL的处理

- **用COALESCE()处理NULL**：将NULL替换为其他值，避免分组时将NULL分为一组
- **注意聚合函数忽略NULL**：如果需要将NULL视为0，可以用`COALESCE(列名, 0)`

### 5. 验证分组结果的合理性

- **检查分组数**：分组后的行数应该与预期一致（如按部门分组，行数应该等于部门数）
- **检查聚合结果**：聚合结果应该在合理范围内（如平均工资不应该为NULL，除非该组所有行的工资都为NULL）

## 常见错误

### 1. 在WHERE中使用聚合函数

**错误示例**：
```sql
-- 错误：WHERE中不能使用聚合函数
SELECT department_id, AVG(salary)
FROM employees
WHERE AVG(salary) > 5000
GROUP BY department_id;
```

**正确做法**：
```sql
-- 正确：用HAVING过滤分组
SELECT department_id, AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) > 5000;
```

### 2. SELECT 中非聚合列没有出现在 GROUP BY 中

**错误示例**：
```sql
-- 错误：first_name没有出现在GROUP BY中
SELECT department_id, first_name, COUNT(*)
FROM employees
GROUP BY department_id;
```

**正确做法**：
```sql
-- 正确：将first_name加入GROUP BY
SELECT department_id, first_name, COUNT(*)
FROM employees
GROUP BY department_id, first_name;
```

### 3. 混淆 COUNT(*) 和 COUNT(列名)

**错误理解**：认为`COUNT(*)`和`COUNT(列名)`是一样的

**正确理解**：
- `COUNT(*)`：统计所有行（包括NULL）
- `COUNT(列名)`：只统计该列非NULL的行

```sql
-- 示例
SELECT 
    COUNT(*) AS total_rows,              -- 所有行数（比如14行）
    COUNT(commission_pct) AS non_null_rows  -- commission_pct非NULL的行数（比如4行）
FROM employees;
```

### 4. 忽略 NULL 值

**错误示例**：
```sql
-- 可能得到NULL（如果所有员工的commission_pct都为NULL）
SELECT AVG(commission_pct) AS avg_commission
FROM employees;
```

**正确做法**：
```sql
-- 用COALESCE将NULL视为0
SELECT AVG(COALESCE(commission_pct, 0)) AS avg_commission
FROM employees;
```

### 5. 在 GROUP BY 中使用列位置（可读性差）

**不推荐**：
```sql
-- 按SELECT列表中第1列分组（可读性差，不推荐）
SELECT department_id, COUNT(*)
FROM employees
GROUP BY 1;
```

**推荐**：
```sql
-- 明确指定分组列（可读性好）
SELECT department_id, COUNT(*)
FROM employees
GROUP BY department_id;
```

### 6. 忘记将 NULL 分为一组

**问题**：`GROUP BY`会将所有NULL分为一组，可能导致结果难以理解

**解决方法**：
```sql
-- 用COALESCE将NULL替换为有意义的值
SELECT 
    COALESCE(CAST(department_id AS VARCHAR), '未分配部门') AS dept,
    COUNT(*) AS employee_count
FROM employees
GROUP BY COALESCE(CAST(department_id AS VARCHAR), '未分配部门');
```

## 总结

SQL分组聚合是数据分析师必须掌握的核心技能，关键要点包括：

1. **掌握GROUP BY执行顺序**：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
2. **理解WHERE和HAVING的区别**：WHERE在分组前过滤，HAVING在分组后过滤
3. **熟练使用聚合函数**：COUNT、SUM、AVG、MAX、MIN（注意它们会忽略NULL）
4. **注意SELECT中的列**：非聚合列必须出现在GROUP BY中
5. **处理NULL值**：用COALESCE()将NULL替换为其他值
6. **掌握高级分组语法**：ROLLUP、CUBE、GROUPING SETS（用于生成小计和总计）

分组聚合是SQL数据分析的基础，需要在实践中不断积累经验。
