# 软件质量保证

## 1. 软件质量概念

软件质量是软件与明确和隐含定义的需求相一致的程度。

### 影响质量的三个因素

| 因素 | 说明 | 关注点 |
|-----|------|-------|
| 产品运行 | 用户使用视角 | 正确性、健壮性、效率、完整性、可用性 |
| 产品修改 | 维护人员视角 | 可理解性、可维修性、灵活性、可测试性 |
| 产品转移 | 移植人员视角 | 可移植性、可再用性、互运行性 |

## 2. 软件质量保证（SQA）

### 定义
建立一套有计划、有系统的方法，向管理层保证拟定出的标准、步骤、实践和方法能够正确地被所有项目采用。

### 目标
- **事前预防**：重缺陷预防而非缺陷检查
- **及时捕获**：在引入缺陷时即捕获
- **过程导向**：作用于过程而非最终产品
- **全面覆盖**：贯穿所有活动

### 主要任务
1. **SQA审计与评审**：评价工作产品是否符合标准
2. **SQA报告**：记录工作结果，发布给相关人员
3. **处理不合格问题**：及时向有关人员反映

### SQA报告三原则
- 与高级管理者有直接沟通渠道
- 发布给软件工程组，不必发布给项目管理人员
- 尽可能向关心质量的人发布

## 3. 软件配置管理（SCM）

### 核心内容
- **版本控制**：追踪文件变更，支持并行开发
- **变更控制**：管理变更，确保有序进行

### 主要活动
- 软件配置管理计划
- 软件配置标识
- 软件配置控制
- 软件配置状态记录
- 软件配置审计
- 软件发布管理与交付

## 4. 软件测试

### 测试方法

| 方法 | 说明 |
|-----|------|
| 静态测试 | 不运行程序，通过分析检查（文档、代码走查、审查） |
| 动态测试 | 实际运行程序（白盒测试、黑盒测试） |

### 白盒测试
- 又称结构测试
- 透明的白盒，完全清楚内部结构
- 逻辑覆盖：语句、判定、条件、判定/条件、修正条件/判定、路径覆盖

### 黑盒测试
- 又称功能测试
- 不考虑内部结构
- 方法：等价类划分、边界值分析、判定表、因果图、状态图

### 测试类型

| 类型 | 说明 |
|-----|------|
| 单元测试 | 模块测试，检查模块功能 |
| 集成测试 | 模块组装后的测试，接口问题 |
| 确认测试 | 验证功能性能是否符合需求 |
| 系统测试 | 完整系统，功能+性能+安全性 |
| 配置项测试 | 验证软件配置项与SRS一致 |
| 回归测试 | 变更后的正确性和不损害性 |

### 面向对象测试特点
- 封装性：信息隐蔽原则的影响
- 继承性：对测试充分性的影响
- 多态性：动态绑定的影响

## 5. 软件过程能力成熟度（CSMM）

### 成熟度等级（5级）

| 等级 | 名称 | 结果特征 |
|-----|------|---------|
| 1级 | 初始级 | 不确定性 |
| 2级 | 项目规范级 | 预期结果 |
| 3级 | 组织改进级 | 稳定实现目标 |
| 4级 | 量化提升级 | 量化管理 |
| 5级 | 创新引领级 | 持续优化 |

### 能力域（4个）
- **治理**：战略与治理、目标管理
- **开发与交付**：需求、设计、开发、测试、部署、服务、开源
- **管理与支持**：项目策划、监控、结项、质量保证、风险管理、配置管理、供应商管理
- **组织管理**：过程、人员、资源、过程能力管理

## 6. 关键考点

- 软件质量三因素：产品运行、产品修改、产品转移
- SQA目标：事前预防、及时捕获、过程导向、全面覆盖
- SQA三大任务：审计评审、报告、处理不合格
- 版本控制主要功能：追踪变更、并行开发
- 静态测试：桌前检查、代码走查、代码审查
- 白盒测试：逻辑覆盖（6种）
- 黑盒测试：等价类、边界值、判定表、因果图
- CSMM 5个成熟度等级
- CSMM 4个能力域：治理、开发与交付、管理与支持、组织管理
