> 观察和交谈是最直接、最有效的需求获取方法，特别适合了解真实工作流程。

---

## 一、什么是观察

### 1.1 定义

观察法是通过直接观察用户在实际工作环境中的行为来收集信息的方法。

### 1.2 观察法的价值

| 价值 | 说明 |
|------|------|
| **真实性** | 观察真实行为，不依赖口头描述 |
| **完整性** | 发现用户自己没意识到的行为 |
| **情境性** | 了解行为发生的具体环境 |

### 1.3 观察 vs 访谈

| 对比项 | 观察 | 访谈 |
|--------|------|------|
| 数据类型 | 实际行为 | 口头描述 |
| 主观性 | 低（直接观察）| 高（自我报告）|
| 深度 | 中等 | 深 |
| 适用范围 | 工作流程 | 态度、观点 |

## 二、观察类型

### 2.1 按参与程度

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| **完全观察** | 观察者不参与，用户不知情 | 研究自然行为 |
| **参与观察** | 观察者参与其中 | 深入理解工作 |
| **半结构观察** | 有观察大纲但灵活 | 大多数项目需求 |

### 2.2 按结构化程度

| 类型 | 说明 |
|------|------|
| **结构化观察** | 按预定表格记录 |
| **半结构化观察** | 有大纲但不限于大纲 |
| **非结构化观察** | 全面记录所见所闻 |

### 2.3 按技术手段

| 类型 | 说明 |
|------|------|
| **现场观察** | 到工作现场观察 |
| **视频观察** | 录像后分析 |
| **屏幕录制** | 软件操作录制 |

## 三、实施步骤

### 3.1 准备阶段

#### 确定观察目标

| 问题 | 示例 |
|------|------|
| 要了解什么？ | 客服人员如何处理投诉 |
| 观察谁？ | 资深客服代表 |
| 观察多久？ | 2-3天 |

#### 获取许可

- 向相关人员说明目的
- 取得被观察者同意
- 说明数据使用方式

#### 准备工具

| 工具 | 用途 |
|------|------|
| 观察记录表 | 标准化记录 |
| 笔记本 | 详细记录 |
| 录音/录像设备 | 辅助记录 |
| 相机 | 拍摄工作环境 |

### 3.2 现场观察

#### 观察要点

| 观察维度 | 具体内容 |
|---------|----------|
| **人** | 谁在做这项工作 |
| **事** | 做了哪些具体操作 |
| **时** | 什么时候做，持续多久 |
| **地** | 在哪里做 |
| **方式** | 怎么做的，有无特殊技巧 |
| **工具** | 使用什么工具或系统 |
| **问题** | 遇到什么困难或问题 |

#### 观察记录示例

```
日期：2024-03-15
观察者：张工
被观察者：李工（资深客服）
观察时间：09:00-12:00

观察记录：
09:15 - 登录系统，查看待处理工单
09:20 - 点击第一个工单，查看客户问题描述
09:22 - 在知识库搜索关键词，找到解决方案
09:25 - 复制回复模板，修改后发送
09:30 - 工单标记为"已解决"
...
```

### 3.3 事后交谈

#### 观察后访谈内容

| 内容 | 问题示例 |
|------|----------|
| 澄清行为 | "刚才那个步骤为什么要这样做？" |
| 追问原因 | "这种情况一般怎么处理？" |
| 了解例外 | "如果客户不配合怎么办？" |
| 收集建议 | "你觉得哪里最需要改进？" |

### 3.4 分析整理

| 步骤 | 内容 |
|------|------|
| 转录整理 | 将记录转为正式文档 |
| 模式识别 | 找出反复出现的模式 |
| 问题归纳 | 总结发现的问题 |
| 需求提炼 | 从问题中提炼需求 |

## 四、记录技巧

### 4.1 现场记录

| 技巧 | 说明 |
|------|------|
| 关键词记录 | 先记关键词，回来再补全 |
| 场景描述 | 描述发生了什么 |
| 引用原话 | 记录被观察者原话 |
| 记录时间 | 记录每个行为的时间点 |

### 4.2 记录模板

```
【基本信息】
日期：
时间：
地点：
被观察者（编号）：
观察者：

【观察记录】
时间 | 行为描述 | 环境/工具 | 问题/发现
-----|----------|----------|----------
09:00|         |          |
09:30|         |          |

【事后访谈记录】
问：
答：

【初步发现】
1.
2.
```

## 五、观察中的交谈

### 5.1 观察时交谈的时机

| 时机 | 交谈内容 |
|------|----------|
| 工作间隙 | 简单寒暄，建立信任 |
| 关键操作后 | "刚才那个是什么意思？" |
| 观察结束后 | 深入了解行为原因 |

### 5.2 提问技巧

| 类型 | 问题示例 |
|------|----------|
| 开放式 | "能跟我说说为什么这样做吗？" |
| 澄清式 | "你是说每次都要这样操作？" |
| 假设式 | "如果系统自动xxx，会更方便吗？" |

## 六、注意事项

### 6.1 观察者偏差

| 偏差类型 | 说明 | 应对方法 |
|---------|------|----------|
| 选择性观察 | 只看到想看的 | 制定观察清单 |
| 晕轮效应 | 因某点好/差影响全面判断 | 多次观察 |
| 推断偏差 | 把自己推断当成事实 | 记录行为而非推断 |

### 6.2 被观察者偏差

| 现象 | 说明 | 应对 |
|------|------|------|
| 霍桑效应 | 知道被观察后行为改变 | 多次观察让其习惯 |
| 表演行为 | 有意展示"正确"做法 | 长期观察 |
| 沉默倾向 | 有问题不说 | 事后访谈深入了解 |

### 6.3 伦理注意事项

| 注意事项 | 说明 |
|---------|------|
| 知情同意 | 事先告知并取得同意 |
| 隐私保护 | 不记录敏感信息 |
| 关系边界 | 保持专业关系 |
| 数据安全 | 记录数据妥善保管 |

## 七、提高观察质量

### 7.1 观察前准备

| 准备项 | 内容 |
|--------|------|
| 学习背景知识 | 了解行业和工作基本知识 |
| 准备观察清单 | 明确要观察什么 |
| 熟悉环境 | 提前了解工作场所 |
| 培训记录技巧 | 统一记录格式 |

### 7.2 观察中

| 技巧 | 说明 |
|------|------|
| 早到晚退 | 观察完整工作日 |
| 多观察几次 | 减少偏差 |
| 记录观察 | 及时记录，不要依赖记忆 |
| 追问验证 | 有疑问及时问 |

### 7.3 观察后

| 行动 | 说明 |
|------|------|
| 及时整理 | 24小时内整理记录 |
| 与被观察者确认 | 关键发现核实 |
| 团队讨论 | 与项目团队分享发现 |
| 提炼需求 | 从观察中提炼系统需求 |

## 八、应用场景

### 8.1 业务流程分析

**适用：** 了解现有流程，发现效率问题

**观察要点：**
- 各步骤花费时间
- 等待和交接环节
- 手工重复操作
- 信息传递方式

### 8.2 用户体验研究

**适用：** 了解用户使用产品的真实体验

**观察要点：**
- 操作路径
- 困难和迷惑
- 试错过程
- 替代做法

### 8.3 工作环境评估

**适用：** 了解团队协作和工作环境

**观察要点：**
- 沟通方式
- 协作流程
- 工具使用
- 空间布局

## 九、总结

### 观察法使用时机

✅ **适合使用：**
- 需要了解真实工作流程
- 用户难以准确描述行为
- 现有流程可能有优化空间
- 需要验证访谈信息

❌ **不适合使用：**
- 只能观察小范围样本
- 被观察行为不频繁
- 工作内容涉及高度隐私
- 时间非常紧迫

### 观察成功的关键

1. **明确目标** - 知道要观察什么
2. **建立信任** - 被观察者放松表现自然
3. **详细记录** - 多记总比少记好
4. **事后验证** - 与被观察者核实发现
5. **提炼行动** - 从观察中提炼改进措施
