> 质量功能展开（QFD）是将客户需求转化为产品设计规格的系统化方法。

---

## 一、质量功能展开概述

### 1.1 什么是QFD

质量功能展开（Quality Function Deployment，QFD）是一种将客户声音（VOC）转化为产品开发规格的系统方法论。

**核心思想：**
- "做什么"（客户需求） → "怎么做"（技术规格）

### 1.2 QFD的价值

| 价值 | 说明 |
|------|------|
| **连接需求与设计** | 架起客户与研发的桥梁 |
| **系统化决策** | 避免主观臆断 |
| **团队共识** | 促进跨部门协作 |
| **质量前移** | 在设计阶段解决质量问题 |

### 1.3 QFD发展历程

| 年份 | 里程碑 |
|------|--------|
| 1966 | 石川馨在日本提出QFD概念 |
| 1972 | 三菱重工神户造船厂首次应用 |
| 1980s | 传入美国，在汽车、电子行业推广 |
| 1990s | 引入软件行业，形成软件QFD方法 |

## 二、质量屋（House of Quality）

### 2.1 什么是质量屋

质量屋是QFD的核心工具，通过矩阵形式展示需求与技术规格的关系。

### 2.2 质量屋结构

```
          技术规格（HOWs）
              ↑
    ┌─────┬─────────┐
    │ 关系│ 屋顶    │ ← 技术规格间关系
    │ 矩阵│         │
    ├─────┼─────────┤
    │客户 │ 需求    │ ← 客户需求（WHATS）
    │权重 │ (WHATS) │
    ├─────┴─────────┤
    │      目标值   │ ← 设计目标
    └───────────────┘
```

### 2.3 各组成部分详解

| 组成部分 | 内容 | 作用 |
|---------|------|------|
| **客户需求** | 用户需求的分类整理 | 明确要做什么 |
| **技术规格** | 将需求转化为技术特性 | 明确怎么做 |
| **关系矩阵** | 需求与规格的关系强度 | 优先级依据 |
| **屋顶** | 技术规格间的相关关系 | 避免冲突 |
| **权重** | 需求的重要性评分 | 资源配置依据 |
| **目标值** | 竞争性基准对比 | 设定改进方向 |

## 三、构建质量屋步骤

### 3.1 步骤概览

```
1. 确定客户需求（WHATS）
        ↓
2. 确定技术规格（HOWS）
        ↓
3. 建立关系矩阵
        ↓
4. 建立屋顶（相关矩阵）
        ↓
5. 确定权重
        ↓
6. 竞争性评估
        ↓
7. 确定目标值
```

### 3.2 步骤详解

#### 步骤1：确定客户需求

**收集方法：**
- 用户访谈
- 问卷调查
- 焦点小组
- 观察使用场景
- 分析投诉数据

**需求整理：**
```
示例（手机APP）：
- 启动速度快
- 操作简单易学
- 功能稳定不崩溃
- 界面美观
- 隐私安全保护
```

#### 步骤2：确定技术规格

**转化原则：**
- 每个需求对应多个技术规格
- 技术规格可测量、可验证

**示例：**
```
客户需求 → 技术规格
启动速度快 → 启动时间<2秒
操作简单   → 核心功能3步可达
稳定不崩溃 → 通过XX测试用例
界面美观   → UI评分>4.0分
隐私安全   → 通过安全认证
```

#### 步骤3：建立关系矩阵

| 关系强度 | 符号 | 分值 |
|---------|------|------|
| 强相关 | ● | 9分 |
| 中等相关 | ○ | 3分 |
| 弱相关 | △ | 1分 |
| 不相关 | 空格 | 0分 |

#### 步骤4：建立屋顶

| 相关类型 | 符号 |
|---------|------|
| 强正相关 | ●● |
| 正相关 | ● |
| 强负相关 | ×× |
| 负相关 | × |

#### 步骤5：确定权重

| 方法 | 说明 |
|------|------|
| 直接评分法 | 用户直接给出1-5分 |
| 层次分析法 | AHP成对比较确定 |
| 加权投票法 | 用户投票分配100分 |

#### 步骤6：竞争性评估

| 评估对象 | 评估内容 |
|---------|----------|
| 自身产品 | 当前产品表现 |
| 竞品 | 竞争对手表现 |
| 标杆 | 行业最佳实践 |

#### 步骤7：确定目标值

**确定依据：**
- 用户期望值
- 竞品水平
- 技术可行性
- 资源约束

## 五、敏捷开发中的QFD

### 5.1 敏捷QFD特点

| 传统QFD | 敏捷QFD |
|---------|---------|
| 详细计划 | 渐进明细 |
| 完整需求文档 | 用户故事 |
| 长期规划 | Sprint规划 |
| 一次性完成 | 持续迭代 |

### 5.2 敏捷QFD实施

**用户故事的QFD排序：**
1. 收集用户故事（相当于WHATS）
2. 确定验收标准（相当于HOWS）
3. 建立关系矩阵
4. 量化故事点
5. 确定Sprint优先级

### 5.3 敏捷质量屋简化版

| 需求 | 商业价值 | 技术难度 | 用户频率 | 综合分 |
|------|---------|---------|---------|--------|
| 登录功能 | 9 | 3 | 9 | 计算 |
| 导出报表 | 7 | 5 | 4 | 计算 |
| 消息通知 | 6 | 4 | 7 | 计算 |

## 六、实施要点

### 6.1 成功关键因素

| 因素 | 说明 |
|------|------|
| **高层支持** | 资源配置和推动 |
| **跨职能团队** | 设计/研发/质量/市场协作 |
| **客户声音** | 真实的一手数据 |
| **持续迭代** | 根据反馈持续优化 |

### 6.2 常见问题

| 问题 | 解决方案 |
|------|----------|
| 需求太多 | 归类分组，控制在20项内 |
| 技术规格难以量化 | 寻找可测量的替代指标 |
| 团队参与度低 | 可视化展示，吸引关注 |
| 与敏捷冲突 | 简化版QFD，适配敏捷节奏 |

### 6.3 注意事项

1. **需求要真实** - 来自用户调研，不是想象
2. **关系要准确** - 避免主观臆断
3. **权重要合理** - 综合多方意见
4. **持续更新** - 根据市场反馈调整
5. **工具辅助** - 使用软件工具提高效率

## 七、QFD与其他工具

### 7.1 QFD与Kano模型

| 工具 | 侧重点 |
|------|--------|
| Kano模型 | 需求分类（基本/性能/兴奋） |
| QFD | 需求转化为规格 |

**结合使用：** 用Kano分类需求，用QFD转化为技术规格

### 7.2 QFD与FMEA

| 工具 | 作用阶段 |
|------|----------|
| QFD | 设计前期的需求转换 |
| FMEA | 设计后期的风险分析 |

## 八、总结

### QFD实施口诀

```
客户声音要收集
需求分类要清晰
技术规格要量化
关系矩阵要准确
权重分配要合理
目标设定要可达
持续迭代要跟进
团队协作要紧密
```

### QFD核心价值

- ✅ 系统化地将客户需求转化为产品规格
- ✅ 量化决策依据，减少主观判断
- ✅ 促进跨部门协作与团队共识
- ✅ 将质量前移到设计阶段
