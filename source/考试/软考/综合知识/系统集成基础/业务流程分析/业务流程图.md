# 业务流程图

## 一、定义

**业务流程图（TFD，Transaction Flow Diagram）** 是一种描述管理系统内各单位、人员之间的业务关系、作业顺序和管理信息流向的图表。

### 核心特征

- 用规定的符号及连线表示某个具体业务的处理过程
- 帮助分析人员找出业务流程中的**不合理流向**
- 基本上按业务的实际处理步骤和过程绘制
- 是一种用图形方式反映实际业务处理过程的"**流水账**"

业务流程图用标准的符号和图形来表示不同的元素：
- 流程步骤
- 决策点
- 文档
- 数据传输
- 参与者

这些符号和图形的组合和连接方式形成了一张具体的图表，展示了业务流程的结构和流程。

## 二、常用符号

| 符号 | 含义 | 说明 |
|------|------|------|
| 角色 | 参与者 | 执行操作的人员或部门 |
| 业务处理 | 活动 | 具体的业务操作步骤 |
| 文档 | 文件、单据 | 输入或输出的文档资料 |
| 信息传递 | 箭头 | 业务活动之间的信息流向 |
| 业务判断 | 菱形 | 条件判断或决策点 |

**注：** 业务流程图与数据流程图（DFD）的符号体系不同——业务流程图侧重业务活动本身，数据流程图侧重数据流动（见《TFD与DFD区别.md》）。

## 三、业务流程图的作用

### 3.1 可视化业务流程

将复杂的业务流程以图形化方式呈现，使抽象的过程变得直观可见，便于分析和讨论。

### 3.2 分析和优化业务流程

通过流程图识别：
- 重复的处理环节
- 冗余的审批步骤
- 不合理的流向
- 效率瓶颈

为流程优化提供依据。

### 3.3 沟通和理解

- 促进业务人员与技术人员之间的沟通
- 统一对流程的理解和认知
- 作为项目文档的一部分，确保信息一致性

### 3.4 培训和知识共享

- 新员工培训的标准材料
- 固化业务流程知识
- 减少因人员流动造成的知识断层

### 3.5 监控和控制

- 为流程监控提供基准
- 确定关键控制点
- 建立流程绩效指标

### 3.6 支持自动化和数字化转型

- 识别可自动化的环节
- 为信息系统设计提供依据
- 支撑业务流程管理（BPM）和工作流引擎

## 四、业务流程图的特点

| 特点 | 说明 |
|------|------|
| 直观性 | 图形化展示业务流程，一目了然 |
| 真实性 | 反映实际业务处理过程，非理想化流程 |
| 完整性 | 包含业务处理的全过程 |
| 灵活性 | 绘制方法较简单，无严格约束 |
| 面向业务 | 以业务处理过程为中心 |

## 五、软考答题要点

### 考题形式一：业务流程图的作用

```
【题目关键词】"业务流程图的作用""TFD的作用"

【标准答案】
1. 可视化业务流程
2. 分析和优化业务流程
3. 沟通和理解
4. 培训和知识共享
5. 监控和控制
6. 支持自动化和数字化转型

（按题目要求选择最相关的几点作答）
```

### 考题形式二：业务流程图的特点

```
【答题框架】
1. 定义：描述管理系统内各单位、人员之间的业务关系、作业顺序和管理信息流向
2. 核心：以业务处理过程为中心（区别于数据流程图以数据为中心）
3. 特点：直观、真实、完整、灵活
4. 作用：可视化→分析优化→沟通→培训→监控→支撑自动化
```
