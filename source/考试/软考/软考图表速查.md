# 软考图表速查

软考涵盖多个级别和方向，不同科目考察的"图"各有侧重。本文将软考中最核心、最高频的图按三大类系统梳理，附核心概念和考点说明。

---

## 一、软件设计与架构类

适用于：软件设计师、系统架构设计师、系统分析师

这类图主要集中在"需求分析"、"系统设计"和"面向对象"三大板块，是上午基础知识题和下午案例分析的常客。

### 1.1 结构化分析与设计工具

早期软件开发方法论，但在软考中依然是必考的基础内容。

#### 数据流图 (DFD)

**概念**：描绘数据在系统中流动和处理的过程，包含四大要素：
- **数据流**（→）：数据的流向
- **加工/处理**（圆或圆角矩形）：对数据的处理
- **数据存储**（开放矩形）：数据的存放
- **外部实体**（矩形）：系统外部的参与者

**考点**：
- 父图与子图平衡：子图的输入输出必须与父图对应加工的输入输出一致
- 数据守恒：每个加工必须有输入和输出
- 补充缺失的数据流

#### E-R 图（实体-关系图）

**概念**：用于数据库概念结构设计，描述：
- **实体**：现实世界中可区别于其他对象的"事物"
- **属性**：实体的特征
- **联系**：实体之间的关系（1:1、1:n、m:n）

**考点**：
- 将现实业务转化为 E-R 图
- E-R 图转换为关系模式（数据库表结构）
- 实体名、属性、联系的识别

#### 状态转换图 (STD)

**概念**：描述系统或对象在不同触发事件下的状态变迁。

**考点**：
- 通过给定的业务场景，补充或绘制状态节点及转移条件
- 识别初始状态、终止状态和中间状态

#### HIPO 图

**概念**：层次图 + 输入/处理/输出图
- **层次图（H 图）**：描述模块间的上下级调用关系（树状结构）
- **IPO 图**：描述具体某个模块的输入（Input）、处理（Process）、输出（Output）

**考点**：
- 区分总体设计（H 图）和详细设计（IPO 图）的侧重
- 模块分解的层次结构

#### 程序流程图

**概念**：用标准图形描绘算法或程序的执行步骤：
- 矩形 → 处理/操作
- 菱形 → 判断/条件分支
- 平行四边形 → 输入/输出
- 圆角矩形 → 开始/结束

**考点**：
- 根据代码逻辑补充流程图
- 指出流程图中的死循环或无法执行路径

### 1.2 UML（统一建模语言）图

UML 是现代软件工程的核心，软考主要考察 UML 2.0 的 14 种图。按静态结构和动态行为分类记忆：

#### 静态图（系统的"骨架"）

| 图 | 说明 | 高频考点 |
|----|------|---------|
| **类图** | 展示类、接口及其关联、继承、依赖、实现关系 | 最核心！类的关系判断、聚合vs组合、依赖vs关联 |
| **对象图** | 类的实例快照，某一时刻的状态 | 与类图对比出题 |
| **组件图** | 系统的物理模块（jar包、DLL、微服务）及依赖 | 组件与接口的关系 |
| **部署图** | 软件如何映射到硬件物理节点（服务器、路由器） | 节点、构件、通信链路的绘制 |
| **包图** | 展示命名空间/模块划分 | 包之间的依赖关系 |

#### 动态图（系统的"灵魂/交互"）

| 图 | 说明 | 高频考点 |
|----|------|---------|
| **用例图** | 展示参与者(Actor)与系统功能(用例)及关系 | 包含(<<include>>)、扩展(<<extend>>)、泛化关系 |
| **序列图/时序图** | 强调消息交互的时间先后顺序 | 补充返回消息、循环/条件框、激活条 |
| **通信图** | 强调对象之间的结构链接关系，弱化时间顺序 | 旧称"协作图"，消息编号 |
| **活动图** | 类似流程图，支持并发 | 分叉/汇合、泳道、对象流 |
| **状态图** | 描述特定对象在其生命周期内的状态变化 | 转换箭头上的事件/条件/动作 |
| **交互概览图** | 活动图 + 序列图的混合 | 高层交互流程 |
| **定时图** | 时间约束下的交互（较少考） | 时间约束、状态变迁 |

## 二、项目管理类

适用于：系统集成项目管理工程师、信息系统项目管理师

在项目管理领域，图主要用于"进度管理"、"成本管理"和"资源管理"。

### 2.1 进度管理核心图

#### 甘特图（Gantt Chart）

**概念**：用横向条状表示任务的开始时间、持续时间和结束时间。

**特点**：
- 非常直观，易于向客户或非技术人员汇报进度
- 缺点：无法清晰展示任务之间的逻辑依赖关系

**考点**：根据描述补充甘特图的条状；识别关键路径（间接）

#### 双代号网络图（ADM / AOA）

**概念**：箭线表示活动，节点表示事件（里程碑）。

**核心难点——虚活动**：
- 虚箭线（--→）不消耗时间和资源
- 纯粹为正确表达多任务之间的逻辑先后关系
- 例：A 和 B 都完成后才能做 C

**考点**：
- 画合规的网络图
- 找关键路径（最长路径）
- 计算总时差（TF）和自由时差（FF）

#### 单代号网络图（PDM / AON）

**概念**：节点表示活动，箭线表示逻辑关系。是主流项目管理软件（如 Project）默认模式。

**考点**：
- 关键路径分析
- 进度压缩（赶工、快速跟进）
- 六时间参数计算（ES/EF/LS/LF/TF/FF）

#### PERT 图（项目评审技术）

**概念**：带权重的网络图，权重用三点估算法：
```
期望时间 = (乐观 + 4×最可能 + 悲观) / 6
```

**用途**：处理不确定性高的项目进度估算

**考点**：标准差计算、完工概率估算

---

### 2.2 成本与资源管理图

#### S 曲线（S-Curve）

**概念**：以时间为横轴，以累计成本或累计工作量百分比为纵轴。项目初期慢、中期快、后期慢，形状像字母 S。

**用途**：挣值管理（EVM）分析
- **PV**（计划值）：应该完成的工作预算
- **AC**（实际成本）：实际花费
- **EV**（挣值）：实际完成工作的价值

**考点**：
- CV、SV、CPI、SPI 计算
- 判断项目是超支还是进度落后

#### 资源直方图（Resource Histogram）

**概念**：条形图，横轴是时间，纵轴是人员/设备数量。

**用途**：
- 发现"资源瓶颈"（某段时间人手严重不足）
- 发现"资源闲置"（某段时间人手过剩）
- 指导资源平滑或资源平衡

## 三、通用基础类

适用于：所有软考科目，上午选择题高频考点

### 数据字典（DD）

**概念**：关于数据的数据，对 DFD 中各个元素进行定义和说明的文档。

**包含内容**：
- 数据项（不可再分的数据单元）
- 数据结构（数据元素的组合）
- 数据流（数据在系统中的流向）
- 数据存储（数据的存放）
- 处理（加工的具体说明）

**考点**：
- 数据字典与 DFD 的对应关系
- 数据项的定义格式（数据类型、长度、取值范围）
- 常与 DFD 结合出题

---

### 判定表与判定树

#### 判定表

**概念**：用表格形式表示复杂的条件组合与对应的操作。

**组成**：
- **条件桩**：列出所有条件
- **动作桩**：列出所有操作
- **条件项**：条件的组合（Y/N）
- **动作项**：条件组合对应的操作

**考点**：根据业务描述补充判定表；识别可以合并的规则

#### 判定树

**概念**：用树形图表示多条件组合判断，每个叶子节点表示一个动作。

**特点**：直观，但复杂条件下不如判定表简洁

**考点**：将文字描述的条件转化为判定树

---

### N-S 图（盒图）和 PAD 图

#### N-S 图

**概念**：结构化程序设计的图形工具，用方框代替传统流程图的控制结构：
- 顺序结构：方框顺序排列
- 选择结构：T/F 分支
- 循环结构：REPEAT-UNTIL / WHILE-DO

**考点**：补充 N-S 图中的处理框；识别死循环

#### PAD 图

**概念**：问题分析图（Problem Analysis Diagram），用二维树形结构表示程序逻辑：
- 竖线分割出程序的控制结构
- 支持顺序、选择、循环、 CASE 等结构

**考点**：根据代码补充 PAD 图

## 💡 备考建议

### 切忌死记硬背图形

理解每个图诞生的初衷（解决什么痛点）和适用场景（给谁看）：
- 给领导汇报 → 甘特图
- 自己排期找风险 → 单代号网络图
- 数据库设计 → E-R 图
- 需求分析 → 用例图 + 活动图

### 重点突破高频图

| 考试类型 | 死磕这些 |
|---------|---------|
| 软件类（设计师、架构师） | 类图、时序图、用例图、DFD、E-R图 |
| 项管类（集成、高项） | 双代号网络图计算、挣值分析曲线、S曲线 |

### 结合历年真题

软考的图常出现在下午案例题中（补全 UML 图、找关键路径），动手做两套真题，比任何总结都管用。
