## 定义

交付绩效域涉及与交付项目要实现的**范围和质量**相关的活动和功能。

> 绩效要点口诀：**价值可交付物质量**

## 预期成果（5项）

1. 项目有助于实现业务目标和推进战略
2. 项目实现了启动它们要交付的成果
3. 在规划的时间框架内实现了项目收益
4. 项目团队对需求有清晰的理解
5. 干系人接受项目可交付物和成果，并对其满意

## 绩效要点

### 1. 价值的交付
如果开发方法支持在生命周期内发布可交付物，在项目进展中就可以为干系人交付价值。

### 2. 可交付物
可交付物反映干系人的需求、范围和质量。需求管理包括：
- 需求启发
- 不断演变和发现需求
- 管理需求
- 定义范围和管理变更

### 3. 质量
- **范围和需求**聚焦于**交付内容**
- **质量**聚焦于需要达到的**绩效水平**
- 与质量相关的成本由项目所在**组织**承担
- 需要在质量和质量成本之间寻找平衡

## 相关定义

| 概念 | 说明 |
|------|------|
| **需求** | 干系人对项目成果的期望 |
| **WBS** | 工作分解结构，分解可交付物 |
| **完成的定义（DoD）** | 判断工作项已完成的标准（敏捷常用） |
| **质量** | 交付物满足要求和预期用途的程度 |
| **质量成本（COQ）** | 一致性成本+非一致性成本 |

## 执行效果检查指标

| 预期目标 | 检查方法 |
|---------|---------|
| 实现业务目标和战略 | **目标一致性**（战略计划/可行性研究/项目授权文件） |
| 实现预期成果 | **项目完成度**（项目基础数据是否仍处于正轨） |
| 按时实现收益 | **项目收益**（进度/财务指标是否按计划） |
| 团队清晰理解需求 | **需求稳定性**（预测型变更少；适应型阶段确认） |
| 干系人满意 | **干系人满意度**（访谈/观察/用户反馈/投诉退货数量） |

## 考点提示

- 交付绩效域预期成果**5项**（区别于规划绩效域6项）
- "完成的定义（DoD）"是敏捷项目的核心概念，在交付绩效域中定义
- 交付绩效域是规划绩效域所规划工作的**执行与累积**
