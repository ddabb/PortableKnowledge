# 质量控制测量结果（Quality Control Measurements）

## 定义

**质量控制测量结果**是**控制质量**过程（Control Quality）的**输出文件**，记录了对质量控制活动的结果的**书面记录**。

这些结果应以**质量管理计划**所确定的格式加以记录，用于评估**质量绩效**、识别**质量偏差**、支持**质量改进**。

---

## 核心内容

一个完整的质量控制测量结果文件应包含以下要素：

### 1. 测量对象信息

- **工作包/可交付成果名称**：如"用户登录模块开发"
- **质量测量指标**：如"缺陷密度"、"代码覆盖率"、"响应时间"
- **测量标准**：如"缺陷密度≤0.5个/千行代码"
- **测量时间**：测量执行的日期和时间

### 2. 测量结果数据

- **实际测量值**：如"缺陷密度=0.3个/千行代码"
- **是否符合标准**：合格/不合格
- **偏差分析**：实际值与标准值的偏差
- **趋势分析**：与历史数据的对比

### 3. 质量问题记录

- **问题描述**：如"发现3个严重缺陷"
- **问题等级**：严重/一般/轻微
- **影响分析**：对质量目标的影响
- **纠正措施**：已采取或计划采取的纠正措施

### 4. 责任人信息

- **测量人**：执行质量控制的人员
- **审核人**：审核测量结果的人员
- **日期**：测量日期、审核日期

---

## 质量控制测量结果的格式

质量控制测量结果的格式由**质量管理计划**确定，常见格式包括：

### 1. 检查表（Checklist）

```
质量检查表

工作包：用户登录模块开发
检查日期：2024-01-15
检查人：张三

| 检查项 | 检查标准 | 检查结果 | 备注 |
|--------|----------|----------|------|
| 功能完整性 | 所有功能已实现 | 合格 | 无 |
| 界面美观性 | 符合UI设计规范 | 合格 | 无 |
| 性能要求 | 响应时间<2秒 | 不合格 | 平均响应时间2.5秒 |
| 安全性 | 无SQL注入漏洞 | 合格 | 无 |

总体评价：基本合格，需优化性能
```

### 2. 控制图（Control Chart）

```
质量控制图

质量指标：缺陷密度（个/千行代码）
标准上限：0.5
标准下限：0
中心线：0.2

测量数据：
第1周：0.3
第2周：0.4
第3周：0.6 ← 超出上限，需分析原因
第4周：0.2

趋势分析：第3周出现失控，需采取纠正措施
```

### 3. 直方图（Histogram）

```
质量缺陷分布直方图

缺陷类型 | 数量
--------|------
功能缺陷 | 15
性能缺陷 | 8
界面缺陷 | 5
安全缺陷 | 2

分析：功能缺陷占比最高，需加强功能测试
```

## 创建质量控制测量结果的步骤

### 步骤1：确定质量测量指标

- 依据**质量管理计划**
- 确定需要测量的质量指标（如缺陷密度、代码覆盖率）

### 步骤2：执行质量控制活动

- 通过**检查**、**测试**、**评审**等方式收集质量数据
- 确保数据准确、完整

### 步骤3：记录测量结果

- 按**质量管理计划**确定的格式记录测量结果
- 包含测量值、是否符合标准、偏差分析

### 步骤4：分析测量结果

- 识别**质量偏差**
- 分析**根本原因**
- 提出**纠正措施**

### 步骤5：审批与发布

- 提交给**项目经理**或**质量经理**审批
- 审批通过后发布给相关干系人

---

## 质量控制测量结果的应用

### 1. 评估质量绩效

- 通过比较**实际测量值**与**质量测量指标**，评估质量绩效
- 识别**质量偏差**，及时采取纠正措施

### 2. 支持质量改进

- 通过分析**质量问题的根本原因**，制定**质量改进计划**
- 持续监控质量改进效果

### 3. 为控制质量提供数据支持

- 质量控制测量结果是**控制质量**过程的**输入**
- 用于**质量审计报告**、**变更请求**等

### 4. 支持项目决策

- 通过**质量趋势分析**，支持项目决策
- 如决定是否发布可交付成果、是否继续项目

## 与其他文件的关联

| 文件 | 关联方式 |
|-----|---------|
| **质量管理计划** | 确定质量控制测量结果的格式和标准 |
| **质量测量指标** | 质量控制测量结果的测量依据 |
| **可交付成果** | 质量控制测量的对象 |
| **工作绩效信息** | 质量控制测量结果是其组成部分 |
| **质量审计报告** | 基于质量控制测量结果编制 |

## 软考考点提示

1. **输出文件**：质量控制测量结果是**控制质量**过程的输出
2. **格式要求**：应以**质量管理计划**所确定的格式加以记录
3. **与质量测量指标的关系**：质量测量指标是**规划质量管理**的输出，质量控制测量结果是对其的测量记录
4. **质量绩效**：通过比较质量控制测量结果与质量测量指标，评估质量绩效

---

## 最佳实践

1. **及时记录**：质量控制活动完成后，及时记录测量结果
2. **格式统一**：按质量管理计划确定的格式记录，保持一致性
3. **数据分析**：不仅记录数据，还要进行分析，识别趋势和问题
4. **闭环管理**：对发现的质量问题，跟踪纠正措施的落实情况
5. **知识沉淀**：将质量控制测量结果归档，为类似项目提供参考

---

## 常见错误

❌ **格式不统一**：不同团队使用不同格式，难以汇总分析  
❌ **数据不准确**：测量方法不科学，导致数据失真  
❌ **只记录不分析**：只记录数据，不进行分析，失去价值  
❌ **不及时记录**：质量控制活动完成后很久才记录，数据失真  
❌ **不跟踪纠正措施**：发现问题后，不跟踪纠正措施的落实

---

## 总结

质量控制测量结果是项目**质量管理**的重要文件，记录了对质量控制活动的结果的书面记录。掌握其创建方法和应用技巧，能有效支持质量绩效评估和质量改进。
