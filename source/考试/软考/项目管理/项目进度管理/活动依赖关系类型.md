## 紧前活动与紧后活动

- **紧前活动（Predecessor）**：在当前活动开始前必须完成的活动，即直接指向当前活动的活动
- **紧后活动（Successor）**：在当前活动完成后才能开始的活动，即当前活动直接指向的活动

> 例：A→B→C，对于B而言，A是紧前活动，C是紧后活动

**路径汇聚与路径分支**：
- **路径汇聚**：有多个紧前活动的活动（风险集中点）
- **路径分支**：有多个紧后活动的活动（影响范围大）

## 四种逻辑关系类型（PDM前导图法）

| 关系类型 | 英文 | 含义 | 使用频率 |
|---------|------|------|---------|
| **完成-开始** | FS (Finish-to-Start) | 前活动完成后，后活动才能开始 | 最常用（约90%） |
| **开始-开始** | SS (Start-to-Start) | 前活动开始后，后活动才能开始 | 较常用 |
| **完成-完成** | FF (Finish-to-Finish) | 前活动完成后，后活动才能完成 | 较常用 |
| **开始-完成** | SF (Start-to-Finish) | 前活动开始后，后活动才能完成 | 极少使用 |

### FS（完成-开始）- 最常用

```
前活动 ──FS──> 后活动
```

**含义**：前活动必须完成后，后活动才能开始

**示例**：
- 墙砌好了才能刷漆
- 代码写完后才能测试
- 地基建好后才能盖楼

**计算公式**：
- 后活动ES = 前活动EF（无滞后时）
- 后活动ES = 前活动EF + Lag（有滞后时）

### SS（开始-开始）

```
前活动 ──SS──> 后活动
```

**含义**：前活动开始后，后活动才能开始

**示例**：
- 开始浇筑混凝土后，开始振捣
- 开始写文档后，开始审阅文档
- 开始开挖后，开始运土

**特点**：常用于并行活动，配合滞后量使用

### FF（完成-完成）

```
前活动 ──FF──> 后活动
```

**含义**：前活动完成后，后活动才能完成

**示例**：
- 培训结束后，学员才能毕业
- 安装完成后，调试才能完成
- 文档写完后，审核才能完成

**特点**：两活动持续时间可能不同，但结束时间有关联

### SF（开始-完成）- 极少使用

```
前活动 ──SF──> 后活动
```

**含义**：前活动开始后，后活动才能完成

**示例**：
- 新系统上线后，旧系统才能停止
- 新保安到岗后，旧保安才能下班

**特点**：逻辑较反直觉，极少使用，仅用于特定场景

## 提前量与滞后量

- **提前量（Lead）**：负数，表示后活动可以提前开始
  - 例：FS关系 + Lead=2天，表示前活动完成前2天，后活动就可以开始
  - 常用于**快速跟进**

- **滞后量（Lag）**：正数，表示后活动需要延迟开始
  - 例：FS关系 + Lag=3天，表示前活动完成后，需等待3天后活动才能开始
  - 常用于**强制等待时间**

**计算示例**：
```
A(5天) ──FS+Lag=2──> B(3天)

A: ES=0, EF=5
B: ES = A的EF + 2 = 7, EF = 7 + 3 = 10
```

## 单代号网络图 vs 双代号网络图

### 单代号网络图（AON / PDM前导图法）

- **节点**：表示活动
- **箭线**：表示依赖关系
- **特点**：
  - 可以表示FS/SS/FF/SF四种关系
  - 不需要虚活动
  - 现代项目管理软件主要使用此方法

```
    ┌───┐      ┌───┐      ┌───┐
    │ A │──────>│ B │──────>│ C │
    └───┘      └───┘      └───┘
```

### 双代号网络图（AOA / ADM箭线图法）

- **箭线**：表示活动（箭尾→箭头表示活动开始→完成）
- **节点**：表示事件（里程碑，某一时刻）
- **特点**：
  - 只能表示FS关系
  - 需要**虚活动**（Dummy Activity）表示逻辑关系
  - 虚活动用虚线表示，持续时间为0

```
    ┌──[A]──┐      ┌──[B]──┐      ┌──[C]──┐
    │       v      │       v      │       v
   (1)            (2)            (3)            (4)
```

### 虚活动的作用

**虚活动（Dummy）**：持续时间为0，不消耗资源，仅用于表示逻辑关系

**场景1：多个活动有共同的紧前和紧后活动**

```
活动表：
- A的紧前：无
- B的紧前：无  
- C的紧前：A
- D的紧前：A、B

双代号网络图需要虚活动：

    ┌──[A]──┐      ┌──[C]──┐
    │       v      │       v
   (1)            (2)            (4)
    │       ^      │       ^
    │       │虚活动│       │
    │       │      └──[D]──┘
   [B]             (3)
    │               ^
    └───────────────┘

虚活动表示：C只依赖A，D依赖A和B
```

**场景2：避免活动编码歧义**

如果两活动起点和终点节点相同，双代号图中无法区分，需用虚活动拆分。

## 考点总结

1. **FS最常用**，约90%的依赖关系
2. **SS和FF**常用于并行活动，配合滞后量
3. **SF极少使用**，考查时注意逻辑判断
4. **双代号网络图只能表示FS关系**，其他关系需转换为FS或使用虚活动
5. **虚活动**是双代号网络图的特征，单代号图不需要
6. **提前量用于快速跟进**，**滞后量表示强制等待**

## 典型例题

**例题1**：活动A持续5天，活动B持续3天，A和B是SS关系，滞后量为2天。若A从第0天开始，B最早何时开始？

**解答**：
- SS关系 + Lag=2
- B的ES = A的ES + 2 = 0 + 2 = 2
- B从第2天开始

**例题2**：在双代号网络图中，虚活动的作用是什么？

**解答**：
1. 表示逻辑依赖关系（某活动只依赖部分前序活动）
2. 区分起点和终点相同的活动，避免编码歧义
3. 虚活动不消耗时间、不消耗资源

**例题3**：以下哪种逻辑关系在项目管理中最常用？

A. SS  
B. FF  
C. FS  
D. SF

**答案**：C（FS完成-开始，约90%的依赖关系）
