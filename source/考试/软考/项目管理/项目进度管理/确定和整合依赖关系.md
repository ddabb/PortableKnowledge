# 确定和整合依赖关系

## 定义

**依赖关系**是指项目活动之间的先后次序关系。

依赖关系可能是强制或选择的，内部或外部的。这四种依赖关系可以组合成强制性外部依赖关系、强制性内部依赖关系、选择性外部依赖关系或选择性内部依赖关系。

确定和整合依赖关系是排列活动顺序过程的重要内容。

## 核心概念

### 1. 依赖关系的分类

依赖关系可以从两个维度分类：
1. **按性质分类**：强制性依赖关系、选择性依赖关系
2. **按来源分类**：内部依赖关系、外部依赖关系

这两个维度组合，形成四种依赖关系：
- 强制性外部依赖关系
- 强制性内部依赖关系
- 选择性外部依赖关系
- 选择性内部依赖关系

### 2. 强制性依赖关系

**定义：**
强制性依赖关系是法律或合同要求的或工作的内在性质决定的依赖关系。

**特点：**
- 法律或合同要求
- 工作的内在性质决定
- 往往与客观限制有关
- 又称硬逻辑关系或硬依赖关系

**示例：**
- 在建筑项目中，只有在地基建成后，才能建立地面结构
- 在电子项目中，必须先把原型制造出来，然后才能对其进行测试

**注意事项：**
- 技术依赖关系可能不是强制性的
- 在活动排序过程中，项目团队应明确哪些关系是强制性依赖关系
- 不应把强制性依赖关系和进度计划编制工具中的进度制约因素相混淆

### 3. 选择性依赖关系

**定义：**
选择性依赖关系有时又称首选逻辑关系、优先逻辑关系或软逻辑关系。

**特点：**
- 基于具体应用领域的最佳实践
- 基于项目的某些特殊性质对活动顺序的要求
- 不是强制性的
- 会影响总浮动时间，并限制后续的进度安排

**示例：**
- 根据普遍公认的最佳实践，在建造期间，应先完成卫生管道工程，才能开始电气工程
- 这个顺序并不是强制性要求，两个工程可以同时（并行）开展工作，但按先后顺序进行可以降低整体项目风险

**注意事项：**
- 应该对选择性依赖关系进行全面记录
- 如果打算进行快速跟进，则应当审查相应的选择性依赖关系，并考虑是否需要调整或去除
- 在排列活动顺序过程中，项目团队应明确哪些依赖关系属于选择性依赖关系

### 4. 外部依赖关系

**定义：**
外部依赖关系是项目活动与非项目活动之间的依赖关系。

**特点：**
- 往往不在项目团队的控制范围内
- 涉及项目外部的因素

**示例：**
- 软件项目的测试活动取决于外部硬件的到货
- 建筑项目的现场准备，可能要在政府的环境听证会之后才能开始

**注意事项：**
- 在排列活动顺序过程中，项目管理团队应明确哪些依赖关系属于外部依赖关系
- 需要密切监控外部依赖关系，因为它们不在项目团队控制范围内

### 5. 内部依赖关系

**定义：**
内部依赖关系是项目活动之间的紧前关系。

**特点：**
- 通常在项目团队的控制之中
- 涉及项目内部活动之间的关系

**示例：**
- 只有机器组装完毕，团队才能对其测试，这是一个内部的强制性依赖关系

**注意事项：**
- 在排列活动顺序过程中，项目管理团队应明确哪些依赖关系属于内部依赖关系
- 内部依赖关系通常比较容易管理和控制

## 详细内容

### 1. 确定依赖关系的方法

**专家判断：**
- 征求具备类似项目经验和专业知识者的意见
- 专家判断可用于确定依赖关系

**数据收集：**
- **访谈**：与项目团队成员、职能经理、相关方等访谈，确定依赖关系
- **观察**：观察工作实际开展方式，确定依赖关系

**人际关系与团队技能：**
- **引导**：引导团队开展依赖关系分析

**会议：**
- 与项目团队、职能经理、相关方等召开会议，确定依赖关系

### 2. 依赖关系的表示

**前导图法（PDM）：**
- 用节点表示活动，用箭头表示活动之间的逻辑关系
- 常用的逻辑关系：完成到开始（FS）、完成到完成（FF）、开始到开始（SS）、开始到完成（SF）

**依赖关系表：**
- 列出所有活动及其紧前活动和紧后活动
- 明确活动之间的依赖关系

**网络图：**
- 用图形表示活动之间的依赖关系
- 直观展示项目进度网络逻辑

### 3. 整合依赖关系

**整合原则：**
- 确保所有依赖关系都被识别和记录
- 确保依赖关系之间不冲突
- 确保依赖关系与项目约束一致

**整合方法：**
- 汇总所有活动之间的依赖关系
- 检查依赖关系的完整性和一致性
- 优化依赖关系，减少不必要的依赖

**整合输出：**
- 项目进度网络图
- 项目文件更新（活动属性、活动清单、假设日志、里程碑清单）

### 4. 依赖关系对进度的影响

**总浮动时间：**
- 选择性依赖关系会影响总浮动时间
- 强制性依赖关系通常决定总浮动时间的下限

**自由浮动时间：**
- 依赖关系会影响自由浮动时间
- 自由浮动时间是指在不延误任一紧后活动最早开始日期的前提下，某进度活动可以推迟的时间量

**进度风险：**
- 外部依赖关系通常带来较高的进度风险
- 选择性依赖关系可以通过快速跟进降低进度风险

## 示例/应用场景

### 示例1：IT项目的依赖关系

**项目背景：**
某软件开发项目，需要确定和整合活动之间的依赖关系。

**依赖关系分析：**

| 活动 | 依赖关系类型 | 说明 |
|------|--------------|------|
| 需求分析 | 外部依赖关系（选择性） | 取决于客户提供需求的时间 |
| 系统设计 | 内部依赖关系（强制性） | 必须在需求分析完成后开始 |
| 编码实现 | 内部依赖关系（强制性） | 必须在系统设计完成后开始 |
| 系统测试 | 内部依赖关系（强制性） | 必须在编码实现完成后开始 |
| 用户验收测试 | 外部依赖关系（强制性） | 取决于客户安排UAT的时间 |

**整合依赖关系：**
- 使用前导图法（PDM）表示依赖关系
- 绘制项目进度网络图
- 更新活动属性和活动清单

**对进度的影响：**
- 外部依赖关系（客户提供需求、客户安排UAT）带来进度风险
- 需要密切监控外部依赖关系
- 内部依赖关系（强制性）决定项目总工期

### 示例2：建设项目的依赖关系

**项目背景：**
某商业大厦建设项目，需要确定和整合活动之间的依赖关系。

**依赖关系分析：**

| 活动 | 依赖关系类型 | 说明 |
|------|--------------|------|
| 地质勘探 | 外部依赖关系（强制性） | 必须在政府审批通过后才能开始 |
| 设计图纸 | 内部依赖关系（强制性） | 必须在地质勘探完成后开始 |
| 土方工程 | 内部依赖关系（强制性） | 必须在设计图纸完成后开始 |
| 基础工程 | 内部依赖关系（强制性） | 必须在土方工程完成后开始 |
| 主体结构 | 内部依赖关系（强制性） | 必须在基础工程完成后开始 |
| 水电安装 | 选择性内部依赖关系 | 可以在主体结构完成前开始（快速跟进） |
| 装修工程 | 内部依赖关系（强制性） | 必须在主体结构完成后开始 |

**整合依赖关系：**
- 使用前导图法（PDM）表示依赖关系
- 绘制项目进度网络图
- 更新活动属性和活动清单

**对进度的影响：**
- 选择性内部依赖关系（水电安装）可以通过快速跟进缩短工期
- 外部依赖关系（政府审批）带来进度风险
- 需要密切监控外部依赖关系

## 最佳实践

1. **全面识别依赖关系**
   - 不要遗漏任何依赖关系
   - 特别是外部依赖关系，往往容易被遗漏

2. **准确分类依赖关系**
   - 准确区分强制性依赖关系和选择性依赖关系
   - 准确区分内部依赖关系和外部依赖关系

3. **记录依赖关系**
   - 全面记录所有依赖关系
   - 特别是选择性依赖关系，应记录理由

4. **使用合适的表示 method**
   - 使用前导图法（PDM）表示依赖关系
   - 绘制项目进度网络图

5. **监控外部依赖关系**
   - 密切监控外部依赖关系，因为它们不在项目团队控制范围内
   - 制定应对措施，降低外部依赖关系带来的风险

6. **定期审查依赖关系**
   - 随着项目进展，依赖关系可能会发生变化
   - 定期审查依赖关系，确保其持续有效

## 常见错误

1. **遗漏依赖关系**
   - 错误表现：遗漏某些依赖关系，特别是外部依赖关系
   - 后果：进度计划不准确，可能导致进度延误
   - 正确做法：全面识别依赖关系

2. **错误分类依赖关系**
   - 错误表现：将选择性依赖关系误认为强制性依赖关系，或将外部依赖关系误认为内部依赖关系
   - 后果：进度计划不灵活，无法优化
   - 正确做法：准确分类依赖关系

3. **不记录依赖关系**
   - 错误表现：不记录依赖关系，或记录不完整
   - 后果：依赖关系不清晰，难以管理
   - 正确做法：全面记录所有依赖关系

4. **不监控外部依赖关系**
   - 错误表现：不监控外部依赖关系
   - 后果：外部依赖关系导致进度延误
   - 正确做法：密切监控外部依赖关系

5. **不审查依赖关系**
   - 错误表现：不审查依赖关系，或审查不及时
   - 后果：依赖关系与项目进展脱节，无法指导进度管理
   - 正确做法：定期审查依赖关系

## 总结

依赖关系可能是强制或选择的，内部或外部的。这四种依赖关系可以组合成强制性外部依赖关系、强制性内部依赖关系、选择性外部依赖关系或选择性内部依赖关系。

强制性依赖关系是法律或合同要求的或工作的内在性质决定的依赖关系，往往与客观限制有关。选择性依赖关系是基于具体应用领域的最佳实践或项目的某些特殊性质对活动顺序的要求来创建的。外部依赖关系是项目活动与非项目活动之间的依赖关系，往往不在项目团队的控制范围内。内部依赖关系是项目活动之间的紧前关系，通常在项目团队的控制之中。

在软考中，确定和整合依赖关系是项目进度管理知识领域的重要考点，可能涉及选择题、案例分析题。考生应理解依赖关系的分类、确定方法、表示 method、对进度的影响等内容，能够根据项目场景确定和整合依赖关系。

对于项目经理来说，掌握确定和整合依赖关系是必备的技能。它有助于制定准确的进度计划，优化项目工期，降低进度风险。
