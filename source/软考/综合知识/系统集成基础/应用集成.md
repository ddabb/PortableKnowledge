# 应用集成

## 1. 业务应用集成概述

### 1.1 定义
业务应用集成（EAI - Enterprise Application Integration）是将独立的软件应用连接起来，实现协同工作。

### 1.2 技术要求
- **互操作性**：不同系统间信息的有意义交换
- **可移植性**：应用程序在系统中迁移的潜力
- **分布透明性**：应用编程者不需关心分布/集中

### 1.3 集成优势
- 共享信息
- 提高敏捷性和效率
- 简化软件使用
- 降低IT投资和成本
- 优化业务流程

## 2. 应用集成发展历程

| 阶段 | 特点 |
|-----|------|
| 80年代 | 连接本地业务应用 |
| 早期ERP | 数据层面集成 |
| 21世纪云SaaS | 混合集成方法 |
| API时代 | 打破组织孤岛，数据源整合 |

## 3. 应用集成组件

### 3.1 API（应用编程接口）
- 定义软件交互方式
- 支持应用相互通信
- 提供数据结构访问

### 3.2 事件驱动型操作
- 触发器启动程序或操作
- 例：订单提交后计费并开具发票

### 3.3 数据映射
- 将数据从一个系统映射到另一个系统
- 定义数据交换方式

## 4. ESB（企业服务总线）

### 4.1 定义
ESB是构建企业级服务导向架构的基础设施，提供松耦合的消息传递机制。

### 4.2 功能
- 服务路由
- 消息转换
- 协议转换
- 服务注册与发现
- 负载均衡
- 故障处理

### 4.3 特点
- 松耦合架构
- 基于标准的通信
- 智能路由
- 服务编排

## 5. SOA（面向服务架构）

### 5.1 定义
SOA是一种组件模型，将应用程序的不同功能单元通过服务接口联系起来。

### 5.2 核心概念

| 概念 | 说明 |
|-----|------|
| 服务 | 可调用功能单元 |
| 服务接口 | 描述服务如何访问和调用 |
| 服务注册 | 服务元数据的存储库 |

### 5.3 SOA特点
- 松耦合
- 可重用
- 可组合
- 标准化接口

## 6. 软件构件标准

### 6.1 CORBA
对象管理组织OMG制定的分布式对象计算标准

**组成：**
- ORB（对象请求代理） - 核心
- 对象服务（15种）
- 公共功能
- 域接口
- 应用接口

### 6.2 COM/DCOM/COM+

| 技术 | 说明 |
|-----|------|
| COM | 二进制代码对象 |
| DCOM | 分布式扩展，位置透明 |
| COM+ | 与操作系统结合 |

### 6.3 .NET

**架构：**
- CLR（通用语言运行环境）
- BCL（基础类库）
- ADO.NET
- ASP.NET

### 6.4 J2EE

**四层架构：**
1. 客户端层
2. 服务器端组件层（JSP/Servlet）
3. EJB层（商业逻辑）
4. 信息系统层

## 7. 部署方式

### 7.1 部署模式

| 模式 | 说明 |
|-----|------|
| 集中式服务器 | 用户访问量小（500人以下） |
| 微服务分布式部署 | 用户访问量大、并发性高 |
| 容器+DevOps | 持续部署与集成 |

### 7.2 部署方式

| 方式 | 说明 |
|-----|------|
| 蓝绿部署 | 准备新旧版本，域名切换 |
| 金丝雀部署 | 先让少量用户使用新版本 |

## 8. 持续集成/持续交付

### 8.1 持续集成（CI）
- 频繁集成代码到共享主线
- 自动构建和测试
- 快速发现集成错误

### 8.2 持续交付（CD）
- 确保代码能快速安全部署
- 一键部署
- 完整自动化流程

### 8.3 持续部署
- 通过流水线自动部署到生产环境

## 9. 关键考点

- EAI是连接独立软件应用实现协同工作
- 应用集成三要求：互操作性、可移植性、分布透明性
- ESB核心功能：路由、转换、协议转换
- SOA特点：松耦合、可重用、可组合
- CORBA：OMG制定，ORB是核心
- COM+：与操作系统结合
- J2EE四层：客户端、组件、EJB、信息系统
- 部署方式：蓝绿部署、金丝雀部署
- 持续交付三阶段：CI→CD→持续部署
