# 案例分析 - 成本管理问题

## 一、常见问题类型

### 1.1 成本超支分析

**问题特征**：
- 实际成本(AC) > 计划价值(PV)
- 成本绩效指数(CPI) < 1
- 预算耗尽但工作未完成

**答题框架**：

```
【问题原因分析】
1. 估算问题：
   - 成本估算不准确，漏项或低估
   - 需求范围不清，导致估算不足
   - 未考虑风险准备金

2. 执行问题：
   - 范围蔓延，需求不断变更
   - 效率低下，实际工作量超预期
   - 返工导致额外成本
   - 资源浪费严重

3. 外部因素：
   - 原材料涨价
   - 汇率波动

【解决方案】
1. 成本控制措施：
   - 冻结非关键支出
   - 优化资源配置
   - 减少不必要的功能

2. 成本预测与调整：
   - 重新估算剩余工作成本
   - 提出预算变更申请
   - 制定成本节约计划
```

### 1.2 挣值分析计算

**核心指标**：

| 指标 | 公式 | 含义 |
|------|------|------|
| PV (计划价值) | 计划工作预算成本 | 应该完成多少 |
| EV (挣值) | 实际完成工作预算成本 | 实际完成了多少 |
| AC (实际成本) | 实际花费 | 实际花了多少 |
| BAC | 完工预算 | 总预算 |
| EAC | 完工估算 | 预计总花费 |
| ETC | 完工尚需 | 还需要多少 |

**绩效指标**：

```
CV = EV - AC （成本偏差）
SV = EV - PV （进度偏差）

CPI = EV / AC （成本绩效指数）
SPI = EV / PV （进度绩效指数）

CV > 0：成本节约
CV < 0：成本超支
CPI > 1：成本节约
CPI < 1：成本超支
```

**完工估算方法**：

```
EAC = BAC / CPI （基于当前绩效）
EAC = AC + ETC （剩余工作重新估算）
EAC = BAC （不考虑绩效变化）
```

## 二、典型案例真题

### 案例一：软件项目成本超支

**背景**：某软件开发项目总预算50万元，工期6个月。项目进行到第4个月时：
- PV = 35万元
- EV = 30万元
- AC = 38万元

**问题**：
1. 计算项目的CPI和SPI，判断项目状态
2. 预测项目完工成本(EAC)
3. 分析成本超支原因并提出改进措施

**参考答案**：

```
【绩效分析】
CPI = EV/AC = 30/38 = 0.79 < 1 （成本超支）
SPI = EV/PV = 30/35 = 0.86 < 1 （进度落后）

项目状态：成本超支、进度落后，属于"双输"项目。

【完工预测】
方法一（基于当前绩效）：
EAC = BAC / CPI = 50 / 0.79 = 63.3万元
预计超支：63.3 - 50 = 13.3万元

方法二（重新估算）：
假设剩余工作按当前CPI执行：
ETC = (BAC - EV) / CPI = (50 - 30) / 0.79 = 25.3万元
EAC = AC + ETC = 38 + 25.3 = 63.3万元

【原因分析】
1. 估算阶段：未充分考虑技术难度，风险准备金不足
2. 执行阶段：
   - 需求变更频繁，增加工作量
   - 团队经验不足，开发效率低
   - 测试发现大量bug，修复成本高

【改进措施】
1. 立即措施：
   - 冻结后续需求变更
   - 增加高效开发人员
   - 砍掉非核心功能

2. 成本控制：
   - 每日监控成本支出
   - 每周计算CPI进行预警
   - 建立成本变更阈值（超过10%需审批）
```

## 三、成本控制措施总结

### 3.1 预防措施

- 详细的需求分析，减少范围蔓延
- 合理的成本估算，包含风险缓冲
- 明确的变更控制流程
- 定期的成本绩效监控

### 3.2 纠偏措施

| 情况 | 措施 |
|------|------|
| CPI < 0.9 | 发出成本预警，评估是否需要变更 |
| CPI < 0.8 | 启动成本控制计划，砍功能或加资源 |
| 成本超支 > 20% | 重新估算项目，提交变更控制 |

### 3.3 成本节约技巧

- 优化资源配置，提高效率
- 采用敏捷开发，快速迭代
- 利用开源组件，减少开发成本
- 自动化测试，降低人工成本
