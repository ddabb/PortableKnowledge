# 案例分析 - 范围管理问题

## 一、常见问题类型

### 1.1 范围蔓延问题

**问题特征**：
- 项目范围不断扩大
- 计划工期一延再延
- 预算不断追加
- 原有需求被稀释

**答题框架**：

```
【问题诊断】
1. 范围蔓延表现：
   - 不断接收新需求
   - 缺少变更控制
   - 范围说明书未遵守

2. 根本原因：
   - 需求调研不充分
   - 变更控制流程缺失
   - 范围定义不清晰
   - 客户期望管理不当

【解决方案】
1. 立即措施：
   - 冻结所有新需求
   - 梳理当前范围，确认核心功能
   - 与客户重新签订范围说明书

2. 控制措施：
   - 建立CCB（变更控制委员会）
   - 严格执行变更流程
   - 设置范围变更阈值

3. 预防措施：
   - 完善需求规格说明书
   - 做好范围基准管理
   - 定期检查范围偏差
```

### 1.2 需求变更管理

**变更控制流程**：

```
变更请求 → 影响分析 → CCB审批 → 实施变更 → 验证变更 → 更新文档
```

**答题要点**：

```
【是否应该批准变更】
1. 评估变更对范围的影响
2. 评估变更对进度的影响
3. 评估变更对成本的影响
4. 评估变更对质量的影响
5. 综合评估变更的价值

【变更处理原则】
- 评估后再决策
- 记录所有变更
- 保持范围基准
- 及时沟通决策结果
```

## 二、典型案例真题

### 案例一：需求变更导致项目失控

**背景**：某政府OA系统项目，合同金额200万，工期12个月。项目进行到第8个月时：
- 已接收需求变更50项
- 实际花费180万
- 核心功能仅完成60%
- 客户仍不断提出新需求

**问题**：
1. 项目范围失控的原因是什么？
2. 如何控制后续的范围变更？
3. 如何与客户沟通调整预期？

**参考答案**：

```
【原因分析】
1. 变更控制缺失：
   - 项目经理无权否决变更
   - 无变更控制流程
   - 变更未经过评审直接实施

2. 需求管理问题：
   - 需求调研不充分
   - 需求文档不完整
   - 缺少需求确认签字

3. 客户期望偏差：
   - 客户认为"提需求不要钱"
   - 未告知客户变更的后果

【控制措施】
1. 立即执行：
   - 成立CCB，由项目经理、客户代表、公司领导组成
   - 冻结所有新需求变更
   - 梳理已接受变更，评估影响

2. 变更控制机制：
   - 所有变更必须书面申请
   - 变更必须评估：范围、进度、成本、质量影响
   - 超过10万或2周工期的变更必须公司审批

3. 客户沟通：
   - 汇报项目当前状态
   - 解释变更对项目的影响
   - 确定核心功能清单
   - 明确后续变更需额外付费

【调整计划】
- 核心功能（必须完成）：公文管理、审批流程、个人办公
- 次要功能（视情况完成）：档案管理、决策分析
- 后续功能（项目二期）：移动办公、知识库
```

## 三、范围管理计算题

### 3.1 偏差分析

```
范围偏差 SV = EV - PV
进度偏差 CV = EV - AC

范围绩效指数 SPI = EV / PV
成本绩效指数 CPI = EV / AC
```

### 3.2 完工估算

```
BAC（完工预算）= 总预算
EAC（完工估算）= 实际成本 + 剩余工作估算

方法一：基于CPI
EAC = BAC / CPI

方法二：重新估算
EAC = AC + 重新估算的ETC

方法三：不考虑偏差
EAC = BAC
```

## 四、答题技巧

### 4.1 范围问题答题框架

1. **判断问题类型**：范围蔓延 OR 需求变更 OR 验收问题
2. **分析原因**：从需求、流程、沟通、期望管理方面分析
3. **提出措施**：建立变更控制流程、与客户重新确认范围
4. **预防建议**：完善需求调研、加强范围基准管理

### 4.2 常用术语

- 范围蔓延（Scope Creep）
- 变更控制委员会（CCB）
- 范围基准（Scope Baseline）
- 需求跟踪矩阵
- 验收标准
- 确认范围（Validate Scope）
- 控制范围（Control Scope）
