## 变更管理定义

变更管理是为使项目基准与实际执行相一致，应对项目变化的一套管理方法。其可能的两个结果：**拒绝变化** 或 **调整项目基准**。

**变更的实质**：根据项目推进中越来越丰富的认知，不断调整项目方向和资源配置，最大程度满足项目需求，提升项目价值。

## 变更的常见原因

1. 产品范围定义过失或疏忽
2. 项目范围定义过失或疏忽
3. 项目执行过程与基准要求不一致（被动调整）
4. 应对风险的紧急计划或回避计划
5. 增值变更
6. 外部事件

## 变更管理原则（7条）

1. **基准管理** — 基准是变更的依据，每次变更后重新确认基准
2. **变更控制流程化** — 所有变更必须遵循变更控制流程
3. **明确组织分工** — 明确评估、评审、执行的职能
4. **与干系人充分沟通** — 征求意见，获得支持
5. **妥善保存变更文档** — 完整、及时、准确、清晰
6. **评估变更的可能影响** — 可视的+不可视的变更操作
7. **变更的及时性** — 宜早不宜晚，只做必要的变更

## 变更流程（8步）

| 步骤 | 主要工作 | 负责人 |
|-----|---------|--------|
| **1. 变更申请** | 任何人均可提出，口头→书面记录，更新变更日志 | 变更请求者 |
| **2. 变更初审** | ①确认必要性；②格式完整性校验；③干系人就信息达成共识 | 项目经理 |
| **3. 变更方案论证** | 论证技术可行性、经济可行性 | 项目经理/专家 |
| **4. 变更审查** | 文档会签、召开正式评审会议 | CCB |
| **5. 发出通知并实施** | 通知受影响干系人，实施变更（含基准调整、交期影响） | CCB/变更实施者 |
| **6. 实施监控** | 监控变更实施内容（CCB或监理单位） | CCB |
| **7. 效果评估** | 依据基准评估目的是否达成、方案是否完成 | 变更经理 |
| **8. 变更收尾** | 变更后项目是否进入正轨，配置基准相应更新 | 项目经理 |

## 变更类型

| 类型 | 说明 |
|------|------|
| **标准变更** | 低风险、预先授权的变更 |
| **正常变更** | 常规的、较低风险的变更 |
| **紧急变更** | 不包括在变更计划内，需要快速响应、尽快实施 |

## CCB与变更管理角色

| 角色 | 职责 |
|------|------|
| **CCB（变更控制委员会）** | 决策机构，审查批准/否决/推迟变更请求，通知相关干系人，确认变更结果 |
| **变更经理/变更管理负责人** | 整个变更过程方案负责人；监控过程；协调资源；确定类型和日程 |
| **变更实施者** | 按计划执行变更任务；记录变更产物；参与验证确认 |
| **变更请求者** | 提出需求，提交变更请求单，初步评估风险 |
| **变更顾问委员会** | 紧急变更时可行使审批权限；定期评估变更管理执行情况 |

## 考点提示

- CCB是**决策机构**，不是作业机构
- 变更初审有3个目的（确认必要性/完整性校验/达成共识）
- 效果评估依据是**项目基准**
- 小变更可简化流程，大变更须走正式变更顾问委员会
- 配置管理也有CCB，与变更管理的CCB**职能有重叠但不同**
