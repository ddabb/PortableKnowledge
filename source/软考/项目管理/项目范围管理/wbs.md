# WBS（工作分解结构）

## 核心定义

**WBS（Work Breakdown Structure，工作分解结构）**：对项目团队为实现项目目标、创建所需可交付成果而需要实施的全部工作范围的层级分解。

WBS 组织并定义了项目的总范围，代表着经批准的当前项目范围说明书中所规定的工作。WBS 最低层的组成部分称为工作包。

## 关键要点速查

| 要点 | 内容 |
|------|------|
| 最低层组件 | 工作包（Work Package） |
| WBS包含 | 全部产品和项目工作（含管理工作） |
| 100%规则 | 各组件之和必须等于上层可交付成果的完整范围 |
| 分解原则 | 分解到工作包层（可估算、可管理）即可 |
| 分解程度 | 取决于所需的控制程度，不能过细也不能过粗 |
| 常用结构 | 按阶段分解 / 按可交付成果分解 / 按子系统分解 |

## WBS创建流程

1. 识别和分析可交付成果及相关工作
2. 确定 WBS 的结构和编排方法
3. 自上而下逐层细化分解
4. 为 WBS 组成部分制定和分配标识编码
5. 核实可交付成果分解的程度是否恰当

## WBS结构示例（IT项目）

```
1.0 项目管理
  1.1 项目启动
  1.2 项目规划
  1.3 项目执行与监控
  1.4 项目收尾
2.0 需求分析
  2.1 业务调研
  2.2 需求文档编写
  2.3 需求评审
3.0 系统设计
  3.1 架构设计
  3.2 详细设计
4.0 编码开发
  4.1 基础平台
  4.2 业务功能（按模块）
5.0 测试
  5.1 单元测试
  5.2 集成测试
  5.3 系统测试
  5.4 验收测试
6.0 部署与上线
7.0 培训与文档
```

## 分解技术

分解是一种把项目范围和项目可交付成果逐步划分为更小、更便于管理的组成部分的技术。创建 WBS 的方法多种多样，常用的包括自上而下分解法和自下而上归并法。

WBS 可以采用提纲式、组织结构图或能说明层级结构的其他形式。不同可交付成果可以分解到不同层次，某些只需分解到下一层即可到达工作包层次，而另一些则须分解更多层。

**工作分解得越细致，对工作的规划、管理和控制就越有力。但过细分解会造成管理精力浪费、资源使用效率低下。**

关于分解技术的详细内容，可参考 `分解.md`。
